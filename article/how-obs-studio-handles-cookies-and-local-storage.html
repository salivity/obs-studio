How OBS Studio Handles Cookies and Local Storage

OBS Studio manages browser cookies and local storage through the Chromium Embedded Framework (CEF), persisting web data across scene changes, source reloads, and software restarts. This article explains how the underlying CEF architecture stores web data on your drive, how session-based versus persistent data behaves during browser source reboots, and the specific source settings that influence cache retention.

The Underlying Engine: Chromium Embedded Framework (CEF)

The OBS Studio Browser Source does not operate as an isolated, standalone web view for every created item. Instead, it relies on an integrated instance of CEF. Because CEF functions as a full-featured Chromium runtime, it inherits standard Chromium web storage mechanisms, including the Cookie database, LocalStorage, IndexedDB, and HTTP cache.

Data Storage Locations on the Host System

When OBS Studio runs, CEF establishes an application-level user data directory on your local machine:

  • Windows: %APPDATA%\obs-studio\plugin_config\obs-browser
  • macOS: ~/Library/Application Support/obs-studio/plugin_config/obs-browser
  • Linux: ~/.config/obs-studio/plugin_config/obs-browser

Within this directory, CEF creates structured storage folders. Local Storage data is stored using LevelDB key-value stores (/Local Storage/leveldb/), and cookies are maintained inside a dedicated SQLite file (Cookies). Because these files are physically committed to disk, any data written to them survives when an individual browser source is refreshed, toggled, or when OBS Studio is closed and reopened.

Persistent Data vs. Session Data

How a browser source retains data across reboots depends directly on whether the data is flagged as persistent or session-only by the hosting website:

  • Persistent Cookies: Cookies set with an explicit Expires or Max-Age attribute are written directly to the SQLite cookie store on disk. When a browser source restarts or OBS Studio reboots, CEF reads these files, keeping your logins, authentication tokens, and preferences active.
  • Session Cookies: Cookies without an expiration attribute are stored only in volatile memory. If OBS Studio is closed entirely, the CEF root process terminates, wiping all session cookies. However, merely switching scenes or hiding a source may not clear these if the main process keeps the runtime context active.
  • Local Storage and IndexedDB: These APIs have no automatic expiration. Unless a script explicitly calls localStorage.clear() or removes items, the data remains permanently in the LevelDB files on disk across both source refreshes and complete application restarts.

Effects of Source Properties on Data Persistence

OBS Studio provides specific controls in the Browser Source properties that alter how the page reloads, though they interact differently with disk storage:

  • "Shutdown source when not visible": When enabled, OBS unloads the rendering instance when the source is not active in the current scene to conserve CPU and GPU resources. When the source becomes visible again, the page reloads. However, because CEF writes storage to disk, local storage keys and persistent cookies are read back into the new rendering instance immediately upon recreation.
  • "Refresh browser when scene becomes active": This forces a standard navigation reload (location.reload()). It clears in-memory JavaScript state and variables, but it preserves all persistent cookies, LocalStorage, and IndexedDB entries.
  • "Refresh cache of current page" Button: Clicking this button directly inside the source properties executes a hard refresh. While this invalidates certain temporary HTTP web caches (like stylesheets and scripts), it generally does not purge established LocalStorage or authenticated persistent cookies.

Clearing Persistent Browser Source Data

Because all browser sources in an OBS profile share the central CEF data folder by default, clearing storage requires targeted action. To reset corrupted states, clear stored logins, or remove leftover tracker data, OBS Studio must be completely closed. Once closed, deleting the contents of the obs-browser directory removes all stored cookies, LevelDB files, and cached web assets, returning all browser sources to a clean-slate state upon the next launch.
