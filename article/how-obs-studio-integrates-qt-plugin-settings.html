How OBS Studio Integrates Qt Plugin Settings

OBS Studio exposes custom plugin settings panels within its native Qt user interface primarily through two distinct mechanisms: the automated obs_properties_t abstraction system and the direct Qt-based obs-frontend-api. Depending on whether a plugin requires standard configuration forms or entirely bespoke graphical layouts, developers can either rely on OBS to dynamically generate native Qt widgets or build custom Qt widgets and inject them directly into the application's interface.

Automated UI via obs_properties_t and OBSPropertiesView

The primary cross-platform mechanism for exposing settings in OBS Studio is the properties API defined in libobs. Plugins define a configuration schema using the obs_properties_t data structure rather than writing direct GUI code.

In this workflow:

  1. The plugin implements a get_properties callback (such as obs_source_info.get_properties).
  2. Inside this callback, developers declare settings fields such as text inputs, sliders, paths, lists, or color pickers using functions like obs_properties_add_text, obs_properties_add_int, or obs_properties_add_list.
  3. When the user opens the settings, filters, or properties window for that plugin, OBS Studio passes the obs_properties_t structure to an internal Qt class named OBSPropertiesView.
  4. OBSPropertiesView dynamically maps each registered property to its native Qt equivalent (such as converting an integer property to a QSpinBox or QSlider, and a list property to a QComboBox).

This mechanism abstracts Qt entirely from the core plugin logic, ensuring consistent styling, automatic layout management, and thread-safe data synchronization with the underlying settings data (obs_data_t).

Direct Qt Integration via obs-frontend-api

For plugins requiring complex, multi-tabbed, or completely custom interfaces, OBS Studio provides the obs-frontend-api. This library links directly with OBS Studio's Qt runtime, allowing plugins to expose custom panels, dialogs, and dock widgets.

Key components of this mechanism include:

  • Custom Docks: Plugins can call obs_frontend_add_dock() or obs_frontend_add_dock_by_id() passing a pointer to a custom QDockWidget. OBS embeds this widget into the main window, allowing users to dock, float, and save the panel's layout alongside native panels like Audio Mixer and Scenes.
  • Menu-Triggered Dialogs: Plugins can register entries in the application's top navigation bar via obs_frontend_add_tools_menu_qaction(). When triggered, these actions display custom QDialog panels created using standard Qt Designer forms or programmatic layouts.
  • Parent Window Access: Developers can retrieve the main Qt window handle using obs_frontend_get_main_window(). This ensures that custom modal dialogs or child windows adhere to native window parenting, modality, and operating system focus rules.

By combining the declarative obs_properties_t engine for modular settings with the obs-frontend-api for deep Qt panel embedding, OBS Studio allows plugins to integrate seamlessly into its native desktop environment.
