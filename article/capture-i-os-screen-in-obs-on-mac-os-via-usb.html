Capture iOS Screen in OBS on macOS via USB

Capturing an iPhone or iPad screen in OBS Studio on macOS using a Lightning or USB-C cable relies on Apple’s native AVFoundation framework rather than external capture hardware. This article explains the technical pipeline that enables this connection, detailing how macOS recognizes the iOS device as a native video source and how OBS Studio hooks into the operating system to ingest and render the display feed with low latency.

Native iOS Recognition via USB Multiplexing

When an iOS device connects to a Mac via a physical cable and the user trusts the computer, the operating system initiates communication using Apple's underlying USB multiplexing daemon (usbmuxd). This connection creates a secure, high-bandwidth data channel between the devices. Rather than operating as a simple storage mount or peripheral, macOS natively supports a tethered capture protocol—the same architecture used by QuickTime Player for screen recording.

AVFoundation and CoreMediaIO Pipeline

Once connected, iOS hardware-encodes its display output and streams it across the cable. At the operating system level, macOS leverages the AVFoundation and CoreMediaIO frameworks to handle the incoming packets:

  • Device Enumeration: macOS registers the tethered iPhone or iPad as an available AVCaptureDevice. This exposes the iOS screen to the system in the exact same manner as a built-in FaceTime camera or external USB webcam.
  • Hardware Decoding: The incoming compressed video stream is decoded by macOS’s media engine directly on the Mac's hardware decoders, minimizing CPU overhead and input lag.

OBS Studio Hook and Ingestion

OBS Studio on macOS includes native source capture plugins that interface directly with Apple's media APIs:

  1. Source Discovery: When you add a Video Capture Device source in OBS, the software calls the AVFoundation API to query all active capture endpoints. The connected iOS device appears in the device drop-down menu automatically.
  2. Buffer Allocation: When selected, OBS requests video frames from the device session. AVFoundation delivers these frames as CVPixelBuffer memory references.
  3. Graphics Rendering: OBS takes these pixel buffers and uploads them into its graphics pipeline. On modern versions of OBS for macOS, this uses the Metal graphics API to render the video frames into the OBS compositor canvas, bypassing redundant software memory copies to ensure real-time performance.

Synchronized Audio Ingestion

Audio transmission follows a parallel hardware-accelerated path. The iOS device routes its digital system audio across the USB connection via the macOS CoreAudio daemon. OBS accesses this stream directly within the same capture source properties or as an independent CoreAudio device, delivering full-fidelity, synchronized stereo sound without the dropped frames or latency common to wireless AirPlay connections.
