How OBS Studio Calculates Filter Bounding Boxes

OBS Studio determines source bounding boxes by querying the outermost layer of a source’s rendering pipeline, dynamically adjusting the selection wireframe and transform matrix when filters expand the native raster dimensions. While a base source has fixed intrinsic dimensions, effect filters that introduce spatial margins—such as drop shadows, glows, or borders—can override dimension reporting functions, forcing the scene canvas to adapt its bounding calculations to the newly expanded texture boundaries.

Base Dimensions vs. Filter Dimensions

In OBS Studio's architecture, every source is represented by an obs_source_t object. Sources define intrinsic dimensions through internal callbacks (get_width and get_height). For an unfiltered asset, such as a 1920x1080 capture card or image, the base dimensions directly dictate the scene item’s bounding box.

When filters are applied, they form a linked processing chain. OBS evaluates dimension queries from the end of the filter chain rather than the base source:

  1. obs_source_get_base_width() / obs_source_get_base_height(): Always returns the original, unmodified dimensions of the root asset.
  2. obs_source_get_width() / obs_source_get_height(): Recursively queries the filter chain. If the top-level filter modifies dimensions, it reports the post-processed raster size to the scene compositor.

The Raster Expansion Mechanism

Filters that add external elements, such as drop shadows, do not simply draw over existing pixels; they allocate a larger rendering target.

When a drop shadow filter executes:

  • Padding Calculation: The filter takes user parameters (shadow offset, blur radius, spread) and calculates the required pixel padding for the top, bottom, left, and right margins.
  • Intermediate Texture Allocation: The filter allocates an offscreen render target (gs_texrender_t) whose width and height equal the base width plus horizontal padding, and base height plus vertical padding.
  • Coordinate Remapping: The native source texture is drawn into this larger buffer with an offset. The shadow is synthesized around it using pixel shaders.
  • Callback Interception: The filter plugin defines its own get_width and get_height API callbacks, returning base_width + padding_x and base_height + padding_y.

Scene Item Bounding Box Evaluation

The scene canvas manages placement via obs_scene_item objects. When calculating the wireframe selection box and applying transformations, the scene item relies on the filtered output:

  • Matrix Transformation: The scene item generates a local transform matrix based on scale, rotation, and alignment. The extents of this matrix are derived from the dimensions returned by the outermost filter.
  • Bounding Types: If a source uses bounding box constraints (such as Scale to inner bounds or Stretch to bounds), OBS fits the expanded raster into the designated box. Consequently, adding a drop shadow to a constrained source will slightly shrink the core content to ensure both the asset and the drop shadow fit inside the defined bounds.
  • Filter Ordering Impact: Because the bounding box queries the final filter in the chain, ordering matters. If an expansion filter is placed before a crop filter, the crop filter will evaluate the expanded dimensions, potentially clipping the shadow and reporting a final size restricted by the crop parameters. If placed after the crop, the shadow expands beyond the cropped boundary and updates the bounding box accordingly.
