Syphon vs NDI in OBS: Architectural Differences

This article provides a technical comparison of the architectural differences between Syphon and Network Device Interface (NDI) video ingestion in OBS Studio. While both technologies route live video between applications, they rely on fundamentally different computational layers: Syphon uses macOS-native inter-process GPU memory sharing for zero-latency local routing, whereas NDI functions as an encode-transport-decode network protocol designed for distributed local area networks.

Core Architectural Model

  • Syphon: Syphon is an open-source macOS technology built around local Inter-Process Communication (IPC). It leverages Apple’s IOSurface framework to share GPU-hosted textures directly between applications without moving pixel data through the host CPU or system RAM. In OBS Studio, the Syphon Client plugin binds directly to the shared texture published by another local application (such as Resolume, MadMapper, or TouchDesigner).
  • NDI: Developed by Vizrt (formerly NewTek), NDI is an AV-over-IP protocol engineered for bi-directional video transport over standard Ethernet networks (LAN). Rather than sharing memory addresses, NDI acts as a client-server broadcast system. In OBS Studio, the obs-ndi plugin acts as an NDI receiver, listening on network sockets for packetized streams broadcast across the network via mDNS discovery.

Data Path and Pipeline Execution

The pipeline through which frames travel from source to OBS Studio illustrates the mechanical contrast:

Syphon Pipeline:
[Source App] -> Render to GPU Texture -> IOSurface Handle -> [OBS Syphon Plugin] -> OBS GPU Pipeline

NDI Pipeline:
[Source App] -> Frame Render -> Codec Compression -> Packetization -> TCP/UDP Socket -> Network Switch -> Socket Read -> Frame Reassembly -> Codec Decompression -> OBS Frame Buffer

The Syphon Data Path (Zero-Copy)

  1. The sending application renders a frame directly to a macOS Metal or OpenGL texture.
  2. Syphon registers the underlying IOSurface handle globally within the operating system.
  3. The OBS Studio Syphon source requests the handle and maps the exact memory region into its own rendering context.
  4. Data remains strictly inside Video RAM (VRAM). The transfer incurs zero memory copy operations, no encoding stage, and no round-trip through CPU memory.

The NDI Data Path (Encode-Transport-Decode)

  1. The source application generates a raw frame.
  2. The NDI sender encodes the video data using a proprietary intra-frame DCT/wavelet compression algorithm (NDI High Bandwidth) or H.264/HEVC (NDI|HX).
  3. The compressed stream is packetized into IP packets and transmitted through the host operating system's network stack via TCP or UDP.
  4. The network interface card (NIC) transmits the packets across the physical network layer.
  5. OBS Studio’s NDI plugin receives the packets, reassembles them, and decompresses the stream using the host CPU or an available hardware decoder.
  6. The uncompressed frame is uploaded into system RAM, then copied to VRAM for OBS to composite.

Latency and Timing

  • Syphon: Operates at the hardware display refresh boundary. Because it simply shares a pointer to an already-rendered GPU surface, latency is sub-frame (effectively 0 ms of processing delay). Synchronization is locked to the host GPU clock and the macOS window server.
  • NDI: Introduces latency governed by compression passes, packet packetization, network routing, buffering, and decompression. Even on an unmanaged Gigabit switch using NDI High Bandwidth, latency typically ranges from 1 to 3 frames (approximately 16 ms to 50 ms at 60 fps). Network jitter and buffer sizes can add additional overhead.

System Resource Footprint

  • Compute (CPU/GPU): Syphon introduces negligible overhead; the CPU is only required to exchange surface handles, and the GPU performs no additional rendering passes. NDI imposes measurable compute overhead because both the sender and the receiver (OBS) must continuously execute compression and decompression routines.
  • Memory Bandwidth: Syphon bypasses system RAM entirely by retaining frames in VRAM. NDI requires multiple read/write cycles across the PCIe bus (VRAM to RAM, RAM to network stack, and the inverse on the receiving end in OBS).
  • Network Infrastructure: Syphon consumes 0 bps of network throughput and requires no network hardware. NDI High Bandwidth consumes roughly 100–250 Mbps per 1080p60 stream and 250–400 Mbps per 4K60 stream, requiring managed Gigabit or 10GbE network infrastructure to prevent frame dropping.

Scope and Deployment

  • Syphon: Strictly intra-machine and platform-dependent. It cannot natively pass video between two separate physical computers and operates exclusively within macOS.
  • NDI: Inter-machine and platform-agnostic. It routes audio and video seamlessly across macOS, Windows, and Linux devices over physical network infrastructure, allowing OBS Studio to capture feeds from external systems, dedicated hardware encoders, and remote production setups.
