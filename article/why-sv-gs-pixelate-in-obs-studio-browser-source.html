Why SVGs Pixelate in OBS Studio Browser Source

Scalable Vector Graphics (SVGs) are mathematically designed to scale infinitely without losing quality, yet users often encounter blurry or pixelated graphics when displaying them via an OBS Studio browser source. This issue stems not from the SVG format itself, but from the way OBS Studio’s underlying browser engine rasterizes, caches, and scales web-based graphics onto its rendering canvas. Understanding how the Chromium Embedded Framework treats vector graphics and how OBS manages internal resolutions allows you to eliminate these artifacts completely.

The Chromium Rasterization Process

OBS Studio relies on the Chromium Embedded Framework (CEF) to render web pages, HTML overlays, and SVGs inside the browser source. Although an SVG consists of mathematical vectors (paths, curves, and points), computer displays ultimately require raster pixels.

When CEF loads an SVG, it calculates the vector paths and rasterizes them into a fixed-resolution pixel buffer (bitmap). Once CEF renders this bitmap to hand off to OBS, the vector data is discarded for that frame. From that moment forward, the browser source behaves like a static image.

Canvas Transformation vs. Source Resolution

The primary cause of pixelation occurs when an asset is enlarged using OBS canvas transform handles rather than the browser source’s native properties:

  1. Default Source Dimensions: When you create a browser source, OBS assigns it a default resolution (often 800×600 pixels). CEF renders the SVG precisely to fit those initial dimensions.
  2. OBS Scene Scaling: If you drag the red bounding box in the OBS preview window to scale the element to 1080p or 4K, OBS does not request a higher-resolution render from CEF. Instead, the OBS compositor takes the existing 800×600 pixel texture and stretches it across the scene.
  3. Texture Interpolation: Stretching this pre-rasterized texture forces OBS to use texture filtering (such as bilinear or bicubic interpolation), creating visible blurriness, jagged edges, and pixelation artifacts on what should be crisp vector lines.

Internal CSS and Viewport Configuration

Pixelation can also occur entirely within CEF before OBS touches the image. If an SVG lacks a defined viewBox attribute or contains fixed width and height dimensions in its internal XML or accompanying CSS, Chromium renders the image at that fixed size.

If CSS rules inside the browser source (such as transform: scale(2)) attempt to upscale an SVG that Chromium has already locked to a smaller rendering layer, the browser itself performs a bitmap upscale rather than re-rasterizing the vector paths at the higher resolution.

GPU Layer Caching

Modern versions of CEF use GPU acceleration to optimize performance during live streaming. To minimize CPU overhead, Chromium frequently promotes complex SVG elements or animated vectors to isolated GPU composition layers. These layers are cached as textures in VRAM. If an animation or scene transition scales the layer, the GPU frequently samples the existing cached texture instead of re-tessellating the vector paths on every frame, resulting in temporary or persistent aliasing artifacts.

How to Resolve the Artifacts

To maintain perfect vector clarity inside OBS Studio:

  • Match Source Dimensions to the Canvas: Open the Browser Source properties in OBS and set the Width and Height values directly to match your canvas size (e.g., 1920×1080) instead of scaling the source using the red transform box.
  • Configure the SVG ViewBox: Ensure the SVG file includes a dynamic viewBox attribute (e.g., viewBox="0 0 100 100") and set the CSS styling to width: 100%; height: 100%; so it expands natively to the full boundaries of the OBS browser frame.
  • Reset Transform in OBS: Right-click the source in your OBS preview window, navigate to Transform, and select Reset Transform (Ctrl + R) to ensure the source renders at a 1:1 pixel mapping.
