OBS Studio JSON Scene Hierarchy and Transforms

OBS Studio stores its entire configuration, including scene layouts, source configurations, and transitions, inside structured JSON files within its user profile directory. Rather than relying on a strictly separated relational database, OBS serializes its layout as a flat list of polymorphic source objects where scenes themselves are treated as sources. This article breaks down how OBS Studio builds parent-child scene relationships through referenced arrays and manages visual spatial data using dedicated scene item transform schemas.

The Flat Source Architecture

At the root of an OBS scene collection JSON file is a top-level dictionary containing general metadata, audio monitoring settings, and a primary array labeled sources.

OBS Studio employs an architectural pattern where a "scene" is technically a specialized visual source whose internal identifier is scene. Because both individual inputs (such as display captures, webcams, or media sources) and full scenes share the same base structure, they all reside side by side within the sources array.

Each source entry contains primary metadata:

  • name: The unique string name assigned to the source or scene.
  • id: The source type identifier (for example, scene, browser_source, or wasapi_input_capture).
  • settings: An object housing configuration variables specific to that source type.

Representing Nested Scenes

Because all sources reside in a flat list, nested scene relationships are represented through composition rather than deep JSON object nesting.

When a scene contains other sources or sub-scenes, those elements are declared inside the parent scene's settings property within an array called items.

{
  "name": "Main Scene",
  "id": "scene",
  "settings": {
    "items": [
      {
        "name": "Sub-Scene Overlay",
        "id": 1,
        "visible": true,
        "locked": false,
        "rot": 0.0,
        "pos": { "x": 0.0, "y": 0.0 },
        "scale": { "x": 1.0, "y": 1.0 }
      }
    ]
  }
}

When OBS renders "Main Scene," it iterates through its items array:

  1. It reads the item reference (via the name field).
  2. It looks up that matching name in the root sources array.
  3. If the resolved source is of type id: "scene", OBS initializes a sub-pipeline rendering pass, processing the child scene’s own items array before compositing the output back into the parent scene.

Circular nesting (e.g., Scene A containing Scene B, which also contains Scene A) is detected and blocked by the application runtime during composition to prevent infinite recursion loops.

The Scene Item Transform Structure

Every element inside a scene's items array contains dedicated transform properties that dictate its position, scale, rotation, alignment, and cropping relative to that scene's coordinate space.

Modern versions of OBS serialize these attributes either directly on the item or grouped within an associated transform dictionary. The core parameters include:

1. Position and Alignment

  • pos: A 2D coordinate object { "x": float, "y": float } describing the element’s placement within the parent scene’s canvas (typically defined in base canvas pixels, such as 1920x1080).
  • align: A bitmask integer representing source anchor points. OBS uses standard bit flags to anchor sources to edges or corners (e.g., 5 corresponds to top-left alignment: Top [1] + Left [4]).

2. Scaling and Rotation

  • scale: A 2D multiplier { "x": float, "y": float } defining size changes relative to the native resolution of the underlying source. A scale of 1.0 maintains native dimensions, while 2.0 doubles them.
  • rot: A floating-point value indicating clockwise rotation in degrees, ranging from 0.0 to 360.0.

3. Bounds and Scaling Behavior

When sources are forced into specific bounding containers (e.g., "Scale to inner bounds"), OBS serializes bounding attributes:

  • bounds: A 2D vector { "x": float, "y": float } setting the box dimensions.
  • bounds_type: An integer mapping to bounding box types (0 = None, 1 = Stretch to bounds, 2 = Scale to inner bounds, 3 = Scale to outer bounds, etc.).
  • bounds_align: An alignment integer defining where the source sits inside the bounding box.

4. Cropping

  • crop_left, crop_right, crop_top, crop_bottom: Integer values specifying how many pixels are cut from each edge of the raw source prior to applying scaling and positioning.

Local vs. Global Coordinate Inheritance

Transforms in OBS are strictly hierarchical and local to their immediate container.

When a sub-scene is nested inside a parent scene:

  • Sources inside the child scene calculate their layout relative to the child scene's internal base dimensions.
  • The parent scene then treats the rendered output of the child scene as a single flat texture.
  • The parent scene's pos, scale, and rot values are applied to that compiled texture as a whole.

This separation ensures that complex multi-source layouts can be designed once within a dedicated sub-scene, then shifted, scaled, or animated within multiple master production scenes without disrupting the internal spatial relationships of the child sources.
