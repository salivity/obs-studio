OBS Studio Encoder Stall with High-Bitrate HEVC

An encoder stall error in OBS Studio occurs when the software's encoding pipeline is forced to halt because it cannot offload encoded video data fast enough to keep up with real-time rendering. When streaming or recording high-bitrate HEVC (H.265) directly to an external storage drive, the combination of dense frame compression, sudden data throughput bursts, and external hardware throughput limitations frequently creates a bottleneck. This article examines the primary hardware, protocol, and configuration causes behind encoder stalls when writing high-bitrate HEVC streams to external media.

Storage Write Speed and Cache Exhaustion

The most frequent hardware cause of an encoder stall is the external drive's inability to maintain a sustained write speed. Many portable SSDs and flash drives rely on pseudo-SLC (Single-Level Cell) write caches to deliver high advertised speeds.

During high-bitrate HEVC recording:

  • Cache Depletion: Once the drive's rapid SLC cache fills up, write speeds often plummet to native TLC or QLC speeds—sometimes dropping as low as 30 to 80 MB/s.
  • Buffer Backlog: If the instantaneous write speed falls below the bitrate demand of the stream, the OBS internal output buffer fills to capacity.
  • Pipeline Halt: Once the RAM buffer is exhausted, OBS must pause the hardware encoder to prevent memory corruption or software crashes, throwing the encoder stall error.

Mechanical external hard drives (HDDs) are especially vulnerable to this, as their maximum sequential write speeds rarely exceed 120–140 MB/s and fall significantly during concurrent operations or head repositioning.

HEVC Bitrate Spikes and Keyframe Density

HEVC is an exceptionally dense, complex compression format. While it offers roughly 50% better compression efficiency than H.264 at identical visual quality, high-bitrate HEVC presents distinct challenges:

  • I-Frame (Keyframe) Surges: In scenes with intense motion or complete scene changes, HEVC keyframes generate massive data bursts. If using Variable Bitrate (VBR) or Constant Quality (CQP) modes, an instantaneous spike can exceed the average bitrate by three to four times.
  • Storage Ingestion Latency: If the external interface cannot immediately absorb this sudden volume of data, the frame queue backs up into the encoder immediately.

USB Bus Contention and Protocol Limitations

How the drive connects to the host computer plays a decisive role in whether the data pipeline stalls:

  • Shared Host Controller Bandwidth: External drives connected via standard USB ports often share a single internal root hub with other high-bandwidth devices, such as USB capture cards, high-resolution webcams, and audio interfaces. When total bandwidth saturates, the operating system introduces packet latency, delaying write acknowledgments.
  • UASP vs. BOT Protocols: Inexpensive drive enclosures running the legacy Bulk-Only Transport (BOT) protocol can only handle one command at a time. Drives using USB Attached SCSI Protocol (UASP) queue multiple commands simultaneously. Without UASP, high-bitrate streaming triggers command queuing delays.
  • Cable and Port Throttling: Using USB 3.0 (5 Gbps) ports instead of USB 3.2 Gen 2 (10 Gbps) or Thunderbolt connections narrows overall throughput and increases bus latency under heavy load.

Operating System and File System Overhead

Software-level communication between OBS Studio and the external drive can also trigger stalls:

  • exFAT File System Latency: Many external drives ship pre-formatted as exFAT for cross-platform compatibility. exFAT lacks efficient allocation metadata handling and journaling. As file sizes expand during multi-gigabyte HEVC captures, file allocation table update delays can block write operations.
  • USB Power Management: Operating system features like USB Selective Suspend or aggressive drive sleep policies can momentarily reduce power to the drive or controller during minor lulls in activity, causing a sudden multi-second I/O lock when data resumes.

Preventing Encoder Stalls in OBS

To eliminate encoder stalls during high-bitrate HEVC recording to external storage:

  1. Record Internally First: Set OBS to record to an internal NVMe SSD, then configure an automated script or tool to move completed recordings to external drives.
  2. Use High-Sustained-Write SSDs: If direct external recording is mandatory, use an external NVMe enclosure supporting UASP over USB 3.2 Gen 2 or Thunderbolt, equipped with a drive featuring high sustained TLC write performance.
  3. Format to NTFS or APFS: Reformat external drives to the native file system of your operating system (NTFS on Windows, APFS on macOS) instead of exFAT.
  4. Isolate USB Ports: Ensure the storage drive is connected directly to a motherboard rear I/O port tied to an unshared USB controller.
