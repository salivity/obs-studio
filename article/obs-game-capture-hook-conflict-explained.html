OBS Game Capture Hook Conflict Explained

A "hook conflict" entry in an OBS Studio Game Capture log reveals that another background application is actively competing with OBS to intercept the target game's graphics rendering pipeline. When multiple applications attempt to inject code into the same DirectX, OpenGL, or Vulkan rendering functions simultaneously, OBS flags this collision in its log files. This conflict indicates that a third-party software overlay or monitoring tool is either blocking OBS from capturing frames, altering the expected render chain, or causing instability that can lead to black capture screens and game crashes.

How Graphics Hooking Works

To capture video directly from a game without significant performance loss, OBS Studio uses a technique called graphics hooking. OBS injects a dynamic-link library (DLL)—typically graphics-hook32.dll or graphics-hook64.dll—into the game's active process. This DLL intercepts rendering calls right before the final frame is sent to the display, copying the image data directly into OBS.

What the Conflict Entry Reveals

When the log records a hook conflict, it provides specific diagnostic insight into your system's software environment:

  • Simultaneous Injection: Another application has injected its own DLL into the same game process to render visual elements on top of the game or monitor system performance.
  • Overridden Function Pointers: The competing software has hooked the graphics API in a way that disrupts OBS Studio’s hook chain, preventing OBS from reading the frame buffer.
  • Security or Anti-Cheat Interference: Some anti-cheat systems or security utilities treat simultaneous hooks as suspicious behavior, selectively blocking OBS's hook while allowing whitelisted overlays.
  • Execution Order Issues: The conflict often reveals that the third-party software initialized after the game started or after OBS hooked the process, breaking the established capture pipeline.

Common Software Causing Hook Conflicts

Third-party applications responsible for hook conflicts typically fall into three categories:

  • Performance and Hardware Overlays: RivaTuner Statistics Server (RTSS), MSI Afterburner, EVGA Precision X, and NZXT CAM.
  • Social and Streaming Overlays: Discord, Steam, EA App, Ubisoft Connect, and Overwolf.
  • Driver-Level Utilities: NVIDIA GeForce Experience (ShadowPlay overlay), AMD Software: Adrenalin Edition, and Razer Cortex.

Resolving Hook Conflicts in OBS Studio

To eliminate hook conflicts and restore reliable game capture, apply the following adjustments:

  • Disable In-Game Overlays: Turn off the overlay functionality in applications like Discord, Steam, and GeForce Experience for the specific game you are capturing.
  • Configure RTSS/MSI Afterburner: If using RivaTuner Statistics Server, open its settings, set the "Application detection level" to low, or enable "Custom Direct3D support." You can also toggle "Use Microsoft basic render driver" or add an injection delay so OBS hooks the game first.
  • Adjust Launch Order: Start OBS Studio as an administrator before launching the game, allowing OBS to establish its graphics hook before secondary applications inject their code.
  • Use Alternative Capture Methods: If an overlay is strictly necessary for your workflow, switch the OBS source from Game Capture to Window Capture using the Windows Graphics Capture (WGC) method, which bypasses process injection entirely.
