Register Frontend Event Callbacks in OBS Studio Plugins

Developing native C or C++ plugins for OBS Studio often requires responding to UI-level changes, such as when a user switches scenes, starts streaming, or exits the application. This functionality is provided by the OBS Frontend API library (obs-frontend-api), which allows plugins to hook directly into the core application state. By utilizing obs_frontend_add_event_callback, developers can attach custom callback functions to capture and process these high-level lifecycle and interface notifications in real time.

Required Header and Dependencies

To interact with the frontend events, your plugin must link against obs-frontend-api and include its header:

#include <obs-module.h>
#include <obs-frontend-api.h>

The Event Callback Signature

The frontend event callback must match the obs_frontend_event_cb function pointer definition:

void on_frontend_event(enum obs_frontend_event event, void *private_data);
  • event: An enumerated value representing the specific event triggered (e.g., OBS_FRONTEND_EVENT_STREAMING_STARTED, OBS_FRONTEND_EVENT_SCENE_CHANGED).
  • private_data: A generic pointer to custom context or state passed during registration.

Registering and Unregistering Callbacks

Registration is typically handled during plugin initialization in obs_module_load(), while cleanup must be performed in obs_module_unload() to prevent dangling pointers and crashes when the plugin shuts down.

  • Register: obs_frontend_add_event_callback(on_frontend_event, context_pointer);
  • Unregister: obs_frontend_remove_event_callback(on_frontend_event, context_pointer);

Implementation Example

The following minimal example demonstrates handling streaming state changes and scene updates within a native C plugin:

#include <obs-module.h>
#include <obs-frontend-api.h>

OBS_DECLARE_MODULE()

static void handle_frontend_event(enum obs_frontend_event event, void *private_data)
{
    switch (event) {
    case OBS_FRONTEND_EVENT_STREAMING_STARTED:
        blog(LOG_INFO, "OBS stream has started.");
        break;

    case OBS_FRONTEND_EVENT_STREAMING_STOPPED:
        blog(LOG_INFO, "OBS stream has stopped.");
        break;

    case OBS_FRONTEND_EVENT_SCENE_CHANGED:
        blog(LOG_INFO, "Active scene changed.");
        break;

    case OBS_FRONTEND_EVENT_EXIT:
        blog(LOG_INFO, "OBS is closing.");
        break;

    default:
        break;
    }
}

bool obs_module_load(void)
{
    obs_frontend_add_event_callback(handle_frontend_event, NULL);
    blog(LOG_INFO, "Plugin loaded and frontend callback registered.");
    return true;
}

void obs_module_unload(void)
{
    obs_frontend_remove_event_callback(handle_frontend_event, NULL);
    blog(LOG_INFO, "Plugin unloaded and frontend callback removed.");
}

Common Frontend Event Types

The enum obs_frontend_event includes a wide array of states, such as:

  • OBS_FRONTEND_EVENT_STREAMING_STARTING / OBS_FRONTEND_EVENT_STREAMING_STARTED / OBS_FRONTEND_EVENT_STREAMING_STOPPING / OBS_FRONTEND_EVENT_STREAMING_STOPPED
  • OBS_FRONTEND_EVENT_RECORDING_STARTED / OBS_FRONTEND_EVENT_RECORDING_STOPPED
  • OBS_FRONTEND_EVENT_SCENE_CHANGED
  • OBS_FRONTEND_EVENT_SCENE_LIST_CHANGED
  • OBS_FRONTEND_EVENT_PROFILE_CHANGED
  • OBS_FRONTEND_EVENT_EXIT

All callbacks run on the main UI thread. Long-running or blocking operations executed inside the callback handler should be dispatched to a separate worker thread to avoid freezing the OBS Studio user interface.
