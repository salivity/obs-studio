OBS Studio 4K High-DPI Scaling for Browser Docks

OBS Studio utilizes a combination of the Qt application framework and the Chromium Embedded Framework (CEF) to render user interface elements and custom browser docks. When deployed on 4K multi-monitor workstations, high-DPI scaling behavior depends on operating system display settings, the specific scaling factor applied to each monitor, and how Qt passes coordinate metrics to CEF. This article examines the technical mechanics behind how OBS Studio handles browser dock scaling across mixed-resolution displays, common visual artifacts encountered on 4K monitors, and the methods used to achieve crisp, responsive rendering.

The Underlying Architecture: Qt 6 and CEF

OBS Studio builds its primary graphical user interface on Qt, while custom browser docks are powered by the Chromium Embedded Framework. Beginning with OBS Studio version 28, the software migrated to Qt 6, which natively supports modern Per-Monitor DPI Awareness (Per-Monitor V2 on Windows).

When a user opens a custom browser dock, the following process occurs:

  1. The operating system informs Qt of the display's scale factor (such as 150% or 200% on a 4K panel).
  2. Qt applies this scaling factor to the dock window wrapper.
  3. CEF detects the target display scale factor and adjusts Chromium’s internal Device Pixel Ratio (DPR).
  4. Web content inside the dock renders at the native hardware resolution of that monitor rather than being stretched via simple bitmap upscaling.

Mixed-DPI and Multi-Monitor Handling

Complications frequently arise on workstations featuring mismatched displays—for example, a primary 4K monitor set to 150% scaling paired with a secondary 1080p monitor set to 100% scaling.

When a browser dock is dragged from a 4K monitor to a standard 1080p display, OBS must trigger a dynamic DPR update inside CEF. In modern versions of OBS Studio:

  • Dynamic Recalculation: CEF catches the monitor change event and dynamically recalculates CSS pixels to device pixels.
  • Fractional Scaling Quirks: Non-integer scaling values (such as 125%, 150%, or 175%) occasionally cause rounding errors within Chromium's layout engine. This can result in micro-blurriness, 1-pixel layout gaps, or slightly soft text rendering compared to integer scaling (100% or 200%).
  • Dock Detaching: When docks are undocked into standalone floating windows, the window manager directly handles DPI transitions. When docked within the main OBS window, the entire composite UI relies on Qt's handling of the display where the primary window currently resides.

Known Visual Artifacts on 4K Setups

Multi-monitor setups with 4K screens may exhibit specific rendering anomalies in custom browser docks:

  • DPI Transition Lag: Rapidly moving an undocked browser panel across monitor boundaries can produce a brief delay where the panel retains the scaling factor of the previous display, temporarily appearing oversized or undersized.
  • Canvas Misalignment: Third-party web applications loaded into docks (such as chat overlays, stream alerts, or control surfaces) that rely on fixed-pixel canvas elements may fail to detect DPI changes automatically, requiring a manual refresh of the dock.
  • Off-Screen Rendering Artifacts: Because CEF uses hardware-accelerated off-screen rendering within OBS, GPU driver conflicts or multi-GPU setups (e.g., integrated GPU running secondary screens and a discrete GPU running the 4K display) can disrupt texture sharing, leading to flickering docks.

Optimizing High-DPI Browser Docks

To ensure maximum visual clarity and responsiveness across 4K displays:

  • Use Integer Scaling Factors: Configuring 4K displays to 200% scaling matches exact pixel multiples, completely eliminating fractional rounding artifacts in CEF.
  • Set Windows High-DPI Overrides: If text remains blurry, users can adjust the executable compatibility settings in Windows by setting high-DPI scaling override to "Application." This forces OBS and CEF to handle all scaling internally rather than letting the Windows Desktop Window Manager (DWM) upscale the window as a bitmap.
  • Apply Custom CSS Zoom: For web panels that do not scale text comfortably under 4K metrics, adding custom CSS zoom directly within the webpage or utilizing the built-in browser zoom controls (Ctrl + Mouse Wheel while focused inside the dock) forces CEF to scale text and UI elements to a legible size.
  • Maintain Display Alignment: Ensuring all connected displays align cleanly within the operating system's virtual display layout prevents boundary-snapping bugs when detaching and positioning docks across physical panels.
