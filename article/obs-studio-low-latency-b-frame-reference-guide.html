OBS Studio Low-Latency B-Frame Reference Guide

Bi-directional predictive frames (B-frames) increase video compression efficiency by referencing both preceding and subsequent frames, but this process introduces intrinsic pipeline delay that conflicts with low-latency delivery. When configuring OBS Studio for real-time cloud platforms and interactive gaming, managing B-frame references requires directly balancing visual fidelity against buffer lag. OBS Studio facilitates this by allowing streamers to limit, reconfigure, or completely disable B-frame generation across various hardware and software encoders.

The Mechanics of B-Frames and Encoder Latency

B-frames calculate motion vectors by looking backward to earlier I- or P-frames and forward to future frames in the display order. For an encoder to construct a B-frame, it cannot output frames immediately; it must hold the current frame in memory, ingest and compress the upcoming reference frame, and then encode the intermediate B-frame.

This out-of-order processing creates two distinct latency penalties:

  • Encode Buffer Lag: The encoder must maintain a lookahead buffer to analyze future frames.
  • Decode Buffer Lag: The cloud ingest server and client media player must hold incoming frames in a reorder buffer (presentation time vs. decode time) before rendering them to the viewer.

In ultra-low-latency scenarios, such as cloud gaming or interactive live-streaming where inputs dictate gameplay, this reordering buffer adds between 33 and 100 milliseconds of unavoidable pipeline latency.

How OBS Controls B-Frames by Encoder

OBS Studio does not process frame references internally; instead, it exposes the reference parameters of the underlying encoder library (NVIDIA NVENC, AMD AMF, Intel QuickSync, or x264).

NVIDIA NVENC

Within OBS Studio’s Advanced Output settings, NVENC provides explicit control over the "Max B-frames" setting:

  • Zero B-Frames (Max B-frames = 0): Setting this to zero disables B-frame generation entirely. The video stream consists strictly of an IPPP cadence. This eliminates the frame reorder buffer, allowing the cloud platform to decode and present each frame the instant it arrives over the network.
  • B-Frame Reference Mode: Modern NVENC architectures (Turing, Ampere, and Ada Lovelace) support using B-frames as references for other B-frames (hierarchical B-frames). When low-latency presets (such as P1–P3) or the "Low Latency" tuning modes are selected in OBS, the software automatically instructs the NVENC SDK to disable B-frame referencing to prioritize rapid throughput over bitrate efficiency.

Software (x264)

When encoding via the CPU using x264, low latency is enforced through custom encoder options or tuning parameters:

  • Setting the Tune dropdown to zerolatency forces bframes=0 alongside disabling the lookahead buffer (rc-lookahead=0) and sliced threads.
  • Alternatively, manual configuration via the custom x264 settings box using bframes=0 disables bi-directional referencing while leaving spatial compression settings intact.

AMD AMF and Intel QuickSync

Both hardware encoders mimic NVENC's implementation in OBS. Setting the B-frame pattern or count to 0 prevents the generation of backward-dependent frames, restricting the stream to I- and P-frame hierarchies suitable for immediate cloud transcoding.

Cloud Platform Ingest Requirements

The optimal B-frame reference configuration in OBS Studio depends on the ingest protocol used by the target cloud infrastructure:

  • WebRTC and Real-Time Streaming Platforms: WebRTC-based interactive setups cannot handle frame reordering buffers. OBS streams targeting WebRTC must have B-frames strictly set to 0. Any non-zero B-frame value will lead to decoding artifacts, packet drops, or outright stream rejection by the media server.
  • Low-Latency HLS (LL-HLS) and Low-Latency DASH (LL-DASH): Cloud ingest engines using chunked transfer modes can tolerate 1 or 2 B-frames if bandwidth conservation is vital. However, for fast-motion gaming content, configuring 0 B-frames ensures uniform packet sizing, which stabilizes chunk transmission and mitigates jitter across edge nodes.
  • Enhanced RTMP and SRT: Secure Reliable Transport (SRT) manages latency via a configured hardware buffer. Disabling B-frames in OBS allows users to lower the SRT latency multiplier to its minimum thresholds without inducing presentation-timestamp (PTS) delivery errors.

Disabling B-frames increases the bitrate required to maintain high visual clarity during high-motion gaming scenes. To offset the loss of B-frame compression efficiency in zero-latency OBS profiles, allocate a higher Constant Bitrate (CBR) or utilize more aggressive spatial quantization settings within the encoder.
