How OBS Configures Opus Bitrate for WebM

This article provides an overview of how OBS Studio manages Opus audio bitrates when multiplexing into WebM containers. It details the underlying encoder architecture, the distinction between standard and custom FFmpeg output modes, how user settings map to encoder parameters, and the default behavior of Opus regarding Variable Bitrate (VBR) processing.

The Underlying Encoder Architecture

OBS Studio does not implement its own Opus encoder directly. Instead, it relies on the FFmpeg multimedia framework to handle both the Opus audio encoding (typically via the libopus library) and the WebM container multiplexing (libwebm or FFmpeg's native WebM muxer). When configuring audio for a WebM output, the configuration parameters set within the OBS interface are translated into FFmpeg's AVCodecContext structures before encoding begins.

Output Mode Configurations

OBS Studio provides two primary workflows for generating WebM files with Opus audio:

  1. Advanced Output (Standard Recording): When the recording format is set to WebM and the audio encoder is set to Opus, OBS uses its internal track-based audio system. The bitrate for each audio track is defined under the Audio tab in the Output settings window. OBS exposes standard discrete bitrate values—typically ranging from 64 kbps up to 320 kbps per track. Once assigned, OBS passes the selected track bitrate directly to the audio encoder instance assigned to that track.

  2. Advanced Output (Custom Output / FFmpeg): If WebM is configured through the Custom Output (FFmpeg) mode, the user bypasses OBS's standard track manager. In this mode, the container format is explicitly set to webm, and the audio encoder is set to libopus. The audio bitrate is defined manually in kilobits per second (kbps) via the settings field or through custom encoder arguments (e.g., b:a=160k).

Bitrate Allocation and Rate Control (VBR vs. CBR)

By default, the Opus encoder operates in Variable Bitrate (VBR) mode. When OBS Studio passes a target bitrate (for example, 160 kbps) to FFmpeg:

  • Target Average: The configured bitrate is treated by libopus as an average target rather than a strict ceiling. Complex audio passages may exceed this value temporarily, while silent or simple passages drop significantly lower to preserve bandwidth.
  • Per-Channel Scaling: The bitrate configured in OBS applies to the total stream. If a track is set to stereo, the encoder dynamically allocates bits across both channels based on stereo correlation, rather than strictly splitting the allocation 50/50.
  • Constrained VBR and CBR: Unless explicit custom parameters are passed via the FFmpeg custom interface (such as vbr=off or vbr=constrained), OBS relies on native Opus dynamic VBR. Constant Bitrate (CBR) is generally discouraged in Opus except for specific real-time streaming constraints where packet sizes must remain completely uniform.

Container Multiplexing

Once the Opus frames are encoded, they are packaged with their respective initialization metadata into WebM audio tracks. The WebM container uses the Matroska specification, mapping Opus packets to WebM SimpleBlocks. The container headers do not lock the audio stream to a fixed bitrate; the WebM playback engine parses each Opus frame header dynamically to decode the varying frame sizes accurately at runtime.
