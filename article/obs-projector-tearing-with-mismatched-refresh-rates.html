OBS Projector Tearing With Mismatched Refresh Rates

When using OBS Studio's fullscreen projector on a monitor that does not share the same refresh rate as your canvas or primary display, horizontal visual artifacts known as frame tearing frequently occur. This article explains the technical mechanics behind this issue, detailing how asynchronous render loops, GPU buffer flips, and Windows Desktop Window Manager (DWM) limitations interact to disrupt smooth video output across mixed-refresh-rate setups.

Understanding Screen Tearing

Screen tearing occurs when a display receives a new video frame while it is actively scanning out the previous frame from top to bottom. Because the monitor draws the image line by line, presenting a new frame halfway through this process results in the top half showing the older frame and the bottom half showing the newer frame. The boundary where these two frames collide appears as a horizontal split or "tear."

How Mismatched Refresh Rates Cause Projector Tearing

When OBS Studio outputs a fullscreen projector to a secondary display with a different refresh rate, several synchronization breakdowns happen simultaneously:

1. Decoupled Frame Delivery and Vertical Blanking (VBLANK)

OBS renders its internal video pipeline at a fixed frame rate set in your settings (commonly 60 FPS). If the target monitor runs at an asynchronous or non-multiple refresh rate—such as 75Hz, 144Hz, or even 59.94Hz versus 60Hz—the intervals at which OBS finishes a frame will not align with the monitor's vertical blanking interval (VBLANK). Without hardware-level synchronization, the GPU pushes the updated buffer mid-scan, producing visible tears.

2. Projector Window Presentation Mode

The OBS fullscreen projector is not an exclusive fullscreen application; it is a borderless, border-stripped window managed by the operating system's windowing system. Unlike full 3D applications that can command exclusive hardware V-Sync or variable refresh rate (G-Sync/FreeSync) pipelines, the projector window relies on standard desktop swap chains. If the graphics driver cannot negotiate a unified vertical sync across monitors running at distinct clock speeds, it drops synchronization on the secondary output to prevent stalling the primary display.

3. Desktop Window Manager (DWM) Desynchronization

On modern Windows systems, the Desktop Window Manager handles compositing for all connected displays. When displays run at mixed refresh rates, DWM historically struggles to sync to multiple hardware refresh intervals simultaneously. If your primary monitor runs at 144Hz and your projector runs at 60Hz, DWM must dynamically adapt its compositing clock. When prioritizing the higher-refresh primary monitor, DWM often flips the frame buffer for the 60Hz secondary display out of sync with that panel’s hardware refresh cycle, leading directly to tearing.

4. Asymmetrical Frame Pacing

If OBS renders at 60 FPS and projects to a 144Hz monitor, 144 is not cleanly divisible by 60. Even if frames do not physically tear at the hardware scanout level, the irregular delivery pattern (frame pacing jitter) creates micro-stutter and duplicate frame presentation that visually mimics tearing artifacts during fast-motion scenes.

Resolving the Issue

To eliminate frame tearing caused by mismatched rates:

  • Match Multiples: Set all displays to matching refresh rates or strict integer multiples (for example, setting the projector screen and OBS canvas to 60Hz, or setting the display to 120Hz for a 60 FPS canvas).
  • Enable Hardware-Accelerated GPU Scheduling (HAGS): In Windows Graphics Settings, turning on HAGS improves DWM’s ability to manage independent frame pacing across multi-monitor setups.
  • Cap OBS FPS Correctly: Align the internal OBS framerate with the exact refresh rate of the destination screen (e.g., set OBS to 59.94 FPS if outputting to a broadcast display running at 59.94Hz).
  • Adjust Variable Refresh Rate Settings: Disable G-Sync or FreeSync on the display receiving the fullscreen projector, as variable refresh rates can conflict with fixed-framerate desktop windows.
