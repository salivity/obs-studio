How to Pass Auth Parameters in OBS SRT Ingest

Passing custom authentication parameters through a Secure Reliable Transport (SRT) connection in OBS Studio requires appending query strings directly to the target SRT URL. Because OBS Studio utilizes standard SRT socket options, you can transmit access tokens, user credentials, and stream identifiers directly to the ingest server via query arguments in the stream settings. This guide explains how to format your SRT connection string and configure OBS Studio to ensure your authentication parameters reach the ingest endpoint successfully.

Understanding the SRT URL Format

SRT connections accept configuration options as standard URI query parameters. The base syntax for an SRT URL is structured as:

srt://<hostname-or-ip>:<port>?<parameter1>=<value1>&<parameter2>=<value2>

In the SRT protocol, authentication is typically handled either through the native passphrase parameter (for pre-shared key AES encryption) or the streamid parameter (for complex authorization tokens, usernames, or hierarchical routing rules).

Step-by-Step Configuration in OBS Studio

  1. Open Stream Settings: Launch OBS Studio, select Settings in the bottom-right control dock, and navigate to the Stream tab.
  2. Select Custom Service: Set the Service dropdown to Custom....
  3. Configure the Server Field: Enter your full SRT address, including your custom query parameters, into the Server input field.
  4. Leave Stream Key Blank: Leave the Stream Key field empty. OBS Studio parses the entire SRT configuration—including credentials and stream paths—directly from the Server field.
  5. Apply Settings: Click Apply and then OK.

Formatting Custom Authentication Parameters

Ingest servers (such as Haivision Media Platform, Nimble Streamer, or custom MediaMTX setups) parse incoming credentials differently. Depending on your ingest provider, use one of the following formats:

Method 1: Using the Standard streamid Specification

The official SRT Access Control specification uses the streamid query parameter formatted as key-value pairs separated by commas and prefixed with standard control blocks:

srt://live.example.com:9998?streamid=#!::u=myUsername,p=myPassword,r=live/streamName
  • u: Username or user identifier.
  • p: Authentication token or password.
  • r: Target resource or stream path.

Method 2: Key-Value Query Tokens

If your receiver or media server expects custom query variables, append them directly as typical URL query arguments:

srt://live.example.com:9998?token=abc123xyz&user=streamer01

Method 3: Combining Custom Tokens with SRT Socket Options

You can send your authentication parameters alongside operational SRT settings (such as latency or passphrase encryption) within the same connection string by chaining parameters with an ampersand (&):

srt://live.example.com:9998?streamid=live/streamName&auth=secretToken123&latency=200000

Critical Syntax Rules

  • URL Encoding: If your authentication credentials or stream keys contain special characters (such as @, ?, =, :, or /), convert them to URL-encoded formats (percent-encoding). For instance, replace @ with %40 and / with %2F to prevent the OBS SRT library from prematurely terminating the parameter parser.
  • Case Sensitivity: Query parameters defined by the SRT specification (like streamid, passphrase, latency, and pbkeylen) are case-sensitive and must be written in lowercase. Custom application parameters should match the casing expected by your ingest server.
