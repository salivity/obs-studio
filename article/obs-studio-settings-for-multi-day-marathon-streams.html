OBS Studio Settings for Multi-Day Marathon Streams

Streaming continuously for multiple days during charity telethons or gaming marathons requires an OBS Studio configuration focused entirely on stability, thermal regulation, and memory leak prevention rather than absolute peak visual fidelity. This guide outlines the essential encoder, network, process, and asset settings required to keep OBS Studio running smoothly for 48, 72, or 100+ consecutive hours without crashing, dropping frames, or suffering audio desynchronization.

Encoder and Video Settings

Hardware encoders must be utilized to prevent prolonged CPU thermal throttling and instability over multi-day sessions.

  • Video Encoder: Select NVIDIA NVENC (new) or AMD HW H.264/HEVC. Do not use software encoding (x264), as long runtimes can cause CPU thermal degradation and process slowdowns.
  • Rate Control: Set strictly to CBR (Constant Bitrate).
  • Bitrate: Use 6,000 to 7,500 kbps for 1080p60, or 4,500 to 5,000 kbps for 900p60/1080p30. Leaving overhead on your internet upload speed prevents network buffer bloating.
  • Keyframe Interval: Set to 2 seconds.
  • Preset: Choose P5: Slow (Good Quality) or P4: Medium. Avoid P7 (Slowest/Best Quality), as pushing the GPU's dedicated encoding chips to maximum capacity for days increases crash risk during heavy visual rendering.
  • Tuning: Set to High Quality or Low Latency.
  • Multipass Mode: Set to Single Pass or Two Passes (Quarter Resolution) to reduce GPU memory footprint.
  • Look-ahead: Disabled. Look-ahead consumes VRAM and utilizes GPU CUDA cores, which can trigger memory bloat over extended runtimes.
  • Psycho Visual Tuning: Disabled or Enabled only if hardware is well-ventilated; disabling saves micro-allocations in GPU memory.
  • Max B-frames: Set to 2.

Audio Configuration and Drift Prevention

Audio desynchronization is one of the most common issues during marathons due to timing differences across hardware clocks.

  • Sample Rate: Explicitly lock the global sample rate in OBS to 48 kHz (Settings > Audio). Ensure every capture card, USB microphone, and Windows playback device is also set to 48,000 Hz in Windows Sound Control Panel.
  • Timestamp Buffering: In the properties of capture cards and audio input devices, disable "Use Device Timestamps" if you experience audio gradually falling out of sync after 24 hours.

Network and Reconnection Protocols

Temporary network drops should never terminate the entire broadcast.

  • Automatic Reconnect: (Settings > Advanced > Automatic Reconnect)
    • Check Enable.
    • Retry Delay: Set to 2 seconds.
    • Maximum Retries: Increase to 100 (default is often too low for prolonged ISP hiccup recovery).
  • Network Optimizations: (Settings > Advanced > Network)
    • Check Enable network optimizations.
    • Check Enable TCP pacing.
    • Bind to IP: Select your specific Ethernet adapter’s local IP address instead of "Default" to prevent routing errors if secondary network interfaces toggle on.
    • Dynamic Bitrate: Check Dynamically change bitrate to manage congestion (Beta) if your connection is prone to ISP throttling, preventing dropped frames by temporarily lowering resolution quality instead of disconnecting.

Memory Leak Prevention: Browser and Media Sources

Web overlays, chat widgets, and donation tickers are the primary causes of OBS crashing after 24–48 hours due to JavaScript memory leaks.

  • Browser Source Management: Open the properties of every Browser Source (alerts, event lists, webcams).
    • Check Shutdown source when not visible.
    • Check Refresh browser when scene becomes active.
    • Check Restart browser when scene becomes active.
  • Hardware Acceleration: Keep hardware acceleration enabled for browser sources in OBS Advanced settings, but periodically execute an automated scene swap or manual cache refresh if custom CSS/JavaScript widgets are running continuously.
  • Media Sources: Ensure all recurring video stings or background loops have Close file when inactive selected to continuously flush local RAM caches.

System-Level Priorities

  • Run as Administrator: Always launch OBS Studio as an administrator. This guarantees Windows gives OBS top scheduling priority in the DirectX and GPU render pipelines, preventing dropped frames when games hit 100% GPU utilization.
  • Process Priority: In OBS (Settings > Advanced > General), set Process Priority to High or Above Normal.
  • Windows Sleep/Update Policies: Set Windows Power Options to "High Performance," disable USB Selective Suspend, and temporarily pause Windows Updates for 7 days to prevent unexpected background reboots during the marathon.
