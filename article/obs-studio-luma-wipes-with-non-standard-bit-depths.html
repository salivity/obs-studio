OBS Studio Luma Wipes with Non-Standard Bit Depths

This article examines the internal pipeline OBS Studio uses to render custom luma wipe transitions when supplied with grayscale gradient bitmaps featuring non-standard bit depths. It details the process from initial image decoding and color normalization to GPU texture allocation and pixel shader execution, explaining how unusual bit allocations impact transition smoothness, performance, and visual artifacts.

Image Ingestion and Decoding

When a user selects a custom bitmap for a luma wipe transition in OBS Studio, the software does not pass the raw file directly to the graphics rendering engine. Instead, the file is processed through OBS Studio's image loading subsystem (libobs/graphics), which relies on platform-native decoding libraries or third-party decoders like FFmpeg and stb_image.

When encountering non-standard bit depths—such as 1-bit monochrome, 2-bit or 4-bit indexed palettes, or high-depth 16-bit integer grayscale images—the decoder normalizes the pixel data into a format compatible with the rendering backend. Sub-8-bit formats (such as 1-bit or 4-bit images) are expanded by looking up the palette values or bit-shifting the packed integer values into standard 8-bit channels. High-depth formats, such as 16-bit grayscale PNGs, are typically downsampled to 8 bits per channel (uint8_t) during the CPU-side decoding stage to conserve memory and maintain uniform texture pipelines.

GPU Texture Conversion and Upload

Once decoded, the CPU-side image data is converted into an internal graphics surface (gs_texture_t). OBS Studio standardizes its internal transitions around common Direct3D 11 and OpenGL formats.

Regardless of whether the source file was an unusual 1-bit bitmap or a 16-bit gradient, the GPU texture is allocated as either an 8-bit single-channel texture (GS_R8) or an 8-bit four-channel texture (GS_RGBA). During this stage:

  • Values are Normalized: The 8-bit integer values (ranging from 0 to 255) are mapped to normalized floating-point values ranging from 0.0 (pure black) to 1.0 (pure white) in GPU memory.
  • Filtering Modes are Applied: OBS applies linear texture filtering (GS_FILTER_LINEAR) by default. This bilinear interpolation creates intermediate gradient steps across neighboring texels, which slightly softens hard pixel transitions introduced by low-bit-depth source files.

Shader Execution in luma_wipe.effect

The actual wipe effect is executed via the luma_wipe.effect shader file on the GPU. The shader samples the luma mask texture and compares its luminance value against the current progress of the transition, which is represented by a scalar float parameter progress ranging from 0.0 to 1.0.

  1. Luma Extraction: If the texture is loaded as an RGBA texture, the shader converts the sampled RGB color into a scalar luminance value using standard Rec. 709 weighting coefficients: \[\text{Luminance} = 0.2126R + 0.7152G + 0.0722B\] If sampled from a single-channel texture, the red channel value is used directly as the luminance reference.
  2. Threshold Testing: The shader computes a visibility threshold based on the transition's progress and a user-defined "softness" parameter. It uses smoothstep or linear interpolation functions to blend between the outgoing and incoming video frames.

Visual Implications of Non-Standard Bit Depths

Because the pipeline forces non-standard bit depths into a normalized 8-bit equivalent before shader evaluation, specific visual behaviors occur:

  • Low Bit Depths (1-bit to 4-bit): Images with 1-bit depth only contain two values (0.0 and 1.0). When used as a luma wipe, this causes an instantaneous binary transition without intermediate gradations, regardless of the softness setting, except for minimal blending along pixel borders caused by bilinear filtering. 4-bit masks provide only 16 distinct grayscale steps, resulting in noticeable posterization and stepping artifacts as the transition advances.
  • High Bit Depths (16-bit): Because the loader truncates or downsamples 16-bit data to 8 bits per channel, any potential 65,536-step gradient resolution is reduced to 256 distinct levels. While this eliminates banding that would otherwise appear with low bit depths, it does not provide true 16-bit micro-stepping; the transition behaves identically to a high-quality 8-bit grayscale source file.
