OBS WebSocket Response Code for Missing Sources

This article details the specific WebSocket response code returned by OBS Studio when an API request references a source name that does not exist in the current collection. It outlines the exact numeric code used in modern OBS versions, the structure of the error payload, and how developers should handle this response when automating OBS Studio.

The Response Code: 600 (ResourceNotFound)

In modern versions of OBS Studio (OBS Studio 28 and newer, which natively integrate obs-websocket protocol version 5), requesting a source, input, or scene item that does not exist returns the response code 600, corresponding to the identifier ResourceNotFound.

The ResourceNotFound error indicates that the requested resource identifier (such as a source or input name) could not be located inside the loaded scene collection.

Response Payload Structure

When a client sends a request referencing a nonexistent source—such as calling GetInputSettings, SetInputSettings, or GetSourceActive with an invalid inputName or sourceName—OBS Studio returns an op code 7 (RequestResponse) with a failed requestStatus.

A typical error payload looks like this:

{
  "op": 7,
  "d": {
    "requestType": "GetInputSettings",
    "requestId": "unique-request-identifier",
    "requestStatus": {
      "result": false,
      "code": 600,
      "comment": "No source was found by the name of 'NonExistentSource'."
    }
  }
}

Key fields in this response:

  • result: A boolean set to false, indicating the request failed.
  • code: The integer 600, representing ResourceNotFound.
  • comment: A human-readable message detailing the specific resource that could not be found.

Legacy Protocol Differences (obs-websocket v4.x)

If interacting with legacy installations running obs-websocket version 4.9.1 or older, the protocol did not use standardized numeric request codes. Instead, requests targeting nonexistent sources returned an "error" field with a descriptive string, typically returning "status": "error" alongside an error message such as "specified source not found" or "resource not found".

All modern implementations should target protocol version 5 and check specifically for code 600.

Handling Code 600 in Client Applications

When developing automated tools or integrations:

  1. Catch Code 600 Explicitly: Differentiate between syntax errors (such as missing required fields, code 300 or 400) and missing resources (code 600).
  2. Refresh Available Resources: If a code 600 is encountered, issue a GetInputList or GetSceneList request to verify whether the source was renamed, removed, or exists in a different scene collection.
  3. Verify Case Sensitivity: Source names in OBS Studio are case-sensitive and must match exact naming conventions, including whitespace.
