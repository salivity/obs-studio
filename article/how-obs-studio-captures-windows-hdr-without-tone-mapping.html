How OBS Studio Captures Windows HDR Without Tone Mapping

This article explains the technical process OBS Studio uses to capture raw High Dynamic Range (HDR) video directly from the Windows Desktop Window Manager (DWM). By tapping into modern Windows capture interfaces, requesting high-precision floating-point swap chain surfaces, and preserving wide color gamut data throughout its internal rendering pipeline, OBS Studio bypasses standard SDR tone mapping to record or stream true 10-bit HDR video.

The Windows DWM Composition Pipeline in HDR

In modern Windows operating systems, when HDR is toggled on in display settings, the Desktop Window Manager switches its internal composition buffer from standard 8-bit sRGB to a wide-color, high-bit-depth format—typically 16-bit floating point (DXGI_FORMAT_R16G16B16A16_FLOAT), also known as scRGB.

Tone mapping to standard dynamic range (SDR) usually occurs only when rendering output destined for an SDR monitor or when a capture application specifically requests an 8-bit SDR surface. The DWM maintains the native HDR luminance and color values in its composition tree so that HDR-capable monitors receive the full range of dynamic values via HDR10 (Rec. 2100 PQ).

Utilizing Modern Capture APIs

To retrieve raw HDR frames without downsampling or tone mapping, OBS Studio avoids legacy capture frameworks (such as GDI or standard BitBlt) and instead relies on:

  1. Desktop Duplication API (DXGI): Part of the DirectX Graphics Infrastructure, this API enables an application to access desktop frames directly from GPU memory.
  2. Windows Graphics Capture API (Windows.Graphics.Capture): A modern, low-latency API introduced in Windows 10 that allows per-window and per-monitor capture via Direct3D 11.

Both APIs allow OBS Studio to query the native pixel format of the display or window swap chain rather than forcing a conversion.

Negotiating Wide Color Formats

When OBS Studio initializes a capture session on an HDR-enabled monitor, it queries the available surface formats from the capture API. If HDR capture is enabled in OBS settings:

  • Format Selection: OBS requests surfaces formatted in DXGI_FORMAT_R16G16B16A16_FLOAT (scRGB) or DXGI_FORMAT_R10G10B10A2_UNORM (HDR10).
  • Direct Texture Access: The capture API provides a shared DirectX surface handle. Because OBS asks for the native HDR format, Windows delivers the frame data directly from the DWM composition buffer prior to any display-side SDR tone-mapping pass.

Color Space Conversion in the OBS Render Engine

Capturing the raw frame is only half the process; OBS Studio must also prevent its own rendering pipeline from clamping the color space to SDR.

  1. Color Space Interpretation: OBS interprets the incoming scRGB floating-point textures (which use linear gamma with standard Rec. 709 primaries where 1.0 represents 80 nits, extending well beyond 1.0 for HDR highlights) or native PQ signals.
  2. Internal Conversion to Rec. 2100: OBS transforms the texture coordinates from scRGB into the Rec. 2100 color space using either Perceptual Quantizer (PQ) or Hybrid Log-Gamma (HLG) transfer characteristics. This transformation is performed via Direct3D compute or pixel shaders using mathematical operations that preserve values above standard SDR limits.
  3. No Tone Mapping Applied: Because OBS treats the target profile as HDR (Rec. 2100), the shader pipeline does not run an SDR compression or tone-mapping operator (such as Reinhard or ACES SDR). The luminance values (up to 1,000 or 10,000 nits) and the wide Rec. 2020 color gamut are maintained intact.

Encoding the Raw HDR Stream

Once the texture is processed in Rec. 2100 color space, OBS passes the frame to a 10-bit hardware encoder (such as NVENC, AMD AMF, or Intel QuickSync) using P010 pixel format. Metadata containing the mastering display color volume and dynamic range parameters is injected into the video stream headers, ensuring that the exported MP4/MKV file or live stream contains pure, non-tone-mapped HDR video.
