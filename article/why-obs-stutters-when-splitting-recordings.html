Why OBS Stutters When Splitting Recordings

OBS Studio allows creators to automatically split long recordings into manageable chapters based on file size or time intervals. However, many users experience a brief video stutter, frame drop, or audio desync precisely at the moment a split occurs. This article examines the core technical causes behind this stutter, focusing on disk input/output saturation, container finalization overhead, keyframe alignment delays, and encoder thread bottlenecks.

Disk I/O Saturation and File Handshake

The primary cause of stutter during automatic file splitting is a momentary spike in storage drive activity. When OBS initiates a split, it must simultaneously perform two demanding operations: finalize and flush the buffer of the current file, and initialize, create, and allocate space for the new file on disk.

If you are recording to a mechanical hard drive (HDD), a slow SATA SSD, or an external drive, the storage controller may become overwhelmed by the sudden queue of write requests. Because the video output thread waits for storage confirmation before processing incoming frames, any input/output (I/O) latency causes the rendering pipeline to back up, resulting in dropped frames in the recording.

Container Overhead: Standard MP4 vs. MKV

The file format you choose significantly impacts split performance:

  • Standard MP4/MOV: These containers store vital metadata (the "moov atom") at the end of the file. When splitting an MP4, OBS must compile the index of all recorded audio and video samples and write this header before closing the file. This process is CPU- and disk-intensive.
  • Fragmented Formats (fMP4/fMOV or MKV): Formats like Matroska (MKV) or fragmented MP4 write data in self-contained chunks as recording happens. Splitting an MKV file requires almost no finalization overhead, whereas standard MP4 requires active indexing that frequently triggers micro-stutters.

Keyframe (GOP) Interval Discrepancies

Video compression relies on complete images called keyframes (I-frames) followed by predictive frames (P-frames and B-frames). A video file can only be cleanly split on a keyframe because new video files cannot begin with predictive data that references frames from the previous file.

If your Keyframe Interval in OBS is set to "Auto" (0), the encoder decides when to place keyframes dynamically. When the split timer or size threshold is reached, OBS may have to force an immediate keyframe or hold frames in a temporary buffer until the next natural keyframe arrives. Forcing an instantaneous I-frame creates a sudden computational spike on the encoder, which often manifests as a visible visual stutter.

Encoder and Muxer Thread Contention

OBS Studio isolates tasks across multiple threads: capturing, rendering, encoding, and muxing (packaging the encoded audio and video into the file container).

When a split occurs, the muxer thread experiences a sudden workload increase. If your system is already operating near maximum CPU or GPU utilization—often the case when running a demanding game alongside a high-bitrate recording—the operating system may fail to prioritize the muxing thread. This causes a cascade where the encoder must pause while waiting for the muxer to finish closing the previous segment, dropping frames in the transition.

How to Prevent Split Stutter

To eliminate stutter during automatic recording splits, implement the following adjustments:

  • Switch Output Formats: Use MKV or Fragmented MP4/Fragmented MOV instead of standard MP4 to eliminate container finalization delays.
  • Set a Fixed Keyframe Interval: Change your Keyframe Interval from 0 (Auto) to 2s in the Output settings so splits align predictably with GOP boundaries.
  • Upgrade Storage Targets: Record directly to an internal NVMe SSD with high sustained write speeds rather than an external drive or mechanical disk.
  • Lower Encoder Overhead: Ensure your GPU or CPU encoder utilization stays below 90% during peak gameplay to leave headroom for file transition operations.
