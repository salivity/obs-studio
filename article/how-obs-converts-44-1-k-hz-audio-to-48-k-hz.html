How OBS Converts 44.1 kHz Audio to 48 kHz

When a 44.1 kHz audio source is fed into an OBS Studio project set to a 48 kHz master sample rate, OBS transparently upsamples the incoming stream in real time to prevent pitch shifting, audio drift, and buffer under-runs. This process is managed directly by OBS Studio's internal audio subsystem, which leverages high-performance resampling libraries to mathematically interpolate new sample points, align non-matching sample rates, and deliver a coherent 48 kHz stream to the final mix.

The Resampling Engine

OBS Studio handles sample rate mismatches at the input level via its core audio pipeline (libobs/audio-io). Before an audio signal reaches the master mixer, OBS evaluates the source properties against the global settings configured under Settings > Audio.

If the input device outputs at 44,100 Hz and the project is configured for 48,000 Hz, OBS initializes a dedicated resampler instance for that specific source. On modern versions, OBS primarily relies on FFmpeg's libswresample library (or platform-native audio conversion utilities depending on the operating system and build configuration) to perform the conversion in memory.

The 147:160 Non-Integer Ratio

Converting 44.1 kHz to 48 kHz requires handling a non-integer mathematical relationship:

\[\frac{48000}{44100} = \frac{160}{147}\]

Because 44.1 does not divide evenly into 48, OBS cannot simply duplicate or drop samples without introducing severe distortion, popping, or timing drift. For every 147 samples received from the 44.1 kHz source, OBS must output precisely 160 samples to the 48 kHz mixer.

To bridge this gap, the resampler uses polyphase filterbanks and sinc interpolation:

  1. Interpolation: The discrete 44.1 kHz digital signal is reconstructed virtually into a continuous-time wave representation.
  2. Filtering: An anti-aliasing low-pass filter is applied to remove spectral imaging and eliminate frequencies that could produce artifacts above the Nyquist threshold (approximately 22.05 kHz for the original signal).
  3. Re-quantization: The continuous signal is sampled at the higher 48 kHz intervals, generating 160 output samples for every 147 original input samples.

Buffer Management and Clock Synchronization

OBS processes audio in discrete, timed blocks (typically around 10 milliseconds of audio per tick, or roughly 480 samples at 48 kHz). Because the ratio between 44.1 kHz and 48 kHz produces fractional sample counts over typical millisecond intervals, OBS uses dynamic ring buffers to store partial frames.

If a 10 ms cycle requires 480 samples, the resampler calculates the necessary fractional input from the 44.1 kHz buffer, extracts the available data, and retains the remainder for the subsequent processing cycle. This phase tracking prevents clock drift between the audio hardware's independent crystal oscillator and the OBS processing thread.

System Impact: Latency, CPU, and Fidelity

  • Latency: The real-time conversion adds a negligible amount of latency—typically a fraction of a millisecond—governed strictly by the size of the resampler's internal filter window.
  • CPU Usage: Modern implementations of polyphase sinc resampling are SIMD-optimized (using AVX/SSE on x86 or NEON on ARM). Processing a stereo 44.1 kHz channel consumes a virtually imperceptible percentage of modern CPU processing time.
  • Audio Fidelity: Because the signal is being upsampled rather than downsampled, no original frequency data is lost. The reconstructed frequencies above 22.05 kHz up to the 48 kHz Nyquist limit (24 kHz) remain silent, preserving the spectral integrity of the original source without introducing harmonic distortion.
