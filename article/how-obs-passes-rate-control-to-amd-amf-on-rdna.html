How OBS Passes Rate Control to AMD AMF on RDNA

This article explains the technical pipeline through which OBS Studio translates user-defined rate control settings into low-level instructions executed by AMD’s Advanced Media Framework (AMF) on RDNA graphics architectures. It covers the abstraction layers from the OBS user interface down to the Video Core Next (VCN) hardware block, detailing parameter mapping, runtime state transitions, and hardware-level rate enforcement.

1. Configuration Mapping in OBS Studio

When a user selects a rate control method (such as CBR, VBR, or CQP) and inputs bitrate values in OBS Studio, the application first packages these values into internal configuration structures. The OBS frontend passes these settings to its native AMF encoder module. The module acts as an intermediate bridge that translates generic OBS stream parameters into explicit AMF key-value property pairs recognized by the AMD driver.

2. Translating Settings to the AMF Property System

The AMF software development kit relies on the AMFPropertyStorage interface to configure encoder components. The OBS AMF implementation assigns encoder parameters by calling SetProperty() using standardized AMF constants:

  • Rate Control Mode: OBS sets AMF_VIDEO_ENCODER_RATE_CONTROL_METHOD (or codec-specific variants for HEVC and AV1) to specific enumeration values such as AMF_VIDEO_ENCODER_RATE_CONTROL_METHOD_CBR, VBR_PEAK, or CONSTANT_QP.
  • Target and Peak Bitrates: For CBR and VBR modes, the software converts user-specified kilobits-per-second into bits-per-second, setting AMF_VIDEO_ENCODER_TARGET_BITRATE and AMF_VIDEO_ENCODER_PEAK_BITRATE. In pure CBR, both properties are typically locked to identical targets.
  • Quantization Parameters (QP): If CQP is selected, OBS maps minimum and maximum I-, P-, and B-frame quantization boundaries using AMF_VIDEO_ENCODER_QP_I, AMF_VIDEO_ENCODER_QP_P, and AMF_VIDEO_ENCODER_QP_B.
  • Buffer Sizing and Filler Data: OBS controls the Virtual Buffer Verifier (VBV) buffer size via AMF_VIDEO_ENCODER_VBV_BUFFER_SIZE and enforces strict streaming CBR compliance by enabling AMF_VIDEO_ENCODER_FILLER_DATA_ENABLE to prevent network drops during low-motion scenes.

3. Encoder Initialization and Dynamic Updates

Parameters are committed to the hardware session in one of two stages:

  • Initialization Phase: During stream or recording startup, properties set within the AMFPropertyStorage container are applied before invoking AMFComponent::Init(). AMF validates that the requested bitrate, profile, and rate control method comply with the hardware capabilities of the detected RDNA generation.
  • Dynamic Reconfiguration: If a user adjusts bitrates dynamically (such as through dynamic bitrate controls responding to network congestion), OBS updates the property values and re-submits them via SetProperty() during the active encoding loop. AMF allows dynamic updates to target bitrates and buffer targets on a per-frame basis without reinitializing the encoder context.

4. RDNA Hardware Execution via Video Core Next (VCN)

Once AMF processes the properties in user-mode space, they are sent via the AMD kernel-mode driver directly to the RDNA GPU’s VCN ASIC block. RDNA architectures feature dedicated hardware microcode responsible for rate control calculations:

  • Token-Bucket Rate Allocation: The VCN engine implements a leaky token-bucket algorithm in hardware. Target and peak bitrate parameters dictated by AMF establish the refill and leak rates of this bucket.
  • Frame-Level Quantization: For each input frame submitted by OBS, the VCN hardware calculates frame complexity. Based on the target bitrate constraints assigned by AMF, the hardware encoder automatically modulates macroblock and transform-block delta QP values across the image plane to maintain the specified rate curve.
  • RDNA Pre-Analysis Integration: On supported RDNA architectures, AMF can also bind pre-analysis flags set by OBS. This allows the VCN engine to assess frame motion and spatial complexity prior to the final encoding pass, ensuring that bit allocation precisely aligns with the OBS rate control model without overflowing the transmission buffer.
