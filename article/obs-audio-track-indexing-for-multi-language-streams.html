OBS Audio Track Indexing for Multi-Language Streams

This article provides a comprehensive guide on how OBS Studio indexes, routes, and packages audio tracks for multi-language broadcasting environments. It explains the mechanics behind the software's internal audio matrix, output track assignment, metadata tagging, and the transmission of separate language feeds over protocols like MPEG-TS, SRT, and modern multi-track streaming workflows.

The OBS Audio Routing Architecture

OBS Studio operates on an internal multi-bus architecture centered around a 6-track discrete routing matrix. Any input source—such as commentator microphones, game feeds, remote translation lines, or ambient sounds—can be routed to any combination of these six tracks simultaneously via the Advanced Audio Properties panel.

In a multi-language production, these tracks do not function as surround channels (such as left, right, center, or LFE). Instead, each numbered track operates as a discrete stereo or mono audio submix. Managing track indexing requires treating each track as an isolated programmatic feed:

  • Track 1: Typically reserved as the default combined mix (Clean feed or primary language + international ambient sound) for platforms that only accept a single audio channel.
  • Track 2: Primary language commentary (e.g., English) mixed with international sound (IS/FX).
  • Track 3: Secondary language commentary (e.g., Spanish) mixed with international sound.
  • Track 4: Tertiary language commentary (e.g., French) mixed with international sound.
  • Track 5: Clean international sound (FX/Game/Stems only, no voices) for archival or live feed distribution.
  • Track 6: Intercom, internal production audio, or auxiliary language.

Configuring the Advanced Audio Properties Matrix

To route inputs to specific output indexes, access the Advanced Audio Properties window by clicking the gear icon in the Audio Mixer dock.

The matrix on the right displays the six numeric track checkboxes for every active source in the project. For a true multi-language output, uncheck the master feeds from foreign tracks to avoid audio bleed. For instance, the Spanish interpreter's microphone must only have the checkbox checked under Track 3, while ambient game sound or stadium noise must be checked across Tracks 1, 2, 3, and 4 to ensure consistent background balance across all language renditions.

Output Mapping: Streaming vs. Recording

The internal track indices (1 through 6) must be assigned to the output container through the Settings > Output menu, configured to Advanced mode.

1. Standard RTMP Streaming (Single Track Limitation)

Legacy RTMP streaming only permits a single indexed audio track to be transmitted to the endpoint. In the Streaming tab, the "Audio Track" radio button dictates which single index is compressed and sent via RTMP. Broadcasters targeting standard single-track destinations must rely on multiple OBS instances or cloud-based ingest servers to split languages if bound by legacy RTMP.

2. Multi-Track Master Recording

Under the Recording tab, users can select multiple track checkboxes simultaneously (Tracks 1 through 6). When saving to containers like MKV or MP4, OBS multiplexes these into separate audio streams within the file:

  • The primary video stream is indexed as Stream 0:0.
  • The selected audio tracks are indexed sequentially as Stream 0:1, Stream 0:2, Stream 0:3, etc., preserving total isolation for post-broadcast editing or multilingual VOD delivery.

3. Native Multi-Track Streaming (SRT and MPEG-TS)

For professional workflows requiring live multi-language transmission from a single OBS instance, the Custom Output (FFmpeg) setting or native SRT output is utilized.

When streaming via MPEG-TS over SRT or UDP, OBS can map multiple tracks into discrete elementary audio streams within the transport stream container:

  1. Navigate to Settings > Output > Recording (or custom streaming output).
  2. Set the type to Custom Output (FFmpeg).
  3. Select MPEG-TS as the container format.
  4. Set the muxer options to map the desired OBS audio tracks into designated Program Elementary Streams (PES).

In MPEG-TS delivery, OBS assigns Packet Identifiers (PIDs) sequentially to each active audio track index.

Audio Track Metadata and Language Tagging

One critical limitation of the standard OBS interface is the lack of native GUI fields for ISO 639-2 language tags (e.g., eng, spa, fra). By default, OBS labels indexed tracks generically as Track 1, Track 2, and so on.

To assign metadata so downstream media players, set-top boxes, and ingest servers automatically identify the language of each track:

  • FFmpeg Muxer Flags: In the FFmpeg custom output settings, muxer arguments can be manually passed to index languages to their respective audio stream: 
    metadata:s:a:0=language=eng metadata:s:a:1=language=spa metadata:s:a:2=language=fra
    (Note: FFmpeg uses a 0-based stream indexing convention where a:0 corresponds to the first selected OBS audio track, a:1 corresponds to the second, and so on.)

Indexing Considerations with Enhanced Broadcasting

Modern updates to OBS Studio introduce support for Enhanced Broadcasting architectures (such as Enhanced RTMP and WHIP/WebRTC). These protocols extend traditional single-track broadcasting by allowing OBS to negotiate multiple audio tracks with ingestion servers directly.

When using Enhanced Broadcasting:

  • The server queries OBS for its available audio configuration.
  • OBS presents its configured track indices over the signaling layer.
  • The ingestion server decodes each track, reads the programmatic identifiers, and routes the individual audio channels to dynamic language selectors on downstream video players.

Ensuring strict track discipline at the Advanced Audio Properties stage is essential to prevent sending unmixed or cross-contaminated language audio down the multi-track pipeline.
