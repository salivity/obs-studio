OBS Studio SRT Caller Mode Setup for Strict NAT

This guide explains how to configure Secure Reliable Transport (SRT) in Caller mode using OBS Studio to bypass restrictive Network Address Translation (NAT) and firewall barriers. By configuring OBS Studio as a Caller, the software initiates an outbound User Datagram Protocol (UDP) connection to an external Listener. This outbound-first mechanism leverages standard stateful firewall behavior to establish a persistent, bi-directional data flow, eliminating the need to configure port forwarding or open incoming ports on local, highly restricted networks.

Understanding SRT Caller Mode and NAT Traversal

In networking environments governed by strict firewalls or Carrier-Grade NAT (CGNAT), incoming connection requests are automatically dropped to protect the local network. This renders SRT "Listener" mode ineffective on the sending machine unless complex port forwarding rules or public static IPs are available.

SRT solves this problem through its handshake modes: Caller, Listener, and Rendezvous. In Caller mode, OBS Studio acts as the client. It generates outbound UDP traffic directed toward a destination IP address and port where a remote server (such as an ingest relay, cloud server, or receiver) is configured in Listener mode.

Because the connection starts from inside the local network:

  1. Stateful Inspection: The local router or firewall registers the outbound UDP packet and dynamically creates an entry in its state table (NAT pinhole).
  2. Bi-directional Routing: The firewall allows subsequent incoming packets (such as SRT ACK/NAK packets and control messages) through the opened pinhole as long as they originate from the destination IP and port defined during the handshake.
  3. Symmetric and Cone NAT Compatibility: Because the client establishes the pathway, Caller mode seamlessly navigates through Full Cone, Restricted Cone, Port Restricted, and most Symmetric NAT topologies without administrative intervention on the client side.

How to Configure SRT Caller Mode in OBS Studio

To route video streams through strict network filters using OBS Studio, apply the following configuration:

  1. Open Stream Settings:

    • Launch OBS Studio.
    • Go to File > Settings (or click Settings in the bottom-right Controls dock).
    • Select the Stream tab from the left sidebar.

  2. Set the Service Type:

    • Change the Service dropdown menu to Custom....

  3. Construct the SRT Caller URL: In the Server field, enter the SRT connection string formatted specifically for Caller mode:

    srt://<destination-ip-or-domain>:<port>?mode=caller
    • Replace <destination-ip-or-domain> with the public IP address or hostname of the receiving server.
    • Replace <port> with the listening UDP port on the destination server (default is often 9000 or 9998).
    • Explicitly appending ?mode=caller ensures OBS initiates the handshake rather than waiting for one.

  4. Tune Parameters for Firewall and Latency Stability: Strict firewalls frequently operate over congested, enterprise, or cellular connections that produce packet jitter. You can append tuning parameters to the URL using the & delimiter:

    srt://<destination-ip-or-domain>:<port>?mode=caller&latency=2000&streamid=#!::u=live,r=channel1
    • latency: Defined in milliseconds. A buffer between 1000 and 2500 (1 to 2.5 seconds) provides sufficient time for SRT to request and recover lost packets (ARQ) across unstable connections without stalling the pipeline.
    • streamid: Required by multi-tenant media servers (such as Nimble Streamer, MediaMTX, or Haivision) to route your stream to the proper destination.
    • passphrase and pbkeylen: Adds end-to-end AES encryption (e.g., &passphrase=YourSecret&pbkeylen=32 for AES-256), securing data transmission across intermediate routing layers.

  5. Finalize the Stream Key:

    • Leave the Stream Key field blank. When using SRT in OBS Studio, all configuration parameters and stream routing keys are passed directly through the query string inside the Server field.

  6. Apply and Test:

    • Click Apply and then OK.
    • Click Start Streaming in the OBS main interface.

Network Requirements on the Receiving End

While Caller mode requires zero port modifications on the broadcaster's local network, the remote destination must be ready to receive the stream. Ensure that:

  • The receiving machine runs SRT in Listener mode (mode=listener).
  • The destination network has properly configured port forwarding for the targeted UDP port.
  • Any cloud hosting firewall (e.g., AWS Security Groups, Google Cloud VPC) allows incoming UDP traffic on that designated port.
