OBS Bicubic Downscaling Algorithm Explained

This article explores the mathematical foundation of the bicubic downscaling filter used in OBS Studio. It covers the specific cubic convolution algorithm implemented in OBS's rendering pipeline, breaks down the mathematical formulas used to weigh neighboring pixels, and explains how this algorithm balances computational performance with image sharpness during live video encoding.

The Core Algorithm: Bicubic Convolution

OBS Studio implements bicubic downscaling using a standard cubic convolution interpolation algorithm operating over a 16-sample grid (a 4x4 pixel kernel). Rather than taking a simple weighted average of adjacent pixels as seen in bilinear scaling, OBS applies a separable third-order polynomial across both horizontal and vertical axes to approximate an ideal sinc reconstruction filter.

In OBS Studio's graphics subsystem (libobs), the bicubic filter relies primarily on the Catmull-Rom spline, a specific formulation of the Keys cubic convolution kernel where the sharpening parameter \(a\) is set to \(-0.5\) (or represented within the Mitchell-Netravali family where \(B = 0\) and \(C = 0.5\)).

Mathematical Formulation

The cubic convolution kernel calculates the weighting factor \(W(x)\) for a pixel at a continuous distance \(x\) from the sampling point using the following piecewise cubic function:

\[W(x) = \begin{cases} (a + 2)|x|^3 - (a + 3)|x|^2 + 1 & \text{for } |x| \le 1 \\ a|x|^3 - 5a|x|^2 + 8a|x| - 4a & \text{for } 1 < |x| < 2 \\ 0 & \text{otherwise} \end{cases}\]

When substituting the Catmull-Rom parameter (\(a = -0.5\)), the system simplifies into two primary distance intervals:

  1. For \(|x| \le 1\): \[W(x) = 1.5|x|^3 - 2.5|x|^2 + 1\]

  2. For \(1 < |x| < 2\): \[W(x) = -0.5|x|^3 + 2.5|x|^2 - 4|x| + 2\]

  3. For \(|x| \ge 2\): \[W(x) = 0\]

Because the kernel evaluates to zero when \(|x| \ge 2\), the algorithm only needs to consider two pixels to the left and two pixels to the right of the sample point along each dimension.

2D Implementation and Separability

Because the 2D cubic filter is mathematically separable, the interpolation can be computed independently along rows and columns:

  1. Sampling: A 4x4 neighborhood of input pixels surrounding the target downscaled coordinate is gathered.
  2. Weight Calculation: The fractional offsets \((\Delta x, \Delta y)\) between the target coordinate and the nearest grid point are passed into the cubic polynomial function to derive four horizontal weights and four vertical weights.
  3. Normalization and Summation: The 16 source color values \(C_{i,j}\) are multiplied by their corresponding spatial weights: \[C_{\text{final}} = \sum_{i=-1}^{2} \sum_{j=-1}^{2} C_{i,j} \cdot W(i - \Delta x) \cdot W(j - \Delta y)\]

In OBS's HLSL shader implementation (bicubic.effect), these calculations are optimized for GPU execution by taking advantage of hardware bilinear filtering to reduce the required texture fetches from 16 discrete reads down to 4 filtered reads with offset sampling coordinates.

Performance and Visual Characteristics

By setting \(a = -0.5\), the Catmull-Rom variant maintains continuity in both the first derivative (slope) and pixel values across sampling boundaries. This negative lobe behavior sharpens edges and preserves fine detail significantly better than bilinear filtering, while avoiding the ringing artifacts (haloing) and high GPU overhead associated with higher-order Lanczos (sinc-based) filtering.
