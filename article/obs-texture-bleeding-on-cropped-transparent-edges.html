OBS Texture Bleeding on Cropped Transparent Edges

Texture bleeding along cropped edges of transparent images in OBS Studio is primarily caused by GPU texture filtering interpolating pixels beyond the intended crop boundaries. When a graphic is scaled, positioned on fractional pixel coordinates, or cropped using OBS's built-in transform tools, the graphics rendering pipeline samples neighboring pixels—including fully transparent pixels with hidden color data—resulting in visible outlines, halos, or artifacts along the sliced edges.

GPU Texture Filtering and Interpolation

OBS Studio relies on the GPU to render scenes in real time using standard rendering APIs like DirectX or OpenGL. When you resize, scale, or transform a source, the GPU applies texture filtering (such as Bilinear, Bicubic, or Lanczos) to smooth the image.

Texture filtering works by sampling multiple adjacent texels (texture pixels) and calculating a weighted average to determine the color of a displayed pixel. When a transparent source is cropped using the Alt-crop method or the Transform menu, the underlying texture still exists in memory. If a crop boundary falls between texels, the sampling filter evaluates pixels just outside the crop boundary, blending edge pixels with neighboring data. This mathematical blending manifests as a faint line or "bleed" along the border.

Straight Alpha vs. Premultiplied Alpha Artifacts

Transparent images, such as 32-bit PNGs, store color across four channels: Red, Green, Blue, and Alpha (transparency). Many image editing applications export transparent images using "straight alpha." In a straight alpha workflow, pixels with an alpha value of zero can still retain residual RGB color values (often solid black or solid white).

When OBS samples across a cropped edge where visible pixels meet transparent pixels:

  • The filtering algorithm interpolates both the alpha and the color values simultaneously.
  • If the fully transparent pixels carry an uncleaned black or white RGB value, the sampler blends that color into the edge pixels before applying transparency.
  • This results in a dark or light fringe along the edge, commonly mistaken for a rendering glitch rather than a mathematical color blend.

Sub-Pixel Positioning and Canvas Scaling

OBS scenes operate on a coordinate plane where sources can accidentally be placed on fractional coordinates (sub-pixels). When a source's position or size is not snapped to a whole integer value (e.g., an X-coordinate of 150.5 instead of 150), the GPU must resample the entire texture to align it with the display grid.

Resampling an already cropped boundary across sub-pixel offsets forces edge pixels to be shared across screen pixels. This misalignment exaggerates texture bleeding, turning a 1-pixel boundary into a semi-transparent, blurred seam.

Lack of Texture Clamping on Basic Crops

When applying a crop using the standard transform properties, OBS does not automatically clamp the texture coordinates strictly to the cropped boundaries at the shader level. Without strict UV coordinate clamping or an explicit scissor test, hardware texture samplers fetch surrounding texels according to the active wrap and filter modes. Consequently, pixels that should visually cease to exist still influence the final edge appearance.

How to Prevent Texture Bleeding

  • Snap to Whole Pixels: Right-click the source, select Transform, and ensure the position and size values are set to whole numbers without decimals.
  • Adjust the Scale Filter: Right-click the source, go to Scale Filtering, and test different algorithms. Setting the scale filter to Point eliminates filtering entirely by using nearest-neighbor sampling, removing edge bleeding at the cost of smooth scaling. Area filtering also provides cleaner edge preservation for downscaled sources.
  • Pre-Crop Assets: Crop the source image to its exact dimensions in an image editor prior to importing it into OBS Studio, ensuring the canvas borders match the actual graphic boundaries.
  • Clean Alpha Channels: Export images with premultiplied alpha or ensure transparent areas have clean, neutral RGB data to prevent contrasting color halos.
