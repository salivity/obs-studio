OBS Browser Source Remote Input Event Handling

This article explores how OBS Studio captures, serializes, and transmits keyboard and mouse input events to embedded browser source panels using remote control APIs. By leveraging the Chromium Embedded Framework (CEF) in conjunction with control interfaces like the OBS WebSocket API, external clients can programmatically interact with web-based overlays and interactive widgets. The following sections break down the underlying architecture, event translation pipeline, and API mechanics that make remote interaction possible.

Architecture: CEF and Off-Screen Rendering

OBS Studio renders web content using the obs-browser plugin, which integrates the Chromium Embedded Framework (CEF). Because OBS integrates browser rendering directly into its compositing pipeline, CEF runs in Off-Screen Rendering (OSR) mode. In OSR mode, the browser does not create a native platform window; instead, it renders directly to a shared texture in memory and relies on OBS to pass hardware events to it.

When a user interacts with a browser source locally, OBS uses a Qt-based "Interact" dialog that listens to native operating system events and forwards them directly to the underlying CEF browser instance. For remote control, this direct OS-level hook is bypassed in favor of remote procedure calls.

The Remote Input Pipeline

Passing input remotely requires an external client to transmit user actions to an API server running within OBS—most commonly obs-websocket. The end-to-end data flow operates through several distinct stages:

  1. Client-Side Event Capture: An external controller, web panel, or stream deck captures raw input (e.g., mouse clicks, cursor movement, or keystrokes).
  2. Message Serialization: The client serializes the event data into a structured payload (typically JSON) containing event types, relative coordinates, key codes, and modifier flags.
  3. Transport via API: The payload is sent over a WebSocket connection to OBS Studio via dedicated request methods.
  4. Coordinate and Key Mapping: OBS deserializes the request, validates the target browser source, and normalizes coordinates and key codes.
  5. CEF Injection: The obs-browser plugin invokes CEF’s internal input dispatch APIs, simulating native user action directly on the rendered DOM.

Input Translation and Normalization

Because remote clients may run on different display scales and screen resolutions, input parameters must be normalized before reaching the browser context:

  • Mouse Coordinates: Browser sources in OBS have defined canvas dimensions (e.g., 1920x1080). Remote APIs accept target coordinates relative to this defined width and height. If an external client uses a responsive or scaled preview, the client or the API layer must scale the coordinates from the preview window to the source's native pixel grid.
  • Mouse Clicks and Scrolling: Mouse events are categorized into MouseButtonDown, MouseButtonUp, and mouse wheel delta events. The API specifies which button is involved (Left, Middle, Right) along with modifier states (Shift, Ctrl, Alt).
  • Keyboard Events: Remote keystroke payloads contain standard Web or Virtual Key codes, character representations, and modifier bitmasks. These must be formatted so that CEF interprets them as corresponding RawKeyDown, KeyDown, Char, or KeyUp states.

CEF Event Injection Methods

Once the API receives and maps the payload, the obs-browser source interacts with the CefBrowserHost instance assigned to that specific source. CEF exposes several low-level methods designed for off-screen rendering input injection:

  • SendMouseMoveEvent(const CefMouseEvent& event, bool mouseLeave): Updates the virtual cursor position, triggering CSS :hover states and JavaScript mousemove listeners within the page.
  • SendMouseClickEvent(const CefMouseEvent& event, CefBrowserHost::MouseButtonType type, bool mouseUp, int clickCount): Dispatches click events, allowing interaction with links, buttons, and custom canvas elements.
  • SendMouseWheelEvent(const CefMouseEvent& event, int deltaX, int deltaY): Simulates scroll wheel actions for scrolling through pages or zooming interactive elements.
  • SendKeyEvent(const CefKeyEvent& event): Injects keyboard inputs directly into active DOM elements, updating text fields and triggering browser key event listeners.

Direct DOM Manipulation Alternative

In scenarios where remote control APIs do not expose full granular CEF input bindings, automation is achieved by dispatching synthetic DOM events via JavaScript execution. Remote control APIs provide methods to execute arbitrary JavaScript within a browser source's execution context. Clients can synthesize and dispatch standard MouseEvent or KeyboardEvent objects directly via script injection, bypassing the CEF host input layer entirely while achieving equivalent interaction within the embedded web application.
