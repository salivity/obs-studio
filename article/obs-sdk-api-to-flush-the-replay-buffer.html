OBS SDK API to Flush the Replay Buffer

This article provides a direct overview of how to programmatically trigger an immediate, non-blocking save of the OBS Studio Replay Buffer to disk. It identifies the specific function in the OBS Frontend API, explains the underlying libobs core procedure call, and outlines the asynchronous execution model that prevents UI or capture thread freezing during the operation.

The Primary Frontend API Call

In the OBS Studio SDK, the standard function used to trigger an immediate, non-blocking flush of the Replay Buffer is:

void obs_frontend_replay_buffer_save(void);

Declared in obs-frontend-api.h, this function instructs the active Replay Buffer output to write its current memory contents to a file. Because it operates asynchronously, the call returns immediately after posting the save command to the output thread, ensuring that neither the render thread nor the UI thread is blocked during disk I/O.

Low-Level libobs Implementation

If you are developing a standalone application or a plugin that interacts directly with libobs rather than the OBS Studio frontend, the Replay Buffer is controlled via its underlying output procedure handler (proc_handler).

At the output level, the replay buffer output exposes a procedure named "save". You invoke it directly using:

obs_output_t *replay_output = ...; // Your replay buffer output instance
proc_handler_t *ph = obs_output_get_proc_handler(replay_output);
proc_handler_call(ph, "save", NULL);

Execution Characteristics

  • Non-Blocking Execution: The "save" procedure sets an internal state flag on the output's worker thread. The muxer then begins writing the cached frames to the destination container in the background.
  • Completion Notification: Once the file has been finalized on disk, the output emits the replay_buffer_saved signal. Plugins using the frontend API receive this notification via the OBS_FRONTEND_EVENT_REPLAY_BUFFER_SAVED event through the frontend event callback system.
