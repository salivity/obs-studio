Configuring SRT AES Encryption in OBS Studio

Secure Reliable Transport (SRT) delivers low-latency, resilient video transmission over unpredictable networks, and OBS Studio natively supports securing these streams using the Advanced Encryption Standard (AES). This guide explains how OBS Studio configures AES-128 and AES-256 encryption using SRT URL query parameters, covering key-length parameters, passphrase constraints, and receiver handshake requirements to establish a secure contribution pipeline.

How OBS Studio Implements SRT Encryption

OBS Studio relies on the libsrt library to handle SRT connections. Rather than providing dedicated graphical user interface (GUI) fields for security keys, OBS Studio configures encryption directly through the target stream URL.

To enable AES encryption, parameters are appended as a standard query string to the srt:// endpoint in the streaming settings. When initiating a connection, the sender (caller) and the receiver (listener) negotiate the encryption during the SRT handshake phase. If the passphrases or key lengths do not match, the connection is rejected immediately.

Query Parameters for AES-128 and AES-256

Two primary parameters govern encryption within the SRT URL string:

  • passphrase: The pre-shared secret key used to derive the encryption keys. By SRT specification, the passphrase must be between 10 and 79 characters long. Shorter or longer values will cause the SRT library to fail initialization.
  • pbkeylen: Specifies the encryption key length in bytes.
    • AES-128: Set pbkeylen=16 (16 bytes = 128 bits).
    • AES-256: Set pbkeylen=32 (32 bytes = 256 bits).

If pbkeylen is omitted from the URL, the SRT library defaults to standard key derivation based on the passphrase length or receiver negotiation, which typically results in AES-128. To enforce AES-256 explicitly, pbkeylen=32 must be declared.

Step-by-Step Configuration in OBS Studio

  1. Open OBS Studio and navigate to Settings > Stream.
  2. Set the Service dropdown menu to Custom....
  3. In the Server field, enter your destination SRT URL along with the encryption parameters.
  4. Leave the Stream Key field blank, as all parameters are contained inside the target URL.

URL Examples

For AES-128 Encryption:

srt://ingest.example.com:9000?passphrase=MySecurePassphrase123&pbkeylen=16

For AES-256 Encryption:

srt://ingest.example.com:9000?passphrase=MySecurePassphrase123&pbkeylen=32

Combining Encryption with Other SRT Parameters

If your contribution pipeline requires additional parameters—such as latency buffers or a streamid for routing to specific ingest points—combine them using standard ampersand (&) separators:

srt://ingest.example.com:9000?streamid=live/channel1&passphrase=MySecurePassphrase123&pbkeylen=32&latency=200

Handshake and Verification

When streaming begins, OBS Studio acts as the caller and transmits the key material wrapped in an SRT Key Exchange (KM) message during the connection handshake.

For the pipeline to function:

  • The receiving media server, hardware decoder, or gateway must have identical passphrase and pbkeylen settings configured on the listening port.
  • If OBS displays a connection failure or repeatedly reconnects, check the OBS log files (Help > Log Files > View Current Log). Encryption mismatches typically report an SRT rejection code corresponding to SRT_ECONNREJ or handshake timeout errors.
