Multi-PC OBS Architecture for Encoding Offload

This article details the recommended multi-PC architecture for offloading intensive video encoding tasks from a master OBS Studio switching console to a dedicated encoding rig. By separating real-time scene composition from final stream compression, production environments eliminate frame drops, minimize latency, and maintain optimal performance across complex live broadcasts.

System Topology Overview

The standard architecture separates production into two distinct functional nodes: the Master Control (Director) PC and the Dedicated Encoding PC.

  • Master Control PC: Ingests raw inputs (cameras, microphones, screen captures, media files), manages overlays, handles audio mixing, and executes scene switching within OBS Studio. It does not compress final delivery streams.
  • Encoding PC: Receives a visually lossless, mixed program feed from the Master PC, applies platform-specific encoding profiles (such as x264, NVENC, or AV1), and pushes the encoded feeds to CDNs (e.g., YouTube, Twitch, custom RTMP/SRT ingest endpoints).

Recommended Interconnect Methods

To pass the program feed from the Master PC to the Encoding PC with minimal processing overhead and near-zero latency, choose one of the following two transports:

1. Hardware Capture via HDMI or SDI (Preferred)

  • How it works: The Master PC outputs its Program feed via a secondary GPU display port (using OBS Fullscreen Projector) or an internal SDI/HDMI output card (such as a Blackmagic DeckLink). The Encoding PC captures this feed via a dedicated internal PCIe capture card (e.g., Elgato 4K Pro or Magewell Pro Capture).
  • Advantages: Complete hardware isolation. Zero local network bandwidth consumption, zero CPU/GPU encoding penalty on the Master PC, and absolute reliability.
  • Considerations: Requires dedicated cabling and capture hardware for each discrete audio/video feed.

2. Network-Based Transport: NDI or Local SRT

  • NDI (Network Device Interface): Using the OBS-NDI plugin, the Master PC broadcasts an uncompressed/mezzanine I-frame video feed over a local network, which is ingested directly as an NDI source inside the secondary OBS instance.
    • Requirements: A minimum of a dedicated 1GbE network switch (2.5GbE or 10GbE recommended if routing multiple isolated feeds).
  • Local SRT (Secure Reliable Transport) / RTMP: The Master PC runs an ultra-low-latency, high-bitrate hardware-accelerated encode (e.g., NVENC at 50,000+ kbps with zero B-frames) and streams point-to-point via SRT to an ingest listener on the Encoding PC.
    • Advantages: Minimal hardware investment; highly scalable for routing multiple isolation (ISO) feeds over standard network infrastructure.

Audio Routing Architecture

Audio synchronization is critical in a multi-PC split:

  • Embedded Audio: Send master program audio embedded within the video pipeline (via HDMI/SDI or NDI). This guarantees video and audio remain phase-locked.
  • Discrete Network Routing (Dante / AES67): For advanced environments, route all microphones and auxiliary sources through an independent digital audio network or a hardware USB interface directly to the Encoding PC, utilizing latency offsets to match video delay.

Configuration Best Practices

  1. Master PC OBS Output Settings: Set base canvas and output canvas resolutions identically to prevent GPU scaling overhead. Disable the "Stream" output entirely; output solely via an OBS Projector, dedicated deck output, or mezzanine NDI sender.
  2. Encoding PC Setup: Keep the OBS Studio scene on the Encoding PC minimal. It requires only one primary scene containing the ingested Program feed and any emergency technical-difficulty slate.
  3. Encoder Load Allocation: Because the Encoding PC is spared from running graphics rendering or software applications, its system resources can be fully dedicated to multi-track recording, local archiving, and multi-destination streaming (e.g., simultaneous AV1 and H.264 outputs).
