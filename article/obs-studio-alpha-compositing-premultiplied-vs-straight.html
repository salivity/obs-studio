OBS Studio Alpha Compositing: Premultiplied vs Straight

OBS Studio composites scene layers within a unified graphics pipeline that standardizes transparency handling across diverse inputs. When mixing premultiplied alpha sources with straight (unassociated) alpha assets, OBS processes color values to avoid blending artifacts such as dark halos or washed-out edges. This article explains how OBS Studio's rendering engine interprets alpha channels, converts straight alpha textures into premultiplied space, and executes GPU hardware blending to ensure accurate visual output across scenes.

Straight Alpha vs. Premultiplied Alpha

To understand compositing in OBS Studio, the distinction between the two alpha storage methods is essential:

  • Straight (Unassociated) Alpha: The RGB color channels and the alpha channel are stored independently. Fully transparent or semi-transparent pixels retain their original RGB values without alteration.
  • Premultiplied Alpha: The RGB color values are pre-multiplied by the alpha value during export (\(R \times A\), \(G \times A\), \(B \times A\)). Fully transparent pixels have RGB values of \((0, 0, 0)\).

Premultiplied alpha is the industry standard for real-time graphics rendering because it prevents fringing artifacts during texture filtering (scaling) and simplifies the mathematical blend equation.

The OBS Internal Compositing Pipeline

OBS Studio’s core graphics subsystem (libobs/graphics) standardizes its internal render targets and framebuffers using premultiplied alpha. Whether running on Direct3D 11 (Windows) or OpenGL/Metal (Linux/macOS), the OBS canvas operates on the standard premultiplied blend function:

\[\text{Result} = (\text{SourceColor} \times 1) + (\text{DestColor} \times (1 - \text{SourceAlpha}))\]

In graphics API terms, this maps to:

  • Source Blend Factor: ONE
  • Destination Blend Factor: INV_SRC_ALPHA

By maintaining a premultiplied render target, OBS can scale, filter (bicubic, bilinear, Lanczos), and stack multiple scene layers without generating black outlines around semi-transparent edges.

How OBS Handles Mixed Alpha Inputs

Because the internal render target expects premultiplied values, incoming sources must match this format before the final hardware blend stage occurs.

1. Straight Alpha Sources

Most standard static images (PNGs) and standard video codecs with alpha (such as straight-alpha ProRes 4444 or QuickTime Animation) enter OBS with unassociated color data.

  • During the draw call, OBS passes the texture through a pixel shader.
  • The shader multiplies the RGB components by the alpha component (color.rgb *= color.a) prior to outputting the pixel to the blend unit.
  • This on-the-fly conversion converts straight assets into the premultiplied space required by the canvas blend state.

2. Native Premultiplied Sources

Certain video streams, browser sources (CEF/Chromium), and optimized media files provide data that is already premultiplied.

  • OBS bypasses the shader-level pre-multiplication step for these sources.
  • The raw RGB values are fed directly to the blend hardware using the ONE, INV_SRC_ALPHA formula.

3. Mixed Alpha Configuration in OBS Media Sources

In components like the OBS Media Source or Stinger transitions, media playback libraries (such as FFmpeg) decode video frames into GPU textures. When rendering media with alpha transparency, OBS provides settings or internal heuristics to determine the alpha type:

  • If a straight alpha asset is mistakenly flagged as premultiplied: The shader will not apply the pre-multiplication step. Because the blend hardware expects colors scaled to alpha, semi-transparent edges appear too bright or produce fringing against dark backgrounds.
  • If a premultiplied asset is treated as straight: The shader multiplies the RGB values by alpha a second time. This causes semi-transparent edges to darken severely, creating a noticeable black halo around transparent elements.

Nested Scenes and Intermediate Surfaces

When a user nests one scene inside another, OBS renders the child scene to an intermediate off-screen texture.

  1. Child Scene Accumulation: The child scene's layers (containing both straight and premultiplied sources) are composited into an off-screen surface using the standard premultiplied formula.
  2. Intermediate Format Retention: The resulting intermediate surface remains in premultiplied format.
  3. Parent Scene Blending: When the parent scene draws the child scene texture, it treats the entire nested scene as a single premultiplied texture, sampling and blending it without redundant conversions.

This uniform pipeline ensures that regardless of how many straight and premultiplied sources are stacked, scaled, or grouped across multiple scene levels, OBS Studio maintains mathematically correct transparency.
