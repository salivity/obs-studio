OBS Studio Sub-Frame Timecode in MKV Files

This article explains how OBS Studio injects and preserves timing metadata within Matroska (MKV) containers to provide sub-frame timecode accuracy. It details the internal high-resolution clock systems within OBS Studio, the structural capabilities of the Matroska container format, how presentation timestamps (PTS) are calculated and quantized, and how supplementary metadata fields are utilized for precise post-production synchronization.

High-Resolution Clocking in the OBS Architecture

Traditional SMPTE timecode operates on a discrete frame-based notation (Hours:Minutes:Seconds:Frames), which inherently lacks the granularity to indicate where an event occurred within the duration of a single video frame. To overcome this limitation, OBS Studio tracks media events using a continuous, monotonic 64-bit nanosecond clock via its internal os_gettime_ns() API.

When video frames and audio samples enter the OBS pipeline from capture hardware, they are immediately stamped with an absolute capture timestamp based on this nanosecond clock. This internal high-precision tracking ensures that before any encoding or container muxing takes place, the exact arrival and intended presentation offset of each media sample are preserved relative to the system's runtime reference.

Matroska Timestamp Scale and Granularity

The Matroska (MKV) container format is structurally designed to support arbitrary timing precision. Unlike older containers that rely on fixed frame-rate counters, an MKV container organizes media within Cluster elements, where each individual data packet (Block or SimpleBlock) contains a relative timecode integer.

The resolution of these timecodes is dictated by two container-level parameters:

  1. TimestampScale (formerly TimecodeScale): A global element in the MKV Info header defined in nanoseconds. The default value is 1,000,000, which assigns each integer tick a resolution of 1 millisecond.
  2. Cluster Timestamp: A base timestamp applied to the beginning of each cluster.

To achieve sub-frame accuracy, the container's timebase must be granular enough to represent divisions smaller than the duration of a single frame (e.g., less than 16.67 ms for 60 fps video). OBS Studio leverages FFmpeg's libavformat muxer to write MKV files. By standardizing the scale to millisecond or sub-millisecond resolutions, the container allows each video frame's presentation timestamp to deviate from a rigid, nominal grid, directly encoding the real-world temporal variation of the source.

Packet Generation and PTS Calculation

During the muxing phase, OBS Studio converts the internal nanosecond capture timestamp into an encoded packet presentation timestamp (AVPacket.pts).

Instead of generating artificial, evenly spaced timestamps based purely on the nominal output framerate (such as exactly 1/60th of a second intervals), OBS can preserve the delta between actual capture intervals:

  1. Capture Offset Recording: When a frame is captured, its precise hardware or system presentation time is matched against the start-of-stream reference time.
  2. Rescaling to Container Units: The delta is converted from nanoseconds into the stream timebase used by the muxer (typically \(1/1000\) for standard MKV millisecond alignment, or \(1/1000000\) for microsecond precision when configured in custom FFmpeg outputs).
  3. Muxing into Blocks: The MKV muxer writes the frame into a SimpleBlock. The block header stores a signed 16-bit integer representing its offset from the parent Cluster timestamp.

Because the timestamp scale permits fractions of a frame duration, video editing software and decoders reading the MKV can calculate the exact temporal placement of the frame down to the millisecond, bypassing the rounding errors associated with traditional frame counters.

Supplemental Enhancement Information (SEI) and Tag Injection

Container-level timestamps define playback pacing, but specialized editing environments often require explicit timecode tracks. OBS Studio bridges this gap through two metadata injection methods:

1. In-Band SEI Metadata

For codecs like H.264 (AVC) and H.265 (HEVC), OBS Studio can pass Supplemental Enhancement Information (SEI) NAL units directly into the elementary video bitstream. These units carry standard Picture Timing SEI or User Data Unregistered SEI messages that embed:

  • Real-world wall-clock times (UTC/NTP references).
  • High-precision fractional offsets representing sub-frame intervals.

2. Matroska Container Tags

OBS writes Matroska Tag elements associated with the specific video track. These tags hold arbitrary key-value pairs formatted in UTF-8. In configurations supporting advanced timecode capture, specific tags—such as TIMECODE or custom vendor tags—are populated with absolute start offsets and microsecond-level synchronization anchors.

Synchronization in Post-Production

By coupling nanosecond internal sampling with the structural flexibility of MKV TimestampScale divisions, OBS Studio bypasses the rigid quantization of SMPTE timecodes. The resulting MKV file retains exact hardware-derived capture timings inside the container blocks, ensuring that multi-track recordings, external audio interfaces, and secondary video inputs can be realigned with sub-frame precision in post-production software capable of reading high-resolution MKV timestamps.
