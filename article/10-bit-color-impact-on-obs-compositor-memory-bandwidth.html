10-Bit Color Impact on OBS Compositor Memory Bandwidth

Enabling 10-bit color formats in OBS Studio increases GPU texture memory bandwidth consumption by expanding the data footprint of intermediate render targets and video frames. Because 10-bit processing frequently relies on 16-bit data containers and high-precision floating-point canvas surfaces, the compositor must read and write substantially more bytes per pixel across every rendering pass. This article explains how OBS handles 10-bit textures, why memory throughput scales non-linearly, and the performance implications for the rendering pipeline.

How the OBS Compositor Processes Color

OBS Studio executes scene composition entirely on the GPU via Direct3D 11 on Windows, Metal on macOS, or OpenGL on Linux. During a standard frame render, input sources (such as capture cards, game captures, and media files) are decoded into memory, uploaded to GPU textures, converted to RGB, and blended onto a master canvas texture. Filters, transformations, and alpha blending are applied as sequential render passes, writing intermediate results to offscreen buffers before generating the final composited frame for the video encoder.

Pixel Layout and Format Expansion

The primary driver of increased bandwidth is how 10-bit samples are represented in memory:

  • Source Textures (P010 vs. NV12): Standard 8-bit 4:2:0 video feeds use formats like NV12, requiring 12 bits (1.5 bytes) per pixel. Most 10-bit 4:2:0 capture feeds use the P010 format. In P010, the 10-bit values are packed into 16-bit words (with 6 bits padded). This increases the memory footprint to 24 bits (3.0 bytes) per pixel—a 100% increase in raw texture data read from VRAM before any composition takes place.
  • Internal Render Targets (RGBA16F vs. RGBA8): In standard SDR mode, OBS composites scenes using 8-bit integer buffers (DXGI_FORMAT_B8G8R8A8_UNORM), which cost 32 bits (4 bytes) per pixel. When configured for 10-bit or HDR color spaces (such as Rec. 2100 PQ or HLG), the internal compositor transitions intermediate render targets to 16-bit floating-point textures (DXGI_FORMAT_R16G16B16A16_FLOAT). This prevents banding, rounding errors, and color clipping during blend operations. This format requires 64 bits (8 bytes) per pixel, directly doubling the data payload for every draw call and compositing operation.

Multiplied Bandwidth Across Render Passes

The bandwidth penalty is not limited to a single read and write. The OBS compositor executes multiple operations per frame:

  1. Format Conversion: Planar 10-bit textures (P010) are sampled and converted into linear floating-point RGB textures.
  2. Layer Compositing: Each visible source is sampled from its source texture and blended into the intermediate canvas texture.
  3. Filter Application: Color correction, scaling, sharpening, and blur filters read from one intermediate 64-bit-per-pixel texture and write to another.
  4. Final Staging: The combined frame is converted back to an encoder-compatible format (such as P010 or NV12) and staged for hardware encoding.

Because the internal render canvas is 8 bytes per pixel rather than 4 bytes, every intermediate pass moves twice as much data over the GPU's memory bus. In a complex scene with multiple nested scenes, transitions, and overlays, the cumulative memory throughput scales multiplicatively.

Bandwidth Calculation Example

For an uncompressed 4K canvas (3840x2160) operating at 60 frames per second:

  • 8-Bit SDR (RGBA8): A single full-screen canvas read or write requires approximately 33.18 MB per frame, translating to 1.99 GB/s of memory bandwidth per pass.
  • 10-Bit/HDR (RGBA16F): The same 4K frame requires 66.36 MB per frame, resulting in 3.98 GB/s of memory bandwidth per pass.

If a scene requires an average of five composite and filter passes before final encoding, the compositor alone demands roughly 19.9 GB/s of memory bandwidth for 10-bit floating-point surfaces, compared to roughly 9.95 GB/s for an 8-bit pipeline.

Real-World Hardware Implications

Modern desktop GPUs with wide memory interfaces (192-bit to 384-bit) typically possess sufficient memory bandwidth (300 GB/s to 1,000+ GB/s) to absorb this overhead without dropped frames. However, the increased bandwidth footprint creates noticeable bottlenecks in specific scenarios:

  • Integrated and Mobile GPUs: Systems utilizing shared system memory (LPDDR4X/DDR5) often have memory bandwidth constrained to between 50 GB/s and 100 GB/s. Dedicating 20 GB/s or more solely to the OBS compositor can cause rendering lag and frame drops.
  • Narrow-Bus GPUs: Entry-level discrete GPUs operating on 64-bit or 128-bit memory buses can experience memory bus saturation when high-resolution 10-bit composition runs concurrently with a graphically demanding game.
  • Encoder Starvation: If the compositor cannot finish reading and writing intermediate textures within the frame interval (16.67 ms for 60 fps) due to memory bus contention, rendering lag occurs, leading to dropped frames before the video data ever reaches the hardware encoder.
