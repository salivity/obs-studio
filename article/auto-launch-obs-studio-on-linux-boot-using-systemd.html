Auto-Launch OBS Studio on Linux Boot Using systemd

This article provides a direct, step-by-step guide to automatically launching OBS Studio upon login on a Linux system using a custom user-level systemd service. Because OBS Studio is a graphical application that requires an active display server (X11 or Wayland), running it through a user-level systemd unit rather than a root-level service ensures it properly inherits your graphical session and audio devices.

Step 1: Verify the OBS Studio Installation Path

Determine the exact path of your OBS Studio executable by opening a terminal and running:

which obs

On most native package installations (such as APT, DNF, or Pacman), the output will be /usr/bin/obs. If you are using Flatpak, the executable command will instead be /usr/bin/flatpak run com.obsproject.Studio. Note down the path that applies to your setup.

Step 2: Create the systemd User Service Directory

Ensure that the local directory for user-specific systemd service units exists:

mkdir -p ~/.config/systemd/user

Step 3: Create the Service Unit File

Create a new file named obs.service inside the user systemd directory using your preferred text editor:

nano ~/.config/systemd/user/obs.service

Paste the following configuration into the file:

[Unit]
Description=OBS Studio Auto-Start Service
PartOf=graphical-session.target
After=graphical-session.target

[Service]
Type=exec
ExecStart=/usr/bin/obs
Restart=on-failure
RestartSec=5

# Optional: Add flags like --startstreaming or --minimize-to-tray to ExecStart if desired:
# ExecStart=/usr/bin/obs --minimize-to-tray

[Install]
WantedBy=graphical-session.target

Note: If using Flatpak, replace ExecStart=/usr/bin/obs with ExecStart=/usr/bin/flatpak run com.obsproject.Studio.

Save and close the file (in Nano, press Ctrl+O, then Enter, followed by Ctrl+X).

Step 4: Reload and Enable the Service

Reload the systemd user manager to recognize the new service file:

systemctl --user daemon-reload

Enable the service so that it automatically runs when your graphical session initializes:

systemctl --user enable obs.service

Step 5: Test the Service

Test whether the service runs immediately in your current active desktop session by executing:

systemctl --user start obs.service

Verify that OBS Studio opens. Check the service status and logs to ensure there are no startup errors:

systemctl --user status obs.service

If you ever need to stop or disable the auto-start behavior, run:

systemctl --user stop obs.service
systemctl --user disable obs.service
