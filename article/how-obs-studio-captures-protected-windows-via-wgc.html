How OBS Studio Captures Protected Windows via WGC

This article explains how OBS Studio utilizes Microsoft's Windows Graphics Capture (WGC) API to record and stream hardware-accelerated, elevated, and protected application windows. By shifting away from traditional memory-injection techniques and legacy display APIs, OBS Studio harnesses modern DWM-level (Desktop Window Manager) compositor integration. This approach enables reliable capture of applications that otherwise produce black screens, while maintaining high performance and system stability.

The Limitations of Legacy Capture Methods

Historically, OBS Studio relied on two primary methods for capturing applications: BitBlt (GDI-based) and graphics hooking (injecting a DLL into the target application’s rendering pipeline via DirectX or OpenGL).

Both approaches struggle with protected or modern application architectures:

  • GDI/BitBlt: Incapable of reading content rendered directly to hardware-accelerated swap chains, resulting in a black window.
  • Injection Hooks: Frequently blocked by anti-cheat systems, digital rights management (DRM), elevated user privilege boundaries (UAC), or universal Windows platform (UWP) sandboxing. If an application runs with administrative rights, a standard-privilege OBS instance cannot inject hooks into it.

What is the Windows Graphics Capture API?

Introduced in Windows 10 (version 1803 and expanded in version 1903), the Windows Graphics Capture API (Windows.Graphics.Capture) is an operating-system-level framework designed for capturing screen and window items.

Instead of intercepting draw calls or scraping the screen surface, WGC operates within the Windows compositor (DWM). It treats target windows as independent visual elements, generating a stream of Direct3D 11 textures directly from the compositor's visual tree.

How OBS Studio Implements WGC

In OBS Studio, the WGC backend is implemented within the standard Window Capture source under the "Windows 10 (1903 and up)" capture method.

  1. Target Identification and Item Creation:
    OBS identifies the target window handle (HWND) and converts it into a GraphicsCaptureItem via the interop interface IGraphicsCaptureItemInterop. This links the capture framework to the target window without modifying or injecting code into the target process.

  2. Frame Pool Allocation:
    OBS creates a Direct3D11CaptureFramePool configured to match the Direct3D 11 device used by the OBS rendering engine. This frame pool pre-allocates DXGI surfaces to receive window updates.

  3. Session Initialization:
    OBS starts a GraphicsCaptureSession. The operating system then sends frame updates asynchronously to the frame pool whenever the target window updates its contents.

  4. Zero-Copy Texture Handling:
    When a new frame arrives via the capture session, OBS retrieves the native ID3D11Texture2D surface. Because OBS operates natively on Direct3D 11 on Windows, it can copy or sample this surface directly on the GPU without round-tripping pixel data through system RAM.

Capturing Protected and Elevated Windows

WGC allows OBS Studio to bypass common capture barriers through specific architectural advantages:

  • Bypassing Privilege Isolation (UIPI): User Interface Privilege Isolation blocks standard applications from interacting with elevated applications. Because WGC is a brokered system service, the operating system manages access to the visual output. OBS does not need administrative privileges to capture elevated windows.
  • Hardware Acceleration Compatibility: Modern browsers, electron apps, and office suites render using hardware-accelerated DirectComposition or DirectWrite. Because WGC reads from the final compositor output of that specific window, hardware acceleration no longer produces a black screen.
  • Elimination of Anti-Cheat Conflicts: Since no foreign DLL is injected into the target address space, security software and anti-cheat modules do not flag OBS, allowing protected environments to be recorded safely.
  • Border and Cursor Control: On supported Windows versions, OBS leverages WGC properties such as IsBorderRequired and IsCursorCaptureEnabled to disable the default yellow capture border and independently toggle mouse cursor visibility.

Through the Windows Graphics Capture API, OBS Studio captures visually isolated, sandboxed, and hardware-accelerated windows cleanly by relying on native OS compositor frames rather than invasive process hooks.
