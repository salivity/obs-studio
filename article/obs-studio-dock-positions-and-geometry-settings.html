OBS Studio Dock Positions and Geometry Settings

OBS Studio manages dock positions, window sizes, and custom user dock arrangements by serializing Qt application states directly into its core configuration files. Instead of storing human-readable layout coordinates for every panel, OBS relies on Qt’s native state-saving mechanisms, converting complex UI hierarchies into encoded binary strings. This article explains where these settings reside, how OBS processes custom browser docks, and how dock layout data is written to and restored from the configuration files.

Configuration File Locations

OBS Studio maintains its interface settings within user configuration directories specific to the host operating system:

  • Windows: %APPDATA%\obs-studio\
  • macOS: ~/Library/Application Support/obs-studio/
  • Linux: ~/.config/obs-studio/

While streaming parameters and output configurations are managed within profile-specific folders, main window parameters, custom browser dock definitions, and layout structures are primarily handled in the global.ini configuration file.

Qt State Serialization and Base64 Encoding

OBS Studio’s user interface is built on the Qt framework, utilizing the QMainWindow class. To manage dock layouts, Qt provides two primary functions: saveGeometry() and saveState().

When OBS closes or when docks are rearranged:

  1. Window Geometry: OBS captures the main window size, screen coordinates, and maximized/minimized status using saveGeometry().
  2. Dock State: OBS captures the status of all internal panels—including native docks (Scenes, Sources, Audio Mixer) and custom docks—using saveState(). This function records whether docks are pinned, tabbed, floating, closed, or nested, alongside their relative pixel dimensions.

These functions output binary data as a QByteArray. Because .ini files require text-based key-value pairs, OBS converts these binary blobs into Base64-encoded strings. In global.ini, these appear under the [BasicWindow] section as:

  • geometry: The Base64 string containing the main window's physical dimensions and screen positioning.
  • DockState: The Base64 string containing the full hierarchical layout and visibility status of all docked and floating panels.

Management of Custom Browser Docks

Custom browser docks—user-defined web panels such as chat feeds or stream analytics—require a two-step management process:

  1. Dock Metadata Definition: OBS Studio saves the metadata for custom browser docks (titles and target URLs) as a JSON-formatted string or discrete keys within global.ini under entries such as ExtraBrowsers. This preserves the unique identifiers and source paths for each custom panel.
  2. Layout Association: When OBS generates the custom dock widget, it assigns an internal Qt object name (objectName) based on the dock’s unique identifier. The general DockState string uses this object name to anchor the custom dock to its respective location alongside native UI elements.

The Restoration Process on Launch

During startup, OBS Studio initializes the core application and constructs the main window framework before reading global.ini:

  1. OBS reads the custom dock definitions and generates the corresponding QDockWidget containers with their embedded web views.
  2. The application passes the Base64-decoded geometry data to restoreGeometry(), repositioning the outer application frame to the user's previous monitor and coordinates.
  3. The Base64-decoded DockState data is passed to restoreState(). Qt matches the saved objectName identifiers against the newly instantiated native and custom docks, automatically restoring dock widths, splitters, tabbed groups, and floating positions to their exact previous state.
