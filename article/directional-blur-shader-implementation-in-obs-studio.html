Directional Blur Shader Implementation in OBS Studio

This article provides a technical breakdown of how directional blur filters are implemented as shaders within advanced OBS Studio plugins like StreamFX. Directional blur simulates linear motion by sampling pixels along a specific angle across a defined distance. By analyzing the coordinate mathematics, sampling loops, weighting algorithms, and GPU execution pipeline, this guide explains how real-time linear convolution occurs inside the OBS graphics subsystem.

Coordinate Mathematics and Vector Calculation

A directional blur works by taking multiple texture samples along a single line vector rather than across a two-dimensional grid. In OBS Studio's HLSL-based rendering pipeline, the filter receives user parameters—typically the blur angle (\(\theta\)) in degrees or radians and the blur distance or size (\(S\)) in pixels.

Before running the sampling loop, the shader converts these parameters into a normalized directional step vector scaled by the inverse of the viewport resolution:

float radians = angle * (3.14159265 / 180.0);
float2 direction = float2(cos(radians), sin(radians));
float2 stepSize = (direction * size) / (textureResolution * sampleCount);

By factoring in the reciprocal of the render target's resolution, the shader ensures that steps correspond accurately to pixel space regardless of canvas scaling or aspect ratio.

Sampling Loop and Kernel Weighting

The core of the pixel shader execution is an accumulation loop. For every rendered pixel, the shader offsets its UV coordinates forward and backward along the calculated vector, samples the source texture repeatedly, and sums the color values.

Directional blurs typically implement one of two weighting profiles:

  1. Box Filter: Every sample along the vector carries equal weight. This produces a simple trailing effect but can exhibit harsh edges at low sample counts.
  2. Gaussian Filter: Samples closer to the origin carry more weight than samples at the extremities. The weight is calculated per step using a one-dimensional Gaussian distribution function:
float weight = exp(-0.5 * pow(i / standardDeviation, 2.0));

During execution, each sampled color is multiplied by its corresponding weight, and the weight is added to an accumulator variable.

Pixel Shader Accumulation Logic

Below is the standard representation of the accumulation routine within an OBS HLSL pixel shader:

float4 totalColor = float4(0.0, 0.0, 0.0, 0.0);
float totalWeight = 0.0;

for (int i = -samples; i <= samples; ++i) {
    float2 offset = stepSize * float(i);
    float weight = calculateWeight(i);
    
    totalColor += imageTexture.Sample(linearSampler, input.uv + offset) * weight;
    totalWeight += weight;
}

float4 finalColor = totalColor / totalWeight;

Dividing the accumulated color by totalWeight normalizes the output, preventing the blurred image from brightening or dimming regardless of how many samples are taken.

Hardware Optimization via Bilinear Filtering

To maintain smooth 60 FPS performance in OBS Studio, high-end directional blur shaders avoid integer-only pixel steps. By placing UV sample coordinates precisely halfway between two texel centers, the GPU’s hardware bilinear filtering automatically interpolates two adjacent pixels in a single texture fetch. This mathematical trick effectively doubles the visual smoothness of the blur without doubling the instruction cost, allowing plugins to achieve smooth results with half the sample iterations.

Integration with the OBS Graphics Pipeline

OBS Studio exposes its rendering architecture through libobs, using Direct3D 11 on Windows and OpenGL or Metal on other platforms. Directional blur plugins pass user-configured variables through constant buffers directly to the graphics pipeline. Because directional blur is fundamentally a 1D convolution, it operates with a computational complexity of \(O(N)\) per pixel, making it significantly less resource-intensive than unseparated 2D spatial blurs (\(O(N^2)\)) and capable of running smoothly alongside resource-heavy streaming and encoding tasks.
