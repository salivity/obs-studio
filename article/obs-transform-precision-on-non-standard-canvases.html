OBS Transform Precision on Non-Standard Canvases

Positioning precision graphics on non-standard canvas dimensions in OBS Studio can introduce subpixel rendering artifacts, blurriness, and misalignment due to floating-point rounding. This article examines how the OBS rendering engine processes transform matrices, why fractional coordinates occur on arbitrary canvas sizes, and how users can enforce exact pixel alignment when working with pixel art, broadcast overlays, or custom streaming layouts.

Floating-Point Coordinates and Matrix Transforms

OBS Studio manages scene items using a scene-graph hierarchy powered by libobs. Every source within a scene contains a transform matrix that dictates position, rotation, scale, and crop margins. Internally, OBS calculates these transformations using single-precision floating-point numbers (float types matching standard IEEE 754).

When an asset is placed on a canvas, its position is represented as a two-dimensional vector (vec2 pos). Because the software supports arbitrary scaling, arbitrary aspect ratios, and fluid mouse dragging within the preview window, transform coordinates are frequently stored with fractional values (e.g., X: 412.37, Y: 108.82).

The Non-Standard Canvas Multiplier

On standard 16:9 resolutions (such as 1920x1080 or 2560x1440), visual snapping and standard integer math frequently align with the physical pixel grid. When an odd or non-standard canvas resolution is used (such as vertical formats like 1080x1920, ultrawide formats, or arbitrary plugin-driven dimensions), transform rounding issues compound in two areas:

  1. The Canvas-to-Output Scaler: If the Base (Canvas) Resolution differs from the Output (Scaled) Resolution, OBS introduces an overall scaling factor. If a non-integer scaling factor is produced (for example, downscaling a 3440x1440 canvas to 1080p), no graphic—regardless of how carefully it is positioned on the base canvas—will align directly with the final raster grid.
  2. Normalized Device Coordinates (NDC): The rendering pipeline converts pixel positions into normalized viewport coordinates ranging from -1.0 to 1.0 before rasterization. Floating-point round-off during these matrix multiplications means that an edge designed to align at exactly one pixel boundary can fall between two texels.

GPU Rasterization and Texture Filtering

OBS Studio composites scenes via hardware acceleration (Direct3D 11 on Windows, Metal on macOS, and OpenGL on Linux). During each render tick, the compositor draws each source as a textured quad using vertex and fragment shaders.

When a source transform resolves to fractional coordinates:

  • Bilinear, Bicubic, and Lanczos Filtering: If the source transform places an edge across half a pixel, the GPU’s texture sampler samples adjacent pixels to approximate the fractional position. This interpolation creates anti-aliasing artifacts, manifested as soft edges, blurring on crisp lines, or faint 1-pixel color fringing along transparency seams.
  • Point (Nearest Neighbor) Filtering: When set to Point sampling, the GPU truncates the coordinate to the closest texel. While this maintains sharpness, a fractional transform can cause "pixel jitter" or uneven line widths across symmetrical assets, as some pixel rows round up while others round down.

Canvas Snapping and Boundary Discretization

The OBS user interface contains an integrated snapping engine configured in the general settings. By default, it snaps sources to the canvas edges, centers, and other sources within a specific pixel threshold.

However, source snapping operates in visual screen coordinates on the preview panel. Depending on the current zoom level of the preview window, mouse-driven movements can snap to what visually appears to be an integer boundary while recording a fractional value in the underlying scene item properties. Furthermore, rotational transforms inherently produce irrational coordinate values along outer borders, preventing true pixel-to-pixel mapping on a 2D grid.

Achieving Exact 1:1 Pixel Mapping

To eliminate transform rounding errors on non-standard canvas sizes, graphics must bypass dynamic interpolation:

  • Manually Set Transform Properties: Open the Edit Transform menu (Ctrl + E or right-click > Transform > Edit Transform). Ensure that the position coordinates (\(X, Y\)) and bounding box sizes are rounded to whole integer values.
  • Maintain Identical Base and Output Dimensions: Set the Base (Canvas) Resolution and Output (Scaled) Resolution to identical dimensions in the Video Settings. This disables the global downscale pass and ensures the compositor’s output matches the scene-graph coordinates.
  • Apply Point Scale Filtering for Precision Assets: Right-click the graphic source, navigate to Scale Filtering, and select Point. This avoids intermediate texture smoothing if the asset must stay strictly sharp.
  • Avoid Fractional Scaling Multipliers: If scaling up an asset, use whole-number scaling factors (e.g., 200%, 300%) rather than freehand dragging with the transform handles, which creates non-integer dimension footprints.
