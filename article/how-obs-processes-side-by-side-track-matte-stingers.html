How OBS Processes Side-by-Side Track Matte Stingers

OBS Studio processes side-by-side Track Matte stingers by dividing a single video file into two equal halves to handle both visual artwork and transition transparency simultaneously. This article explains how the software splits the video coordinates, reads the matte data, and uses a custom rendering shader to transition between scenes without requiring a dedicated alpha channel video codec.

Understanding the Side-by-Side File Structure

A side-by-side track matte stinger packs two separate video streams into a single standard video file (typically encoded as H.264 or HEVC MP4).

For a standard 1080p (1920x1080) stream, the video file is rendered at double the width: 3840x1080 pixels.

  • The Color Fill (Usually Left): The first 1920x1080 section contains the visible graphic overlay, logos, or full-color motion graphics that appear on top of the transition.
  • The Matte Mask (Usually Right): The adjacent 1920x1080 section contains a grayscale or alpha representation that dictates where and when the underlying stream scenes switch.

Coordinate Splitting and Texture Mapping

When a transition triggers, OBS Studio’s rendering engine identifies the file format selected in the stinger properties ("Side-by-side"). The transition shader calculates the normalized texture coordinates \((U, V)\) and divides the horizontal axis (\(U\)) in half:

  1. Color Coordinates: Mapped across \(U \in [0.0, 0.5]\) to sample the color fill.
  2. Matte Coordinates: Mapped across \(U \in [0.5, 1.0]\) to sample the corresponding matte pixel for the exact same display position.

By sampling both points in parallel on the GPU, OBS ensures zero synchronization drift between the moving graphic and the scene cut beneath it.

Processing the Matte Channel

OBS evaluates the matte section based on the user's selected matte type:

  • Luminance Matte: OBS measures the brightness of each pixel in the matte half. Pure white pixels (value of 1.0) instruct the engine to display Scene B (the incoming scene). Pure black pixels (value of 0.0) instruct it to display Scene A (the outgoing scene). Gray values represent intermediate transparency, creating soft edges or feathered wipes.
  • Alpha Matte: If the video file retains an actual alpha channel within the mask section, OBS evaluates the alpha channel values instead of luminance to blend the incoming and outgoing scenes.

The Final Composite Pipeline

During each frame of the stinger playback, OBS Studio renders the final output using a single multi-layered pass:

  1. Background Layer: The outgoing scene (Scene A) and the incoming scene (Scene B) are fed into the transition shader.
  2. Matte Blending: The shader linearly interpolates (lerp) between Scene A and Scene B based on the sampled matte value: \[\text{Scene Output} = \text{Scene A} \times (1.0 - \text{Matte}) + \text{Scene B} \times \text{Matte}\]
  3. Color Overlay: The sampled color fill is layered directly on top of the blended scenes according to the fill's own opacity or masking properties.

This side-by-side approach allows streamers to use lightweight, hardware-accelerated video formats like MP4 while achieving complex, per-pixel transparency transitions typically limited to heavy formats like ProRes 4444 or WebM with alpha channels.
