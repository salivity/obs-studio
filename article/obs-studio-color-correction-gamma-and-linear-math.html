OBS Studio Color Correction Gamma and Linear Math

OBS Studio handles gamma adjustments in its Color Correction filter through a direct exponential shader operation rather than a true physical linear-light transformation. While rigorous linear color space workflows require converting compressed pixel values into linear luminance before modifying the signal, OBS executes gamma adjustments directly on incoming texture data within its pixel shader. This article explains the shader mechanics behind OBS Studio's gamma controls, compares the process to linear color math, and outlines the practical effects on video rendering.

The Mathematical Formula in OBS Shaders

OBS Studio implements color correction through an HLSL pixel shader (found in color_correction_filter.effect). When a user adjusts the gamma slider, the software maps the slider's floating-point value to an exponent and applies a standard power-law function across the RGB channels:

\[\text{Color}_{\text{out}} = \text{pow}(\text{Color}_{\text{in}}, \frac{1.0}{\gamma})\]

In this function:

  • \(\text{Color}_{\text{in}}\) represents the clamped \([0.0, 1.0]\) color value read directly from the source's texture sampler.
  • \(\gamma\) represents the user-adjusted gamma value.
  • \(\text{Color}_{\text{out}}\) is the resulting pixel value written to the output buffer.

Because \(0.0^{\gamma} = 0.0\) and \(1.0^{\gamma} = 1.0\), the absolute black and white points remain anchored, while the intermediate values (midtones) shift up or down along a non-linear power curve.

Linear Color Space Math vs. OBS Processing

In a physically accurate color pipeline, image math is performed in a linear color space where numerical values are directly proportional to physical light intensity (photometric luminance):

  1. De-gamma / Linearization: Non-linear display-referred inputs (such as sRGB or Rec. 709) are converted to linear light using their inverse electro-optical transfer functions (EOTF).
  2. Linear Processing: Operations such as exposure adjustment, physical lighting calculations, and optical blurs occur while values are linear.
  3. Re-gamma / Encoding: The linear values are transformed back through the display transfer function (OETF) into the target output color space.

OBS Studio's standard Color Correction filter skips the preliminary linearization step when dealing with standard dynamic range (SDR) sources. The input texture sampled by the filter is typically already encoded with an sRGB or Rec. 709 gamma curve.

Instead of converting the signal into linear space and altering exposure or physical gain, OBS applies the power function directly to these already non-linear, perceptual values.

The "Gamma on Gamma" Result

Applying a power function to an already gamma-compressed signal creates a compound curve:

\[\text{Value}_{\text{final}} = (V_{\text{linear}}^{\gamma_{\text{encoding}}})^{\gamma_{\text{filter}}} = V_{\text{linear}}^{\gamma_{\text{encoding}} \times \gamma_{\text{filter}}}\]

Because this math is performed directly on the encoded buffer:

  • Perceptual Shift: The operation functions as an artistic tone curve adjustment rather than a photometrically accurate exposure adjustment.
  • Midtone Redistribution: Increasing gamma boosts the perceptual brightness of darker midtones quickly, compressing highlights. Decreasing gamma pulls the midtones down toward black, expanding highlight contrast.
  • Hue and Saturation Side Effects: Because the power function is applied independently across the red, green, and blue channels without constant-luminance weighting, large gamma shifts can introduce non-linear saturation shifts and slight hue shifts in highly saturated midtones.

Performance Considerations

OBS Studio avoids full linearization in its basic Color Correction filter to preserve GPU performance. Direct evaluation of a single pow() call on the existing render target avoids the computational overhead of matrix color conversions and inverse/forward transfer functions on every frame. This ensures high-throughput, low-latency rendering across diverse hardware configurations during real-time streaming and recording.
