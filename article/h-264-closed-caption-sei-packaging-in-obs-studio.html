H.264 Closed Caption SEI Packaging in OBS Studio

This article provides a technical breakdown of how OBS Studio formats, encapsulates, and injects CEA-608 and CEA-708 closed captioning data into H.264 elementary bitstreams. It covers the end-to-end data path, from receiving raw caption bytes within the libobs core to structuring ATSC A/53-compliant Supplemental Enhancement Information (SEI) payloads, handling byte-level emulation prevention, and ordering Network Abstraction Layer (NAL) units for real-time streaming protocols like RTMP and MPEG-TS.

Caption Ingestion and Buffer Handling

OBS Studio accepts closed caption data primarily through specialized input plugins (such as DeckLink SDI VANC capture) or via speech-to-text filters. Within libobs, caption data is normalized into 3-byte EIA-608/CEA-608 or multi-byte CEA-708 data packets (cc_data). These packets are synchronized with the internal audio/video presentation timestamps (PTS) to ensure accurate alignment with the corresponding video frames.

Instead of writing caption data into separate container-level metadata tracks, live broadcast standards require embedding captions directly into the video elementary stream. OBS queues these synchronized caption packets in its video encoding pipeline to be processed on the next encoded video frame.

The ATSC A/53 SEI Payload Structure

H.264 relies on Supplemental Enhancement Information (SEI) NAL units (NAL unit type 6) to carry non-slice data such as captions, mastering metadata, and timecodes. Closed captions in H.264 use the ITU-T T.35 User Data Registered format, defined by payload type 4.

OBS Studio structures the raw SEI payload according to the ATSC A/53 Part 4 specification. The payload is laid out sequentially as follows:

  1. Payload Type: 0x04 (user_data_registered_itu_t_t35).
  2. Payload Size: Variable byte length calculated using standard H.264 variable-length encoding (where any byte equal to 0xFF indicates an overflow to the next byte).
  3. ITU-T T.35 Country Code: 0xB5 (representing the United States).
  4. Provider Code: 0x0031 (16-bit integer denoting ATSC).
  5. User Identifier: 0x47413934 (ASCII for GA94, standard ATSC identifier).
  6. User Data Type Code: 0x03 (designates cc_data).
  7. Caption Header: Contains control flags, including process_cc_data_flag, additional_data_flag, and a 5-bit cc_count indicating the number of 3-byte caption constructs that follow.
  8. Caption Data Packets: The sequence of 3-byte triplets containing the marker_bits, cc_valid flag, cc_type (CEA-608 Field 1/2 or CEA-708), and the two payload data bytes (cc_data_1 and cc_data_2).
  9. Payload Trailing Bits: A trailing byte (typically 0xFF as marker padding) to close the A/53 payload.

Raw Byte Stream Encoding and Emulation Prevention

Once the user_data_registered_itu_t_t35 payload is fully assembled in memory, it exists as a Raw Byte Sequence Payload (RBSP). Before this RBSP can be placed into a bitstream, it must be protected against accidental start code emulation.

In an H.264 elementary stream, start codes take the form of 0x000001 or 0x00000001. If the caption payload naturally contains binary sequences matching these patterns, a decoder will misinterpret the caption payload as a new NAL unit boundary. OBS Studio—or the underlying encoder library (such as libx264, NVENC, or Apple VideoToolbox)—processes the RBSP to insert an emulation prevention byte (0x03) wherever the following sequences occur:

  • 0x00 0x00 0x00 \(\rightarrow\) 0x00 0x00 0x03 0x00
  • 0x00 0x00 0x01 \(\rightarrow\) 0x00 0x00 0x03 0x01
  • 0x00 0x00 0x02 \(\rightarrow\) 0x00 0x00 0x03 0x02
  • 0x00 0x00 0x03 \(\rightarrow\) 0x00 0x00 0x03 0x03

The resulting data stream is the Encapsulated Byte Sequence Payload (EBSP).

NAL Unit Packaging and Stream Injection

To finalize the NAL unit, a 1-byte H.264 NAL header is prepended to the EBSP:

  • forbidden_zero_bit: 0 (1 bit)
  • nal_ref_idc: 00 (2 bits, indicating that SEI units do not modify reference frame states)
  • nal_unit_type: 00110 (5 bits, evaluating to 6 for SEI)

This yields a combined single-byte header of 0x06.

OBS Studio inserts this complete SEI NAL unit into the video packet buffer immediately preceding the primary coded picture slice NAL units (types 1 or 5) of the associated frame. When using Annex B formatting (typical for MPEG-TS), a 3-byte or 4-byte start code (0x00000001) is prefixed to the SEI unit. When using AVCC formatting (typical for RTMP/FLV and MP4), a 4-byte big-endian length prefix replaces the start code.

Because the SEI packet is injected upstream directly into the outgoing frame buffer, consumer platforms, decoders, and media players extract and parse the embedded EIA-608/CEA-708 data directly from the H.264 access units without requiring secondary network requests or out-of-band subtitle streams.
