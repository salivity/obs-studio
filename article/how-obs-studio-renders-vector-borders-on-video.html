How OBS Studio Renders Vector Borders on Video

OBS Studio renders custom vector borders around cropped camera frames through a multi-stage graphics pipeline that involves coordinate mapping, vector rasterization, shader-based masking, and GPU hardware compositing. Because OBS operates natively on raster textures within its rendering subsystem (libobs/graphics), vector paths defining custom borders must be translated into pixel coordinates and blended with the cropped video texture using custom HLSL or GLSL shaders.

1. Frame Acquisition and Texture Cropping

When a camera capture device feeds video into OBS Studio, the raw video frames are uploaded into VRAM as 2D textures using Direct3D 11 (Windows), Metal (macOS), or OpenGL (Linux).

When a user applies a crop—either via scene item transform settings or the dedicated Crop/Pad filter—OBS modifies the texture coordinates (UV coordinates) rather than cutting the underlying buffer immediately:

  • The source frame's UV mapping [0.0, 1.0] is re-scaled to the cropped dimensions.
  • The vertex buffer for the source quad is recalculated to match the cropped bounding box.
  • Non-destructive cropping is maintained in VRAM, allowing dynamic border alignment around changing frame boundaries.

2. Vector Path Ingestion and Rasterization

OBS Studio does not contain a native vector rendering engine (such as Skia) in its core compositing loop. Instead, vector paths used for borders and masks—typically supplied as SVG files or parametric shapes via plugins—are processed using one of two methods:

  • Pre-Rasterization via CPU/Libraries: External vector paths (SVGs) are commonly rasterized upon loading using integrated libraries like librsvg or Qt's SVG rendering tools. The vector path is converted into an offscreen RGBA texture at the project’s canvas resolution or the source's native resolution.
  • Signed Distance Fields (SDF) or Procedural Shaders: Advanced border plugins generate shapes mathematically inside the fragment shader using Signed Distance Fields. This method preserves crisp vector edges dynamically without requiring intermediate raster textures.

3. Coordinate Alignment and Aspect Ratio Normalization

To accurately trace the outline of a cropped camera frame, the border's path coordinates must align with the post-crop bounding box. OBS normalizes the dimensions:

  1. Resolution Matching: The vector path's aspect ratio is matched to the post-crop resolution of the camera frame.
  2. Padding and Stroke Allocation: If an outer border is applied, the source quad is expanded outward by the pixel width of the stroke to prevent edge-clipping. If an inner border is applied, the stroke is clamped to the interior bounds of the cropped frame.

4. Shader Execution and Blending

The final integration of the vector border and cropped video frame is executed via an effect file (HLSL/GLSL pixel shader):

  • Masking (Alpha Channel): If the vector path defines a non-rectangular shape (such as rounded corners or an angled polygon), the path’s rasterized alpha channel is sampled. The camera texture's alpha is multiplied by the mask alpha, discarding pixels outside the boundary.
  • Border Compositing: The border path texture (or procedurally generated stroke) is overlaid on top of the masked camera frame. The shader checks the distance from the path edge to perform analytical anti-aliasing via functions like fwidth() and smoothstep().
  • Blend States: The resulting color is calculated using standard alpha blending (SRC_ALPHA, ONE_MINUS_SRC_ALPHA) to seamlessly merge the border stroke with both the video feed and the scenes below it.

5. Final Canvas Pass

Once the shader completes execution, the combined texture (the cropped, masked camera frame and its rendered vector border) is drawn onto the scene’s main render target. This frame is then passed along to the OBS rendering pipeline for preview rendering and stream/recording encoding.
