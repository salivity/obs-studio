Why Animated SVGs Cause High CPU in OBS Browser Source

Displaying complex animated SVG graphics inside an OBS Studio browser source often leads to high CPU usage because the underlying Chromium Embedded Framework must continuously calculate, rasterize, and redraw mathematical vector paths on every frame. Unlike standard video formats that simply unpack pre-rendered pixels, animated vector elements force the browser engine to perform real-time geometry calculations and software-based repaints, quickly exhausting processor resources during live rendering.

Real-Time Vector Rasterization

Scalable Vector Graphics (SVGs) are not made of static pixel grids; they consist of XML-based mathematical instructions defining points, curves, and lines. When an SVG is animated, the browser cannot merely display an existing bitmap. Instead, it must re-calculate these mathematical formulas and convert (rasterize) them into pixels dynamically for every single frame of the animation. At typical stream frame rates of 60 frames per second, this recalculation generates a massive, non-stop computational workload.

Chromium Embedded Framework (CEF) Limitations

OBS Studio handles web content through the Chromium Embedded Framework (CEF). While modern standalone browsers like Google Chrome efficiently offload many vector rendering tasks to the GPU, the embedded browser inside OBS often defaults to or falls back on software rendering. If hardware acceleration is disabled in OBS settings, or if the GPU driver does not properly interface with CEF, the central processor is forced to execute all compositing, rendering, and rasterization tasks entirely in software.

Continuous DOM Reflow and Repaints

Animated SVGs—whether driven by CSS animations, SMIL (<animate> tags), or JavaScript—frequently trigger two expensive browser pipeline events: "reflow" (layout calculation) and "repaint" (pixel painting).

  • Attribute Alterations: Animating path attributes (such as d, cx, cy, or points) directly alters the geometry, forcing the browser to recompute the entire layout of the vector object.
  • Filter Effects: Elements using SVG filters (like feGaussianBlur, drop shadows, or blend modes) demand heavy mathematical convolutions per pixel. Processing these filters on a frame-by-frame basis without dedicated GPU shaders immediately spikes CPU usage.

Excessive Path Complexity

The internal complexity of the SVG file directly correlates to processing time. Graphics with thousands of anchor points, dense grouping hierarchies, clipping masks, and nested gradients require extensive tree traversals and floating-point operations. When complex shapes morph or move across each other, the browser must also calculate complex layer intersections and anti-aliasing algorithms to keep edges smooth, further saturating CPU cores.

Resolution and Scaling Overhead

Browser sources in OBS are often mapped to canvas resolutions of 1080p or 4K. Because SVGs are resolution-independent, the browser engine scales the math to fit the designated output viewport. Rasterizing complex vectors across large pixel dimensions requires significantly more CPU cycles than rasterizing smaller assets, as the surface area requiring pixel shading scales exponentially with canvas resolution.
