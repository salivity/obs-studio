OBS Studio Aspect Ratio Lock Mechanism

OBS Studio maintains source proportions during freehand transformations by capturing mouse interactions on its preview canvas, projecting these movements into the source's local coordinate space, and applying mathematical scalar constraints before updating the scene item's affine transformation matrix. By recalculating dimensions along a locked diagonal axis or applying a uniform scale factor to both dimensions, the software ensures that freehand dragging cannot distort the native width-to-height ratio of the visual asset.

Input Capture and Coordinate Translation

The transformation workflow begins within the preview viewport subsystem (OBSBasicPreview). When a user clicks and drags a transform handle—typically located on the corners or edges of a selected source—the user interface captures the cursor’s raw screen coordinates via Qt event handlers (mouseMoveEvent).

Because the canvas can be panned, zoomed, or rendered at a different resolution than the output base resolution, the system first maps these screen coordinates back into canvas-space coordinates. It then uses the inverse of the source’s current transform matrix to convert the canvas-space delta into the source’s local model coordinate space.

The Scalar Constraint Calculation

Once the cursor's movement is translated into local coordinates, OBS Studio evaluates whether the aspect ratio lock is enforced. Aspect ratio preservation is either the default state or toggled via modifier keys (such as holding Shift to disable locking, depending on configuration).

To lock the aspect ratio during corner-handle transformations, OBS Studio evaluates the displacement along the primary axes and constrains the scaling vector:

  1. Delta Projection: The engine calculates the requested change in width (\(\Delta x\)) and height (\(\Delta y\)) based on the handle position.
  2. Dominant Axis or Diagonal Vectoring: Rather than independently applying \(\Delta x\) to the width and \(\Delta y\) to the height, the transformation logic projects the mouse offset onto the aspect ratio vector \((W_{base}, H_{base})\). Alternatively, it identifies the dominant axis of movement and calculates a single uniform scale factor \(k\): \[k = \frac{\text{New Dimension}}{\text{Base Dimension}}\]
  3. Coupled Scaling: The engine forces the secondary axis to conform to \(k\): \[\text{Scale}_x = k\] \[\text{Scale}_y = k\]

If a side handle (top, bottom, left, or right) is dragged while aspect ratio locking is enforced, the movement along a single axis automatically scales the perpendicular axis proportionally from the source's defined origin or anchor point.

Matrix Construction and the Scene Pipeline

After computing the constrained scale factors, the interaction logic passes the values to the core scene management subsystem (libobs/obs-scene.c) using functions such as obs_sceneitem_set_scale().

The underlying pipeline converts the position, rotation, and constrained scale values into a standard 4x4 affine transformation matrix (matrix4). During rendering, this matrix is pushed to the OBS graphics subsystem (libobs/graphics), transforming the vertex coordinates of the source quad. Because the horizontal and vertical scaling components of the matrix are kept mathematically coupled, the GPU renders the source texture with its original proportions preserved across every frame.
