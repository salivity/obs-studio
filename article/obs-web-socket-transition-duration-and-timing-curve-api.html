OBS WebSocket Transition Duration and Timing Curve API

Controlling program scene transitions through the OBS Studio WebSocket protocol (obs-websocket v5) requires interacting with transition-specific requests and parameters. While transition duration is explicitly defined through the transitionDuration parameter in milliseconds, manipulating the timing curve (easing) is handled either through custom transition properties passed via transitionSettings or dynamically generated using the SetTBarPosition API.

Transition Duration: SetCurrentSceneTransitionDuration

To set how long a transition takes, the WebSocket API provides the SetCurrentSceneTransitionDuration request.

  • Request Type: SetCurrentSceneTransitionDuration
  • Governing Parameter: transitionDuration (Integer)
  • Description: Defines the length of the transition in milliseconds.

When querying the current transition state via GetCurrentSceneTransition, the response returns the active transitionDuration alongside transitionName, transitionKind, and transitionFixed. Standard triggers, such as TriggerStudioModeTransition, execute using this defined millisecond value.

Transition Settings and Timing Curves: SetCurrentSceneTransitionSettings

Native OBS Studio transitions (such as Cut, Fade, and Slide) utilize fixed linear timing or predefined internal curves that do not feature an open-ended generic "curve" parameter in core requests. To adjust transition-specific timing properties or custom curves provided by plugins, developers use:

  • Request Type: SetCurrentSceneTransitionSettings
  • Governing Parameters:
    • transitionName (String): The name of the transition to configure.
    • transitionSettings (Object): A key-value map configuring the internal parameters of the specific transition kind.
    • overlay (Boolean, optional): Whether to merge the settings with existing settings or overwrite them.

When using advanced transition plugins, such as the popular Move Transition plugin, the transitionSettings object exposes specific curve parameters, including:

  • easing (Integer / String): Defines easing types (e.g., Quadratic, Cubic, Quintic, Sine, Exponential, Circular).
  • curve (Float): Modifies the tension or curve steepness depending on the easing function selected.

Custom Timing Curves via T-Bar Emulation: SetTBarPosition

For complete mathematical control over custom timing curves on native transitions, the API allows developers to bypass the internal timer and drive the transition curve manually using T-Bar controls.

  • Request Type: SetTBarPosition
  • Governing Parameters:
    • position (Number / Float): A value between 0.0 and 1.0 representing the progress percentage of the transition.
    • release (Boolean): Determines whether to complete and release the T-Bar once the final position is reached.

By implementing mathematical easing functions (such as Bezier, Ease-In-Out, or custom cubic equations) client-side, developers send successive SetTBarPosition requests with variable step intervals to achieve non-linear timing curves across any OBS transition type. Setting release: true on the final request (position: 1.0) commits the transition to the Program output.
