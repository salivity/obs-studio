How OBS Studio Captures Wayland Windows with PipeWire

This article explores the technical pipeline OBS Studio uses to capture individual application windows under Linux Wayland compositors through PipeWire and the XDG Desktop Portal framework. Due to Wayland's strict security model, individual applications cannot directly access the window buffers of other running programs. Instead, OBS Studio orchestrates capture by delegating user permissions to the compositor, receiving a hardware-accelerated media stream through PipeWire, and importing frame buffers directly into its graphics pipeline for low-latency compositing.

The Wayland Security Barrier

Under legacy X11 display servers, every client has unrestricted read and write access to the global display server, making window and screen capture straightforward via standard X11 protocol requests. Wayland fundamentally departs from this design by isolating client surfaces. Each application only renders to its own private buffers, and the Wayland compositor alone manages the global scene graph. To maintain this security isolation without permanently breaking desktop capture functionality, the Linux desktop ecosystem standardizes capture through external system interfaces rather than extending the core Wayland protocol directly to client applications like OBS Studio.

The XDG Desktop Portal Handshake

When an OBS Studio user creates a "Window Capture (PipeWire)" source, the application cannot directly query the system for a list of open windows. Instead, OBS initiates an IPC request over the D-Bus system bus to the org.freedesktop.portal.ScreenCast interface exposed by xdg-desktop-portal.

The portal service dispatches the request to the active desktop environment's specific backend implementation, such as xdg-desktop-portal-gnome, xdg-desktop-portal-kde, or xdg-desktop-portal-wlr. At this stage, the compositor—not OBS—presents an interface prompt allowing the user to select the specific window they wish to capture. This preserves the security model: untrusted software cannot surreptitiously target a window without explicit user consent.

Session Establishment and PipeWire Stream Routing

Once the user approves the window selection, the compositor configures a private capture session. The compositor hooks directly into its internal rendering pipeline to duplicate the chosen window's surface whenever that window redraws.

To transfer these video frames back to OBS, the portal creates a PipeWire multimedia node. PipeWire acts as an IPC media router, specialized in handling low-latency video and audio streams between isolated processes. The desktop portal passes two critical pieces of data back to OBS Studio over D-Bus:

  1. A file descriptor providing access to the PipeWire daemon.
  2. A unique PipeWire Node ID corresponding to the newly created capture stream.

Buffer Transfer via DMA-BUF

With the node ID and file descriptor, OBS Studio's internal PipeWire capture plugin connects directly to PipeWire's graph. Rather than copying frame data across CPU memory—which would introduce severe performance penalties and CPU overhead—the capture pipeline relies on DMA-BUF (Direct Memory Access Buffer) sharing.

  1. Surface Redraw: When the target window updates, the compositor renders the surface into a GPU buffer.
  2. Buffer Export: The compositor exports this buffer as a DMA-BUF file descriptor.
  3. PipeWire Transport: PipeWire passes the buffer metadata and the DMA-BUF descriptor across the process boundary to OBS Studio using Unix domain sockets.
  4. Zero-Copy Ingestion: OBS Studio receives the file descriptor and imports the buffer straight into its graphics context (typically via EGL and OpenGL) as an external texture.

Through DMA-BUF, the pixel data remains entirely within VRAM, bypassing system RAM and enabling zero-copy frame ingestion at native display refresh rates.

Handling Window Resizing and Lifecycle

Discrete window capture introduces dynamic challenges that full-screen capture avoids, notably window resizing and minimization. When a captured window changes dimensions, the compositor allocates new DMA-BUFs matching the new geometry.

PipeWire handles this dynamism by negotiating format and parameter changes on the fly via the SPA (Simple Plugin Architecture) protocol. OBS receives a renegotiation event, updates the scaling and UV coordinate mapping for the source, and seamlessly adjusts the rendered texture without dropping the capture session. If the window closes, the compositor destroys the backing surface, prompting PipeWire to signal an end-of-stream state, which OBS Studio reflects by clearing the frame or rendering a transparent placeholder.
