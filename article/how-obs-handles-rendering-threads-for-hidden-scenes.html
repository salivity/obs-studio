How OBS Handles Rendering Threads for Hidden Scenes

This article examines the internal behavior of OBS Studio when an entire parent scene is hidden or deactivated, focusing on how the graphics pipeline and underlying source threads respond. When a parent scene is hidden, OBS Studio prunes that scene from the active scene graph, immediately halting GPU draw calls for child elements. However, whether the underlying capture, decoding, and worker threads stop, pause, or continue operating in the background depends entirely on OBS Studio’s activation signals, internal buffering models, and source-specific configuration settings.

The Render Loop and Scene Graph Traversal

OBS Studio utilizes a dedicated graphics thread that runs continuously at the configured canvas frame rate (e.g., 60 FPS). During each tick, this thread traverses the active scene graph starting from the output channels (Program, Studio Mode Preview, or active Virtual Camera outputs).

When a parent scene's visibility is toggled off:

  1. Draw Call Elimination: The graphics thread checks the visibility flag of the scene item. If the parent scene is marked invisible, the rendering pipeline skips the traversal of that branch entirely.
  2. GPU Texture Updates Halt: Because the render function (obs_source_video_render) is never called for the child sources within that branch, no draw calls, vertex transformations, or pixel shaders are executed for them.
  3. Compositing Bypass: The parent scene ceases to allocate or update its offscreen intermediate render target, immediately reducing GPU load.

Visibility vs. Deactivation Signals

OBS Studio strictly differentiates between visibility (whether an item is drawn to a frame) and activation (whether an item is active in the pipeline).

When a scene is hidden from the main mix, OBS fires internal signals down the hierarchy:

  • hide: Dispatched when the source is no longer visually rendered.
  • deactivate: Dispatched when the source is completely removed from all active outputs (Program, Preview, and active recordings/streams).

If a scene is hidden on the Program output but still visible in Studio Mode Preview or a Multiview projector, it receives a hide signal for the program context but remains active globally. If it is hidden across all viewports, it receives a full deactivate signal.

Behavior of Specific Source Threads

Although the GPU stops rendering the frames, the behavior of CPU worker threads, hardware decoders, and frame capture loops varies by source type.

Video Capture Devices (Webcams, Capture Cards)

Most direct hardware capture drivers maintain an active capture thread even when deactivated. While raw frames are discarded instead of uploaded to GPU VRAM textures, the hardware thread often keeps polling to prevent device re-initialization latency and USB bus renegotiation freezes when unhidden.

Browser Sources

OBS Browser sources (powered by the Chromium Embedded Framework / CEF) operate independent render and process loops.

  • If the setting "Shutdown source when not visible" is unchecked, CEF continues executing JavaScript, processing CSS animations, and generating software frame buffers in the background, though OBS ceases copying these buffers to the GPU.
  • If the setting is checked, OBS destroys the underlying CEF frame provider, completely terminating the web page's execution threads until the scene is made visible again.

Media Sources (Local Files and Streams)

Media sources rely on FFmpeg demuxing and decoding threads.

  • If "Close file when inactive" is disabled, decoding threads remain paused or maintain a minimal buffer, holding the file handle open.
  • If enabled, the playback thread is killed, the file handle is released, and the memory footprint is cleared. When toggled back on, the thread must re-instantiate and seek to the specified timestamp.

Game Capture and Window Capture

Game capture hooks inject a dynamic-link library (DLL) into the target process. When the parent scene is hidden, the hook thread inside the game continues to detect frame presentations, but OBS stops copying the shared memory texture. Window capture (via Windows Graphics Capture or BitBlt) stops pulling desktop frames entirely, allowing the capturing worker thread to sleep until visibility resumes.

Audio Pipeline Independence

Audio in OBS Studio is processed on a discrete subsystem isolated from the video rendering pipeline. Video visibility toggles do not automatically silence audio. If a parent scene containing an active audio-producing source is hidden visually, the audio rendering thread continues to sample, filter, and mix the audio frames into the output bus unless the source is explicitly muted, assigned to an inactive audio track, or governed by a deactivation rule that tears down the entire media container.
