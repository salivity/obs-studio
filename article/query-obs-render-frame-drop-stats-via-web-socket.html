Query OBS Render Frame Drop Stats via WebSocket

This article explains how to retrieve real-time rendering frame drop statistics from OBS Studio using its native WebSocket server. It identifies the exact Remote Procedure Call (RPC) request required under the modern obs-websocket protocol, demonstrates the payload structure, and highlights the specific fields in the response that measure rendering lag and dropped frames.

The Specific RPC Request: GetStats

To query current rendering performance and frame drop statistics in OBS Studio (v28 and later using obs-websocket v5 protocol), you must send the GetStats request.

OBS WebSocket uses JSON-RPC-styled messages over an established WebSocket connection. A client sends a message containing an operation code (op: 6 for a Request) along with the request payload data.

Request Payload

The client must send the following JSON message:

{
  "op": 6,
  "d": {
    "requestType": "GetStats",
    "requestId": "f9409477-7690-4a88-8255-66779435b6b1"
  }
}
  • op (6): Specifies the operation code for a Request.
  • requestType ("GetStats"): Identifies the specific command that queries system and session statistics.
  • requestId: A unique alphanumeric identifier supplied by the client to correlate the asynchronous response back to this specific request.

Response Data and Rendering Drop Fields

When OBS processes the GetStats command, it responds with an operation code 7 (RequestResponse) containing execution status and a responseData object.

A typical response payload looks like this:

{
  "op": 7,
  "d": {
    "requestType": "GetStats",
    "requestId": "f9409477-7690-4a88-8255-66779435b6b1",
    "requestStatus": {
      "result": true,
      "code": 100
    },
    "responseData": {
      "activeFps": 60.0,
      "averageFrameRenderTime": 4.12,
      "renderSkippedFrames": 42,
      "renderTotalFrames": 125430,
      "outputSkippedFrames": 0,
      "outputTotalFrames": 125400,
      "cpuUsage": 5.4,
      "memoryUsage": 820.5,
      "availableDiskSpace": 245600.0
    }
  }
}

Relevant Statistical Metrics

To evaluate rendering-specific performance from the responseData object, inspect the following keys:

  • renderSkippedFrames: The cumulative number of frames missed specifically due to rendering lag. This occurs when the GPU cannot composite scenes within the target frame budget.
  • renderTotalFrames: The total number of frames rendered by the canvas during the current session.
  • averageFrameRenderTime: The average duration (in milliseconds) required to render a single frame.

Dividing renderSkippedFrames by renderTotalFrames yields the exact percentage of rendering frame drops for the session. Note that this is distinct from outputSkippedFrames, which measures drops caused by video encoding lag.
