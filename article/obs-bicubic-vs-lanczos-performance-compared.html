OBS Bicubic vs Lanczos: Performance Compared

When configuring video settings in OBS Studio, choosing between the Bicubic (16 samples) and Lanczos (36 samples) downscale filters directly impacts both visual fidelity and GPU resource consumption. This article compares the computational complexity, hardware overhead, and practical performance differences between these two algorithms to help you choose the right filter for your hardware setup.

Algorithmic Complexity and Sample Counts

The primary computational difference lies in the kernel size used for pixel interpolation during scaling:

  • Bicubic (16 samples): Bicubic scaling samples a 4x4 grid of surrounding pixels (16 total texture lookups) to calculate the value of each destination pixel. It uses cubic splines to produce a smooth, moderately sharp image.
  • Lanczos (36 samples): Lanczos scaling uses a sinc-based windowed filter across a 6x6 grid (36 total texture lookups) per destination pixel.

Because Lanczos processes 36 samples per output pixel compared to Bicubic’s 16, it requires 2.25 times (225%) more texture fetches and mathematical operations per frame for every pixel rendered on the canvas.

GPU Impact and Rendering Overhead

OBS Studio performs all video scaling on the graphics processing unit (GPU) via custom pixel shaders. The computational cost of these filters scales directly with the output resolution and target framerate (e.g., 1080p at 60 FPS requires rendering approximately 124.4 million pixels per second).

  • Texture Memory Bandwidth: Lanczos puts significantly higher strain on GPU memory bandwidth due to the increased sample fetches. On dedicated modern GPUs (such as NVIDIA RTX or AMD Radeon RX series), this extra bandwidth is typically negligible, resulting in render time differences of less than 0.2 milliseconds per frame.
  • Integrated and Low-End GPUs: On systems using integrated graphics (Intel Iris/UHD, AMD APUs) or older dedicated cards with limited memory bandwidth and compute units, the 2.25x calculation jump of Lanczos can cause frame rendering stalls. This manifests in OBS as "encoding lag" or "rendering lag" (missed frames due to rendering delay).

Visual Trade-Offs vs. Processing Cost

While Lanczos is computationally heavier, the visual improvement does not always scale proportionally with the performance cost:

  • Bicubic (16 samples): Delivers a balanced, natural image with minimal edge distortion. It requires very low processing power, making it the safest default choice for almost all hardware profiles.
  • Lanczos (36 samples): Preserves sharper text and high-contrast lines better than Bicubic. However, the higher-frequency sinc algorithm can introduce "ringing" artifacts (faint halos along sharp edges) and higher bitrate demand, as the extra sharpness increases high-frequency noise that video encoders must compress.

Recommendation

For modern dedicated GPUs with rendering headroom, Lanczos can be used safely to maximize image sharpness without noticeable performance degradation. For setups with high base GPU usage (such as streaming GPU-intensive games from a single PC) or systems utilizing integrated graphics, Bicubic (16 samples) is recommended to prevent rendering lag while retaining high visual clarity.
