H.264 Color Primaries Metadata in OBS Studio

This article provides an overview of how OBS Studio manages and embeds color primaries metadata within outgoing H.264 video streams. It details the role of the Sequence Parameter Set (SPS), the translation of internal OBS color configurations into Video Usability Information (VUI) syntax, and how software and hardware encoders implement these tags to ensure accurate color reproduction across playback platforms.

The H.264 VUI Metadata Structure

In H.264 (AVC) bitstreams, color information is not stored within the raw pixel data itself. Instead, it is signaled through the Video Usability Information (VUI) parameters embedded in the Sequence Parameter Set (SPS) NAL units, as defined in Annex E of the ITU-T H.264 specification.

When color signaling is enabled, the bitstream sets the colour_description_present_flag to 1. This exposes three distinct fields:

  • colour_primaries: Defines the chromaticity coordinates of the source color primaries (e.g., Rec. 709, Rec. 601, Rec. 2020).
  • transfer_characteristics: Specifies the opto-electronic transfer function (e.g., standard SDR gamma, PQ, or HLG).
  • matrix_coefficients: Dictates the matrix used to derive luma and chroma signals from the green, blue, and red primaries.

OBS Studio is responsible for passing the correct integer values for these fields from its internal rendering engine to the selected video encoder.

How OBS Studio Translates Internal Color Settings

OBS Studio allows users to configure the color pipeline under Settings > Advanced > Video. The primary controls affecting metadata generation are Color Format, Color Space, and Color Range.

When a frame is prepared for encoding, OBS takes these project-level properties and maps them directly to corresponding standardized values:

  • Rec. 709: The colour_primaries field is tagged with the value 1 (ITU-R BT.709).
  • Rec. 601: The colour_primaries field is tagged with either 6 (SMPTE 170M) or 5 (ITU-R BT.470 System B, G), depending on whether NTSC or PAL-derived variants are targeted.
  • Rec. 2020 / Rec. 2100: Added in modern OBS Studio releases for HDR pipelines, setting the value to 9 (ITU-R BT.2020).

Alongside primaries, OBS tags the video_full_range_flag based on the Color Range setting. Selecting "Limited" sets this flag to 0 (studio swing, 16–235), while "Full" sets it to 1 (full swing, 0–255).

Encoder Implementation: Software vs. Hardware

OBS Studio does not write H.264 NAL units manually; it relies on encoder backends to write the SPS headers. The method of injecting color primaries depends on the active encoder module:

1. Software Encoding (libx264)

When using x264, OBS passes configuration parameters directly to the encoder instance. Internally, this populates the x264_param_t structure:

  • param.vui.i_colorprim receives the integer matching the configured color space.
  • param.vui.i_transfer and param.vui.i_colmatrix are set in tandem.
  • param.vui.b_fullrange is configured according to the range setting.

If custom x264 options are used (such as manually specifying colorprim=bt709), those options will override the defaults generated by OBS Studio.

2. Hardware Encoders (NVENC, QuickSync, AMF)

For hardware encoders, OBS utilizes vendor-specific APIs or FFmpeg wrappers:

  • NVIDIA NVENC: OBS populates NV_ENC_CONFIG_H264_VUI_PARAMETERS within the encoder configuration structure, explicitly specifying colourPrimaries, transferCharacteristics, and matrixCoefficients.
  • Intel QuickSync (QSV) and AMD AMF: OBS assigns equivalent parameters in their respective initialization structures, ensuring the hardware encoder generates compliant SPS NAL units with the requested VUI payloads.

Downstream Implications

Accurate tagging of colour_primaries by OBS Studio prevents playback discrepancies. Video decoders in web browsers, media players (like VLC), and streaming ingestion services (such as YouTube and Twitch) read the VUI parameters inside the H.264 SPS to convert YUV data back to RGB for display. If OBS leaves these fields untagged or improperly mapped, the playback client will typically fall back to default assumptions—often assuming Rec. 601 for standard-definition content and Rec. 709 for high-definition content—which can result in slight color shifts or crushed shadow detail.
