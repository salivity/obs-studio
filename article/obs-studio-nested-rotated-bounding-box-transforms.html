OBS Studio Nested Rotated Bounding Box Transforms

OBS Studio resolves complex layouts of nested, rotated sources by evaluating hierarchical 2D affine transformation matrices across a scene graph. When sources reside within nested scenes or groups, OBS does not compute complex polygon boolean intersections directly; instead, it accumulates translation, rotation, scale, and alignment into a global transform matrix or resolves nested scenes sequentially through off-screen render targets. This article details the mathematical pipeline, coordinate spaces, and rasterization methods OBS Studio uses to compute these nested transforms and intersections.

Hierarchical Scene Graph and Local Transforms

OBS Studio organizes sources, groups, and nested scenes into a parent-child hierarchy. Every visual item in a scene possesses an individual transform state consisting of:

  • Position: The \((X, Y)\) offset relative to the parent container.
  • Rotation: An angular rotation value (in degrees) around a defined origin point.
  • Scale and Size: The horizontal and vertical scaling factors derived from source dimensions or designated bounding box sizes.
  • Alignment (Pivot Point): An anchor point (e.g., top-left, center) that determines the local origin \((0, 0)\) for scaling and rotation operations.

To place an element on the screen, OBS calculates a \(3 \times 3\) affine transformation matrix (\(M\)) in homogeneous 2D coordinates for each item:

\[M_{\text{local}} = T(\text{position}) \times R(\text{rotation}) \times S(\text{scale}) \times T(-\text{pivot})\]

Nested Matrix Multiplication

When elements are nested inside groups, OBS multiplies the child’s local matrix by the parent's accumulated transformation matrix:

\[M_{\text{final}} = M_{\text{parent}} \times M_{\text{local}}\]

This sequential matrix multiplication propagates rotation, translation, and non-uniform scaling down the tree. A vertex \(V_{\text{local}} = (x, y, 1)^T\) defined in the local space of the innermost child is mapped to canvas space coordinates via:

\[V_{\text{canvas}} = M_{\text{final}} \times V_{\text{local}}\]

Because matrix multiplication preserves collinearity and ratios of distances, applying consecutive rotations produces a combined rotation equal to the sum of the angles (modulo \(360^\circ\)), adjusted for any non-uniform scale introduced by parent containers.

Nested Scenes vs. Groups: The Render Target Difference

OBS Studio handles nested transformations differently depending on whether the container is a Group or a Nested Scene:

1. Groups (Direct Transform Pass-Through)

Groups act as coordinate-space containers. The vertices of sources inside a group are transformed directly by the group’s matrix and drawn directly to the main canvas backbuffer. If two rotated sources within a group intersect, their four-corner quad coordinates are transformed independently into canvas space, and the graphical overlap is resolved per-pixel via the depth/blend state during rasterization.

2. Nested Scenes (Texture Flattening)

When an entire Scene is added as a source into another Scene, OBS treats the child scene as an isolated sub-graph:

  • The child scene renders all of its internal rotated sources into an intermediate off-screen render target (a separate 2D texture) sized to that scene’s defined dimensions.
  • Internal rotations and intersections are fully rasterized and blended inside this intermediate buffer.
  • The resulting texture is then assigned a single four-point bounding quad in the parent scene.
  • The parent's rotation and scaling transformations are subsequently applied to this flattened rectangular quad.

Consequently, any rotation applied inside the nested scene affects only the pixels within the intermediate texture, while the parent rotation rotates the entire boundary of that intermediate texture.

Bounding Box Types and Alignment Calculation

OBS allows users to wrap sources in distinct bounding box types (e.g., Scale to inner bounds, Scale to outer bounds, Stretch to bounds). When a source with an explicit bounding box is rotated:

  1. Local Axis Alignment: The bounding box is established in the source’s local unrotated coordinate space.
  2. Corner Projection: The four corners of the bounding box are multiplied by the accumulated rotation and scale matrix.
  3. Oriented Bounding Box (OBB): The interactive selection box in the OBS preview window displays the true Oriented Bounding Box (OBB) by drawing lines between the four transformed vertices.
  4. Axis-Aligned Bounding Box (AABB) Computation: When OBS needs to determine clipping or visibility rejection against the viewport, it calculates an AABB by taking the minimum and maximum \(X\) and \(Y\) coordinates from the four transformed corners: \[X_{\min} = \min(x_1, x_2, x_3, x_4), \quad X_{\max} = \max(x_1, x_2, x_3, x_4)\] \[Y_{\min} = \min(y_1, y_2, y_3, y_4), \quad Y_{\max} = \max(y_1, y_2, y_3, y_4)\]

Intersection and Hit-Testing

When multiple nested, rotated sources intersect on the canvas, OBS resolves intersections at two levels:

  • Hit-Testing (Selection in Preview): To determine which rotated item is clicked, OBS maps the mouse cursor coordinate \((X_{\text{mouse}}, Y_{\text{mouse}})\) from canvas space back into the local space of each source using the inverse matrix (\(M_{\text{final}}^{-1}\)). If the resulting point falls within the source's local \([0, \text{width}]\) and \([0, \text{height}]\) range, a hit is registered. In cases of intersection, the item highest in the scene tree order (top-most layer) takes precedence.
  • Visual Intersection: Visual overlap between intersecting bounding quads is executed on the GPU. Vertices generated from the final accumulated transformation matrix are submitted as triangle strips. The GPU’s rasterizer determines pixel ownership, and standard alpha blending combines overlapping areas from back to front according to the scene's layer hierarchy.
