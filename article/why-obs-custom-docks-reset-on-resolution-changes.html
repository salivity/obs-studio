Why OBS Custom Docks Reset on Resolution Changes

Switching display resolutions or moving OBS Studio between monitors often causes custom browser docks and UI panels to disappear, overlap, or revert to default positions. This issue is primarily caused by the underlying Qt framework OBS relies on for window management, how the operating system handles display scaling (DPI), and built-in safety mechanisms designed to prevent user interface elements from rendering off-screen. Understanding these mechanisms helps clarify why layout states fail to adapt dynamically and how to keep docks stable.

Qt Framework Geometry and Coordinate Mapping

OBS Studio is built using the Qt GUI framework, which utilizes QMainWindow and QDockWidget classes to manage customizable panels. When you dock a window or place a custom browser dock, Qt records its layout state, floating coordinates, and dimensions as specific pixel offsets relative to the primary display's resolution.

When you change your display resolution—for example, dropping from 4K (3840x2160) to 1080p (1920x1080)—the total coordinate grid shrinks. If a custom dock was positioned at an offset beyond the 1920x1080 boundary, Qt no longer recognizes that screen area as valid display space.

Off-Screen Failsafe Triggering

To prevent docks and floating panels from becoming permanently inaccessible outside the visible desktop area, Qt and OBS feature built-in boundary checks. When the operating system broadcasts a display configuration change (such as a resolution drop or monitor disconnection), OBS evaluates whether the saved window coordinates fall within the new desktop boundaries.

If the application determines that a dock’s previous coordinates exist outside the new bounds, it triggers a recovery mechanism. Depending on the dock's configuration, this mechanism will either:

  • Reset the dock to a fallback position inside the main window.
  • Collapse the dock entirely, unchecking it from the Docks menu.
  • Stack multiple docks into a single tabbed group or default column.

High-DPI Scaling and OS Display Changes

The problem is compounded when display resolution changes occur alongside adjustments to Windows or macOS display scaling (DPI). For example, running a laptop at 1080p at 125% scale connected to an external monitor at 1440p at 100% scale creates varying coordinate scaling factors.

When OBS is shifted between these screens, or when the resolution changes during full-screen gaming, the operating system attempts to resize and rescale the application frame. If OBS recalculates widget sizes before the operating system finishes negotiating the new desktop resolution, the docks are forced to compress or reposition within an artificially constrained canvas, breaking the custom layout.

Automatic Saving of Corrupted Layout States

OBS Studio automatically saves the current UI state to its configuration files (basic.ini) upon closing or whenever layout changes occur. If a resolution drop forces custom docks to collapse or reposition, OBS often immediately commits these changes to the active configuration profile. Consequently, returning to the original higher resolution will not restore the previous dock layout, as the safe fallback state has already overwritten the previous coordinates.

Mitigating the Issue

To minimize dock resets when switching resolutions:

  • Lock the UI: Enable Docks > Lock UI to prevent docks from detaching or resizing easily during minor scaling fluctuations.
  • Maintain Consistent DPI: Ensure that multiple monitors share compatible scaling factors (e.g., 100% across all screens) to prevent coordinate recalculation errors.
  • Backup Layout Configurations: Keep a backup of the basic.ini file located in the OBS AppData directory to quickly restore dock placements if a resolution change resets the layout.
