WebRTC Video Feeds in OBS Custom Browser Docks

OBS Studio handles WebRTC video feeds in custom browser docks by utilizing its integrated Chromium Embedded Framework (CEF) to establish real-time, low-latency peer-to-peer or server-mediated connections. Custom browser docks function as persistent web panels embedded directly into the OBS user interface, enabling broadcasters to monitor remote guests with minimal delay. This setup runs on a separate execution layer from the main OBS video canvas, providing an efficient way to interact with off-air or on-air talent without cluttering the broadcast mixer or requiring external browser windows.

The Underlying Engine: Chromium Embedded Framework (CEF)

Custom browser docks in OBS Studio are powered by an embedded instance of Chromium. Because modern WebRTC implementations rely on standard browser APIs, the CEF layer handles all native WebRTC protocols directly:

  • Signaling and Negotiation: The dock executes standard JavaScript signaling mechanisms (such as WebSockets or HTTP APIs) and handles Session Description Protocol (SDP) exchanges.
  • NAT Traversal: It natively manages Interactive Connectivity Establishment (ICE), STUN, and TURN protocols to establish direct peer connections between the guest and host.
  • Media Decoding: Video streams encoded in VP8, VP9, H.264, or AV1, along with Opus audio streams, are decoded directly by the CEF process.

UI Thread vs. Render Pipeline Separation

A critical distinction in how OBS Studio handles browser docks compared to standard "Browser Sources" lies in the rendering pipeline:

  • Isolation from Canvas: Unlike a Browser Source—which renders frames into an off-screen buffer that OBS composits into the final broadcast scene—a custom browser dock exists solely inside a Qt-based dockable UI window.
  • Resource Prioritization: The dock runs as an independent Chromium process. This separation ensures that decoding remote video for monitoring purposes does not directly interfere with OBS Studio’s internal 60 FPS video rendering loop, preventing canvas frame drops if the remote connection fluctuates.
  • Audio Routing: Media playback inside a custom dock is handled through standard OS audio channels rather than the OBS audio mixer. Audio from a dock outputs directly to the system's default monitoring device, preventing accidental broadcast loops unless the user intentionally routes that audio back via a virtual cable or desktop capture.

Performance and Hardware Acceleration

WebRTC decoding can be computationally expensive, particularly with multiple high-definition guest feeds. OBS Studio manages this workload through specific hardware and resource management strategies:

  • GPU Acceleration: When "Enable Browser Source Hardware Acceleration" is checked in OBS settings, the custom browser docks also utilize GPU acceleration for decoding and rendering video elements via Chromium’s graphics pipeline.
  • CPU and Memory Overhead: Each independent custom dock instantiates its own CEF helper process. While this increases overall RAM usage, it isolates failures; a crash in a guest monitoring feed will generally not crash the core OBS broadcasting engine.
  • Resolution Adaptation: Because custom docks are intended for monitoring rather than program output, services feeding these docks (such as VDO.Ninja or custom WebRTC gateways) typically serve lower-resolution, lower-bitrate streams to reduce local decode overhead.

Practical Considerations for Guest Monitoring

To ensure stability when monitoring remote guests via custom browser docks:

  • Authentication and Permissions: WebRTC browser docks in OBS do not have easy access to local media input prompts (such as grant-access pop-ups for webcams and microphones). Consequently, these docks are best utilized as "receive-only" monitors for remote guests rather than two-way communications requiring host camera access within the dock itself.
  • Keep-Alive Behavior: Custom docks remain active even when hidden behind other tabbed docks, continuing to decode video and consume bandwidth. Broadcasters should close unused docks to conserve system resources.
  • Custom Flags: Advanced implementations can configure CEF command-line flags within OBS shortcuts (e.g., enabling specific codecs or disabling autoplay restrictions) to ensure seamless WebRTC auto-reconnects and low-latency playback upon startup.
