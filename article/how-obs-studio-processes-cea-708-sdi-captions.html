How OBS Studio Processes CEA-708 SDI Captions

OBS Studio processes multi-channel SDI ancillary data containing CEA-708 closed captions through a pipeline that bridges hardware capture SDKs, ancillary data demultiplexing, and broadcast streaming protocols. When receiving professional SDI feeds, OBS extracts Vertical Ancillary (VANC) packets via dedicated capture card integrations—such as Blackmagic DeckLink or AJA—demultiplexes the SMPTE 334M data streams, parses the embedded CEA-708 services, and injects the resulting caption data into H.264 or H.265 Supplemental Enhancement Information (SEI) user data units for final distribution.

SDI Ancillary Data Ingestion

SDI video feeds transport data outside the active picture area within the Vertical Blanking Interval (VBI). Closed captions comply with the SMPTE 291M ancillary data standard and the SMPTE 334M mapping standard.

OBS Studio does not read raw SDI signals directly at the hardware layer; instead, it relies on vendor-specific plugins (predominantly obs-decklink using the Blackmagic Desktop Video SDK). During frame capture:

  1. The hardware interface captures both the active video frame and the corresponding VANC lines.
  2. The capture driver isolates ancillary packets flagged with the standard Data Identification (DID) 0x61 and Secondary Data Identification (SDID) 0x01, which signify caption data under SMPTE 334M.
  3. The capture plugin passes these raw VANC packets to OBS Studio's internal caption handling pipeline alongside the decoded audio and video frames.

CEA-708 Demultiplexing and Multi-Channel Handling

CEA-708 is designed to support advanced digital television closed captioning (DTVCC), carrying multiple data streams simultaneously. A single CEA-708 packet sequence can contain:

  • Legacy CEA-608 compatibility data (transferred inside CEA-708 caption service blocks or via line 21 conversion).
  • Up to 63 independent DTVCC logical services (typically Service 1 for primary language, Service 2 for secondary language, and higher services for additional languages or specialized displays).

OBS Studio parses the incoming payload using lightweight parsing libraries like libcaption. The demultiplexer reads the packet header, sequence number, and service blocks:

  • Service Block Identification: Each block header inside the CEA-708 packet indicates the targeted service number and the block size.
  • Stream Routing: When configured for pass-through or re-encoding, OBS tracks the multi-service packets. If downmixing or legacy conversion is active, the engine separates CEA-608 byte-pairs embedded within the CEA-708 stream.
  • Synchronization: Captions are associated with the presentation time stamps (PTS) of the corresponding video frame to ensure that multi-channel text maintains lip-sync and timeline accuracy.

Video Encoding and Output Injection

Once processed, the caption streams must be carried into digital distribution formats like RTMP, SRT, or local recordings (such as MP4 or MKV):

  1. SEI NAL Unit Packaging: Because streaming protocols do not natively pass raw SDI VANC packets, OBS converts the CEA-708 data into MPEG-4/AVC or HEVC Supplemental Enhancement Information (SEI) messages.
  2. ITU-T T.35 Formatting: The captions are encoded as user data registered according to ITU-T T.35 format specifications (country code 0xB5, provider code 0x0031 for ATSC A/53). Both CEA-608 data (for broad player compatibility) and CEA-708 multi-service structures are encapsulated in this structure.
  3. Muxing: The video encoder (such as x264 or hardware encoders like NVENC) appends the SEI NAL units directly to the keyframes (IDR) and predictive frames (P/B-frames) of the active video stream, allowing downstream media players and decoders to display user-selected multi-language captions.
