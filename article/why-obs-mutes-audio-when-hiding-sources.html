Why OBS Mutes Audio When Hiding Sources

In OBS Studio, toggling the visibility of a source by clicking the eye icon often cuts off its accompanying audio feed because the software treats visibility as an operational state rather than a purely visual layer. By default, OBS connects audio processing to the active rendering of video frames to optimize system performance. Understanding this relationship between resource-saving settings, source properties, and audio monitoring paths clarifies why hidden sources go silent and how you can maintain continuous audio playback.

Resource Management and Source Deactivation

OBS Studio is designed to minimize CPU and GPU overhead during live broadcasts and recordings. To achieve this, several media and capture sources include performance flags that stop processing entirely when the source is not actively rendered on the canvas:

  • Deactivate When Not Showing: Common to Video Capture Devices (webcams and capture cards), this setting instructs OBS to disconnect or sleep the hardware interface the moment the visual layer is hidden. Because the hardware connection pauses, any embedded audio stream transmitted through that connection cuts out instantly.
  • Close File When Inactive: Found in Media Sources (video and audio files), this forces OBS to unload the media file from memory when the eye icon is toggled off. The playback halts, and audio output ceases.
  • Restart Playback When Source Becomes Active: Paired with file closing, this setting ensures media only starts over once made visible, confirming that playback is strictly bound to visual presentation.

When these optimization flags are enabled, OBS terminates the processing pipeline for the source, cutting both visual rendering and audio generation simultaneously.

The Separation of Render and Audio Pipelines

OBS Studio handles scene rendering through a visual hierarchy. If a source resides inside a scene and is hidden, the engine skips that source during the video composition phase. For sources that bundle video and audio together (such as Browser Sources, Capture Cards, and Media Sources), the audio stream frequently relies on the master tick of the video decoder.

If the video frame loop stops because the source is hidden, the audio clock pauses alongside it. The audio engine does not independently poll the hidden source unless the source remains active in the background.

The Role of Audio Monitoring Configurations

OBS Studio features an Advanced Audio Properties panel where tracks can be set to Monitor Off, Monitor Only (mute output), or Monitor and Output.

When audio monitoring is active (either "Monitor Only" or "Monitor and Output"), OBS routes the feed through an independent monitoring device defined in your global audio settings. In certain configurations, assigning a source to actively monitor forces OBS to keep an active audio decoding thread alive, even if the primary scene renderer drops the video feed. However, if the underlying source property still tells the hardware or file to "deactivate," the audio will cut out regardless of monitoring settings because the source has completely stopped delivering data.

How to Maintain Audio While Hiding Visuals

To keep the audio feed playing while concealing the video layer:

  1. Uncheck Deactivation Settings: Open the properties of your source (e.g., Video Capture Device or Media Source) and disable options like Deactivate when not showing or Close file when inactive. This forces OBS to render the audio track continuously in the background.
  2. Decouple Audio from Video: Instead of relying on the embedded audio from a capture card or browser source, add a dedicated Audio Input Capture source pointing directly to the hardware. Because Audio Input Capture sources have no visual component to toggle, their feeds remain constant across all scene changes.
  3. Use Source Filters Instead of Visibility Toggles: Apply a Color Correction filter with opacity set to 0%, or use a dedicated scene transition, to visually hide an element without triggering the engine-level deactivation caused by the eye icon toggle.
