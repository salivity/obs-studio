Causes of DAW Audio Latency in OBS Studio

Routing live program audio through a digital audio workstation (DAW) into OBS Studio allows for professional-grade processing, but it frequently introduces latency that can progressively worsen over time. This latency buildup—often experienced as audio drifting out of sync with video or significant monitoring delays—is primarily caused by audio buffer discrepancies, clock-rate mismatches, internal plugin delay compensation, virtual driver bottlenecks, and CPU scheduling limits. Understanding these root causes enables stream engineers and creators to pinpoint desync issues and maintain real-time monitoring stability.

Plugin Delay Compensation (PDC) and Lookahead Processing

Complex DAWs utilize Plugin Delay Compensation (PDC) to ensure all audio tracks align before reaching the master output. When a mix includes latency-heavy plugins—such as linear-phase equalizers, multiband compressors, pitch correction, or limiters with lookahead features—the DAW must delay every other channel to match the slowest track. In a live environment, this inherent lookahead requirement adds non-negotiable delay at the DAW’s output stage. If dynamic processing parameters change during a session, dynamic PDC adjustments can cause perceived latency jumps.

Sample Rate Mismatches and Clock Drift

One of the primary causes of latency that grows over time (drift) is asynchronous audio clocks resulting from sample rate mismatches. If your DAW operates at 44.1 kHz while your operating system, virtual audio device, or OBS Studio is set to 48 kHz, the system must resample the audio on the fly. Because software clocks between non-hardware-linked virtual devices are rarely identical, slight timing errors accumulate. Over long streaming sessions, these micro-discrepancies force audio buffers to stretch or fill up, manifesting as an ever-increasing delay.

Virtual Audio Cable and Driver Bridging Overhead

Passing audio from an ASIO-based DAW into OBS generally requires a virtual bridge, such as VB-Audio Cable, ReaRoute, Voicemeeter, or NDI. These bridges introduce an intermediate processing layer with its own input and output buffers. If the virtual cable's internal buffer does not strictly synchronize with the DAW's ASIO buffer size, packets queue up rather than processing instantaneously. Over time, an overfilled buffer reservoir creates an expanding latency gap between the monitored DAW signal and the OBS ingest feed.

Inefficient Audio Driver Buffer Sizes

The hardware buffer size configured in your audio interface's ASIO control panel determines how many samples are processed in a single cycle. While a larger buffer size (e.g., 512 or 1024 samples) prevents audio dropouts and crackling under heavy CPU load, it adds base round-trip latency. When paired with secondary buffering inside OBS Studio, this base latency compounds, making instantaneous monitoring impractical.

CPU Throttling and Thread Scheduling

Complex DAW sessions running multiple synthesizers, convolution reverbs, and mastering chains demand substantial multi-threaded CPU performance. If OBS and your DAW compete for the same CPU cores or if system power-management profiles dynamically throttle CPU clock speeds, the DAW may fail to empty its audio buffer in real time. Instead of dropping out entirely, some audio drivers and virtual routing software hold onto buffered data, progressively slipping further behind the live real-time capture point.

How to Mitigate Latency Buildup

  • Standardize Sample Rates: Ensure the DAW, operating system audio properties, virtual cables, and OBS Studio are universally locked to 48 kHz.
  • Eliminate Lookahead Plugins: Replace mastering-grade, high-latency plugins on the live broadcast chain with zero-latency, live-tracking alternatives.
  • Optimize Buffer Sizes: Keep ASIO buffer sizes at 128 or 256 samples, adjusting upward only if CPU performance issues cause audible glitches.
  • Use Direct Plugins Instead of Bridges: Where possible, utilize direct ASIO capture plugins within OBS (such as obs-asio) or VST processing directly on OBS audio filters to minimize virtual routing layers.
