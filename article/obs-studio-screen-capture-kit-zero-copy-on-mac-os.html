OBS Studio ScreenCaptureKit Zero-Copy on macOS

This article explains how OBS Studio leverages Apple’s ScreenCaptureKit framework on macOS Sonoma to deliver high-performance screen and window capture. By utilizing an end-to-end GPU workflow, OBS Studio eliminates unnecessary CPU memory transfers through a zero-copy pipeline. This modern architecture bypasses legacy capture bottlenecks, significantly lowering CPU and power consumption while maximizing capture frame rates on Apple silicon and modern Intel Macs.

The Shift from Legacy APIs to ScreenCaptureKit

Prior to the introduction of ScreenCaptureKit, macOS screen capture in broadcasting software relied on deprecated APIs such as CGDisplayStream and CGWindowListCreateImage. These older interfaces required the operating system's window server to capture a frame, write it into system memory, and force OBS to read it back into the CPU before transferring it to the GPU for rendering. This constant copying across memory spaces generated high CPU utilization, increased system temperatures, and caused frequent frame drops during high-resolution or high-refresh-rate streaming.

The Zero-Copy Mechanism via IOSurface

OBS Studio implements ScreenCaptureKit by taking direct advantage of Apple's unified memory architecture and the IOSurface framework.

When OBS initiates a capture session using SCStream, the ScreenCaptureKit daemon captures display output or application windows directly on the GPU. Instead of passing raw pixel arrays to the client application, ScreenCaptureKit wraps each captured frame inside a CMSampleBuffer. Within this buffer lies a CVPixelBuffer that is backed directly by an IOSurface.

An IOSurface is an operating-system-level handle to shared hardware memory. Because macOS allows an IOSurface to be accessed across process boundaries without duplicating the underlying buffer, OBS Studio can access the frame data instantaneously. No memory is duplicated between the macOS WindowServer and the OBS rendering process, fulfilling the technical definition of a zero-copy pipeline.

Integration with the OBS Metal Render Pipeline

Once the capture plugin in OBS receives the CMSampleBuffer, the integration process proceeds entirely on the graphics hardware:

  1. Surface Extraction: The OBS capture module extracts the IOSurfaceRef from the incoming CVPixelBuffer via Core Video.
  2. Texture Binding: OBS utilizes the Apple Metal graphics backend to bind the extracted IOSurface directly into a Metal texture (id<MTLTexture>).
  3. Scene Compositing: The Metal texture is passed into the core OBS rendering engine as a source texture. The compositor uses this texture directly when rendering the output canvas.

Because the data never moves out of VRAM—or unified system memory in Apple silicon architectures—the CPU is entirely relieved from handling raw frame pixels.

macOS Sonoma Advancements

macOS Sonoma introduced low-level refinements to ScreenCaptureKit that OBS Studio utilizes to further stabilize capture:

  • Lower Ingestion Latency: Sonoma reduces internal queuing delays within the SCStream rendering pipeline, ensuring that captured frames align closely with real-time screen updates.
  • Per-App and Multi-Window Synchronization: Independent window streams maintain smooth frame pacing without requiring capture of the entire desktop context.
  • HDR and Wide Color Gamut (P3): Frames encoded in 10-bit and P3 color spaces are mapped directly into compatible rendering formats without manual pixel conversions.
  • Integrated Audio Capture: System and application audio streams arrive synchronized with corresponding video frames within the same session callback, avoiding drift.

By routing frames through shared IOSurface references directly to Metal textures, OBS Studio achieves near-zero CPU capture overhead on macOS Sonoma, offering an efficient solution for high-framerate streaming and recording.
