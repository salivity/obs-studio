OBS Studio Timecode Burn-In for Legal Verification

OBS Studio handles timecode burn-in overlays by permanently rendering frame-accurate temporal data directly onto the recorded video frames using internal text engines, scripting modules, or dedicated capture hardware. In legal and broadcast verification environments, these burned-in timecodes (BITC) establish an immutable, frame-by-frame visual record of events, ensuring synchronization across disparate media, preventing tampering, and fulfilling strict chain-of-custody and regulatory compliance requirements.

Why Burn-In Overlays Are Required for Legal Verification

Standard digital video containers store timecode as metadata, which can be stripped, rewritten, or lost during transcoding and file transfer. For legal recording—such as regulatory broadcast logging, depositions, or incident documentation—metadata alone is often insufficient in court or compliance audits.

A burned-in timecode becomes part of the raster image itself. Altering a frame with a burned-in visual timecode disrupts the image continuity, making video manipulation immediately detectable. It also guarantees that playback software on any standard monitor displays the exact same time markers without requiring specialized metadata readers.

Native Methods: Text Sources and Scripting

OBS Studio does not include a hardware SMPTE LTC decoder out of the box, but it provides flexible internal mechanisms to generate real-time visual timestamps:

  • Text (GDI+ / FreeType 2) Sources: OBS allows operators to display system time, stream duration, or elapsed recording time.
  • Lua and Python Scripts: Using the built-in script engine (Tools > Scripts), operators can load scripts (such as countdown.lua or custom timecode generators) that query system time down to the millisecond or frame number. These scripts update a Text Source continuously, rendering an HH:MM:SS:FF (Hours:Minutes:Seconds:Frames) overlay over the target feed.

While native scripting is effective for general logging, standard system time scripts can suffer from millisecond drift or frame jitter under high CPU loads, which must be accounted for during legal setup.

Specialized Plugins and External Ingest

For broadcast-grade compliance where SMPTE 12M or Linear Timecode (LTC) standards are legally mandated, production teams rely on advanced workflows:

  1. Third-Party Timecode Plugins: Dedicated OBS plugins interface directly with audio inputs carrying LTC audio chirps or IP-based timing protocols (such as NDI metadata or PTP/IEEE 1588). The plugin decodes the signal and updates a dedicated visual overlay in real time with zero frame drift.
  2. Hardware Capture Pre-Processing: High-reliability workflows bypass software generation entirely by burning the timecode into the SDI/HDMI signal prior to entering OBS. Broadcast capture cards (such as Blackmagic DeckLink or AJA Corvid) or hardware timecode generators insert the overlay upstream, ensuring OBS receives and records an already verified, locked image.

Ensuring Frame Accuracy and Legal Integrity

To maintain legal defensibility, an OBS timecode burn-in workflow must meet several technical benchmarks:

  • Authoritative Clock Synchronization: The host machine running OBS must be synchronized to a stratum-1 NTP (Network Time Protocol) server or a local GPS time server. This ensures the timestamp matches universal atomic time standards.
  • Locked Canvas Framerate: The canvas frame rate in OBS (Settings > Video) must match the input signal's framerate exactly (e.g., 29.97, 25.0, or 59.94 fps). Framerate mismatches introduce dropped or duplicated frames, invalidating the frame-counter segment of the burn-in.
  • Canvas Placement: Overlays should be applied at the Scene Collection level or within a global parent scene. Placing the overlay as the topmost layer across all production scenes prevents operators from accidentally obscuring the verification feed during scene transitions.
  • Container Resilience: Recordings intended for legal archives should use containers like Matroska (.mkv) to prevent file corruption in the event of unexpected system shutdowns or power loss.
