Configure ISO Recording Bitrates in OBS Studio

While OBS Studio defaults to a unified recording output for the master scene, content creators and production teams frequently require isolated (ISO) camera recordings configured at distinct bitrates to balance storage limits, post-production fidelity, and hardware capabilities. By integrating specialized plugins—primarily the Source Record plugin—OBS can tap into multi-instance encoding pipelines. This architecture allows each video input to bypass global output limitations, assigning independent software or hardware encoders, rate controls, and bitrates directly to individual capture devices.

The Underlying Limitation of Native OBS

By design, OBS Studio routes all active scene elements through a single canvas that is compressed via the encoder parameters defined in Settings > Output. While this is sufficient for a master program feed, it does not support native multi-track video capture at different compression levels. Achieving independent ISO recordings requires intermediate capture filters running on the source level before rendering into the master composition.

Utilizing the Source Record Plugin

The industry standard solution for ISO capture in OBS Studio is the Source Record plugin. Instead of relying exclusively on the global recording bus, Source Record operates as an audio/video filter placed directly onto specific sources, such as capture cards, webcams, or media sources.

Each instance of the filter possesses its own encoder instance, allowing you to establish custom bitrates and encoding types independent of what OBS records in the primary output.

Step-by-Step Configuration Process

1. Apply the Filter to the Target Source

  1. In the Sources dock, right-click the video capture device designated for ISO recording.
  2. Select Filters.
  3. Under the Audio/Video Filters column on the left, click the + (Add) icon and select Source Record.
  4. Name the filter descriptively (e.g., ISO Rec - Cam 1 - 15Mbps).

2. Configure Recording Triggers

  • Record Mode: Choose when the individual feed records. Options include:
    • None: Manual trigger via hotkeys.
    • Recording: Starts and stops automatically when OBS master recording toggles.
    • Streaming: Records whenever the live stream begins.
    • Always: Continuously records as long as OBS is open.

3. Establish Independent Bitrates and Encoders

By default, the plugin mirrors the system configuration. To assign independent bitrates:

  1. Locate the Encoder dropdown in the filter properties.
  2. Switch the setting away from standard presets to a dedicated hardware or software encoder (e.g., NVIDIA NVENC H.264, Apple VT H.264 Hardware, or x264).
  3. Set the Rate Control method (e.g., CBR for constant bitrate or CQP/VBR for quality-based variable encoding).
  4. Set the exact target in the Bitrate field:
    • Primary Camera (High Fidelity): 15,000–25,000 Kbps for pristine master files.
    • Secondary Camera / Overhead (Standard): 6,000–8,000 Kbps to conserve disk space.
  5. Define the Keyframe Interval (typically set to 2s or 0 for auto).

4. Specify File Paths and Unique Naming

Because multiple files will write concurrently:

  1. In the filter properties, define a specific Path.
  2. Use dynamic naming formats (e.g., %CCYY-%MM-%DD %hh-%mm-%ss_Cam1) in the Filename Formatting field. Ensure each camera filter uses a distinct naming suffix to prevent write conflicts or file corruption.

Hardware and Resource Management

Running parallel encoding engines with independent bitrates imposes heavy demands on system hardware. Keep the following technical constraints in mind:

  • Hardware Encoder Limits: Consumer-grade graphics cards (such as NVIDIA GeForce GPUs) have a driver-enforced limit on concurrent NVENC encoding sessions (typically 3 to 5 simultaneous sessions depending on current driver updates). Exceeding this limit will trigger encoder initialization errors.
  • Mixed-Encoder Strategies: To maximize efficiency without exceeding hardware limits, assign your primary camera to a dedicated hardware encoder (NVENC/QuickSync/AMF) at a high bitrate, while secondary ISO feeds can be distributed to secondary GPUs or processed via CPU using x264 with a fast preset (veryfast or superfast).
  • Disk I/O Bottlenecks: Writing multiple high-bitrate video streams simultaneously requires high-speed storage. Record ISO feeds directly to an NVMe SSD or high-throughput external drive array to prevent dropped frames caused by disk write queues.
