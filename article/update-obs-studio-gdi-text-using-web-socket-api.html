Update OBS Studio GDI+ Text Using WebSocket API

This article explains how external applications can programmatically update the text content of a GDI+ text source in OBS Studio using the modern obs-websocket protocol (version 5.x). By establishing a standard WebSocket connection, authenticating, and dispatching a SetInputSettings request payload, developers can automate overlays, live alerts, and real-time data streams inside their broadcasts.

Prerequisites

OBS Studio version 28 and above comes with obs-websocket pre-installed. Before sending commands:

  1. Open OBS Studio.
  2. Navigate to Tools > WebSocket Server Settings.
  3. Check Enable WebSocket server.
  4. Note the Server Port (default is 4455) and the Server Password if authentication is enabled.
  5. Create a Text (GDI+) source in your scene (e.g., named "ScoreboardText").

Protocol Authentication

When connecting to ws://127.0.0.1:4455, the OBS WebSocket server immediately sends an op: 0 (Hello) message containing server details, authentication challenges, and salt if password protection is enabled.

Your application must respond with an op: 1 (Identify) message. If authentication is enabled, compute the SHA256 response string using the secret, salt, and password as specified by the obs-websocket v5 protocol before proceeding.

The SetInputSettings Request

Once identified (op: 2), the application can update the text by sending an op: 6 (Request) payload targeting the SetInputSettings command.

The internal property for the content of a GDI+ text source (text_gdiplus_v2) is "text". Setting "overlay": true ensures that only the text property is modified without resetting other attributes such as font, size, alignment, or color.

JSON Payload Structure

{
  "op": 6,
  "d": {
    "requestType": "SetInputSettings",
    "requestId": "update-text-001",
    "requestData": {
      "inputName": "ScoreboardText",
      "inputSettings": {
        "text": "Updated Text Content via API"
      },
      "overlay": true
    }
  }
}

Implementation Example (Node.js)

Using a standard WebSocket client library (such as ws) or an official OBS wrapper, the process can be implemented directly:

import WebSocket from 'ws';

const ws = new WebSocket('ws://127.0.0.1:4455');

ws.on('open', () => {
  // If no password is set, send a minimal Identify payload
  ws.send(JSON.stringify({
    op: 1,
    d: {
      rpcVersion: 1
    }
  }));
});

ws.on('message', (data) => {
  const message = JSON.parse(data);

  // Once identified (op: 2), send the text update
  if (message.op === 2) {
    updateText("ScoreboardText", "Hello World!");
  }
});

function updateText(sourceName, newText) {
  const payload = {
    op: 6,
    d: {
      requestType: "SetInputSettings",
      requestId: "text-update-" + Date.now(),
      requestData: {
        inputName: sourceName,
        inputSettings: {
          text: newText
        },
        overlay: true
      }
    }
  };
  
  ws.send(JSON.stringify(payload));
}

Verification and Response

Upon receiving the request, OBS updates the GDI+ rendering engine immediately. The WebSocket server sends an op: 7 (RequestResponse) message indicating success:

{
  "op": 7,
  "d": {
    "requestType": "SetInputSettings",
    "requestId": "update-text-001",
    "requestStatus": {
      "result": true,
      "code": 100
    }
  }
}

If the source name does not exist or matches a non-input source, the server returns a non-100 error code with a descriptive reason.
