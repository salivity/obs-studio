Causes of OBS Color Banding on LED Video Walls

Color banding, or posterization, occurs when smooth gradients are displayed as distinct, stepped blocks of color. When outputting an OBS Studio program feed to large-scale LED video walls over HDMI, this visual artifact is typically caused by bit-depth limitations, dynamic range mismatches, aggressive chroma subsampling, and improper signal conversion between the rendering engine, the GPU, and the LED video processor.

Bit-Depth Bottlenecks (8-bit vs. High Bit-Depth Processing)

OBS Studio primarily renders and outputs video in an 8-bit color pipeline (typically using the NV12 or sRGB/Rec.709 format). While an 8-bit signal provides 256 shades per color channel—sufficient for standard computer monitors—large-scale LED video walls amplify each step in the gradient across thousands of high-brightness diodes. LED processors frequently utilize 10-bit, 12-bit, or higher internal processing to maintain smooth grayscale calibration. When an 8-bit OBS feed is stretched across this high-gamut, high-contrast canvas, the intermediate shades do not exist in the source data, making quantization steps visibly apparent.

Dynamic Range Mismatches (Full vs. Limited RGB)

A frequent culprit in HDMI pipelines is a mismatch between Full (0–255) and Limited (16–235) quantization ranges.

  • If OBS Studio is set to Full range while the GPU's HDMI output or the LED processor expects Limited, the values are crushed or clipped.
  • Conversely, if OBS outputs Limited range and the processor stretches it to Full, missing values are interpolated unevenly across the spectrum.

This mismatch directly leads to crushed shadow detail and visible banding across mid-tones and dark gradients.

Chroma Subsampling

To save system resources and transmission bandwidth, both video software and display interfaces often drop color resolution via chroma subsampling. If OBS is configured to use color formats like NV12 or I420, it discards 75% of the color data (chroma subsampling at 4:2:0). Furthermore, if the graphics card auto-negotiates the HDMI output to YUV 4:2:0 or 4:2:2 due to cable bandwidth constraints, horizontal and vertical color resolution drops drastically. When projected onto large LED modules, the lack of color resolution creates hard boundaries in place of smooth transitions.

Incompatible Color Spaces and Rounding Errors

Every conversion within the video pipeline introduces mathematical rounding errors:

  1. Media or capture card into OBS (e.g., Rec. 709 or sRGB).
  2. OBS internal compositing.
  3. GPU video output driver (RGB vs. YCbCr).
  4. LED sending card/processor input.
  5. Receiving card output to LED driver ICs (often mapped to custom LED native gamuts).

Cascading conversions back and forth between RGB and YCbCr color spaces cause data loss, amplifying gradient separation.

LED Processor Dimming and Grayscale Loss

Large-scale LED walls intended for indoor use are rarely run at 100% brightness. If an operator reduces overall screen brightness via software controls rather than hardware-level pulse-width modulation (PWM) control, the processor artificially compresses the grayscale range. Operating an 8-bit OBS input on an LED wall dialed down to low brightness reduces the effective bit depth even further, often down to 5 or 6 bits of actual depth, severely exaggerating color banding across all content.
