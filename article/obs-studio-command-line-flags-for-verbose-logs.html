OBS Studio Command-Line Flags for Verbose Logs

Troubleshooting elusive crashes, hardware encoder failures, and plugin conflicts in OBS Studio often requires deeper diagnostic data than standard logs provide. By launching OBS Studio with specific command-line flags, you can force the application to log internal operations at a granular level. This guide explains the specific command-line arguments needed to enable verbose logging and details how to execute them across Windows, macOS, and Linux.

Key Command-Line Flags for Debugging

OBS Studio accepts several flags via the terminal or command line that alter its logging behavior:

  • --verbose: Forces OBS Studio to log internal trace and debug messages that are normally suppressed. This includes granular module loading details, graphics API initializations, and hook routines.
  • --unfiltered_log: Disables log filtering, preventing OBS from collapsing repeated lines or omitting rapid stream-state output.

Combining both flags (--verbose --unfiltered_log) yields the most comprehensive diagnostic output available without compiling OBS Studio from source in debug mode.

Launching OBS with Verbose Logging

Windows

You can run the flags either directly via Command Prompt/PowerShell or by modifying a shortcut.

Method 1: Command Prompt or PowerShell

  1. Close any running instances of OBS Studio.
  2. Open Command Prompt or PowerShell.
  3. Navigate to the 64-bit OBS binary directory: 
    cd "C:\Program Files\obs-studio\bin\64bit"
  4. Execute OBS with the verbose flags: 
    obs64.exe --verbose --unfiltered_log

Method 2: Desktop Shortcut

  1. Right-click your OBS Studio desktop shortcut and select Properties.
  2. Go to the Shortcut tab.
  3. Locate the Target field. It typically looks like: "C:\Program Files\obs-studio\bin\64bit\obs64.exe"
  4. Add a space after the closing quotation mark, then append: --verbose --unfiltered_log
  5. Click Apply and OK. Launching OBS via this shortcut will now automatically run with verbose logging.

macOS

On macOS, command-line arguments must be passed to the underlying executable inside the application bundle via Terminal.

  1. Quit OBS Studio completely.
  2. Open Terminal.
  3. Run the executable with the flags: 
    /Applications/OBS.app/Contents/MacOS/OBS --verbose --unfiltered_log

Terminal will display the output in real time while also writing it to the standard log directory.

Linux

On Linux, launch OBS directly from your preferred terminal emulator.

Native Package (APT, RPM, Arch, etc.):

obs --verbose --unfiltered_log

Flatpak:

flatpak run com.obsproject.Studio --verbose --unfiltered_log

Accessing and Inspecting the Logs

Once OBS is launched with verbose flags, the additional output is written directly to standard log files as well as to your active terminal window.

  1. Reproduce the bug, crash, or unexpected behavior in OBS Studio.
  2. If OBS remains open, navigate to the top menu bar:
    • Click Help > Log Files > Show Log Files.
  3. Open the latest .txt log file in a text editor.
  4. Search for entries labeled [debug] or look for explicit module load failures, memory allocation warnings, or frame delivery drops that were previously hidden in standard logs.
