OBS Studio NDI Tally Light Signaling Explained

OBS Studio uses Network Device Interface (NDI) integration to automate tally light signaling, alerting on-screen talent and camera operators when a video feed is live or in preview. By transmitting real-time metadata back across the local network to connected NDI-enabled devices, OBS Studio triggers hardware tally lights—typically turning them red for Program (live) or green for Preview (on-deck). This article breaks down how OBS Studio generates these signals, the network mechanics involved, and the key configurations required to maintain an accurate tally system.

The Role of the OBS-NDI Plugin

OBS Studio does not support NDI natively; it relies on third-party plugins, most notably obs-ndi, which integrates the official NDI Software Development Kit (SDK). When you add an NDI source (such as a PTZ camera, a mobile device running an NDI camera app, or a hardware converter) to an OBS scene, the plugin opens a two-way communication channel across your local area network (LAN).

Bidirectional Metadata Communication

While video and audio stream downstream from the camera to OBS Studio, NDI is inherently bidirectional. The NDI SDK continuously sends lightweight metadata packets upstream from OBS Studio back to the transmitting device.

Tally information is packaged within this metadata stream as simple state flags:

  • Program State (Live): When a source is visible in the active Program output, OBS sends a metadata flag instructing the device's tally system to illuminate red.
  • Preview State (Standby): When a source is loaded into Preview (via Studio Mode) but is not yet live, the metadata instructs the device to illuminate green.
  • Inactive State: If a source is neither in Program nor Preview, the tally metadata tells the device to turn the indicator off.

Because NDI operates over standard IP networks using TCP and UDP, these state changes transmit with negligible latency, ensuring the tally indicator updates simultaneously with scene transitions in OBS.

The Importance of Studio Mode

For tally signaling to function with both Preview and Program indicators, OBS Studio must be operating in Studio Mode.

In standard mode, OBS Studio only features a single output monitor. In this state, any active scene is automatically live, meaning tally lights will only ever toggle between off and red (Program). Enabling Studio Mode creates a dual-canvas workflow, allowing the obs-ndi plugin to differentiate between a camera waiting in queue (green tally) and a camera actively broadcasting to viewers or recordings (red tally).

Network and Device Requirements

For OBS tally signals to successfully reach talent-facing devices:

  • Bidirectional Network Traffic: Firewalls on the OBS host machine must allow both incoming video streams and outgoing tally metadata packets across standard NDI ports (typically beginning at port 5960).
  • Hardware Support: The physical camera or NDI converter must have built-in tally LEDs or tally output ports configured to interpret standard NDI tally commands.
  • Scene Visibility: OBS Studio triggers tally based on visibility. If an NDI source is inside an active scene but hidden via the eye icon in the Sources list, OBS reports the source as inactive, keeping the tally light off.
