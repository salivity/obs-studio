Monitor OBS Dropped Frames via WebSocket for Alerts

Streaming stability is critical for live broadcasters, and network or hardware bottlenecks often result in dropped frames that degrade broadcast quality. This article explains how an external automation tool can connect to OBS Studio's native WebSocket server, monitor real-time stream statistics, calculate dropped frame percentages, and trigger automated visual or audible alerts back inside OBS Studio when streaming thresholds are breached.

Enabling the OBS WebSocket Server

Modern versions of OBS Studio (version 28 and newer) include an integrated WebSocket server based on the obs-websocket v5 protocol.

  1. Open OBS Studio.
  2. Navigate to Tools > WebSocket Server Settings.
  3. Check Enable WebSocket server.
  4. Set a port (default is 4455) and configure an authentication password.

Connecting the External Automation Tool

Your automation tool—whether built with Python, Node.js, Node-RED, or platforms like Streamer.bot—must establish a standard WebSocket connection to ws://localhost:4455 (or your OBS machine's local IP address).

Upon opening the socket, the client must perform the OBS WebSocket v5 handshake:

  1. Receive the Hello message from OBS (OpCode 0).
  2. Send an Identify message (OpCode 1), containing the RPC version (1), required event subscriptions, and an authentication string (a SHA256 challenge generated with your password and the salt provided in the Hello payload).
  3. Receive the Identified message (OpCode 2) confirming a valid session.

Querying Stream Statistics

While OBS issues events for state changes, granular stream output metrics are typically retrieved by polling the GetStreamStatus request at regular intervals (such as every 2 to 5 seconds).

Send a Request message (OpCode 6):

{
  "op": 6,
  "d": {
    "requestType": "GetStreamStatus",
    "requestId": "check-frames-task"
  }
}

OBS Studio responds with a payload containing current broadcast performance metrics:

  • outputActive: Boolean indicating if the stream is live.
  • outputSkippedFrames: Number of frames dropped due to rendering/encoding lag.
  • outputTotalFrames: Total frames processed by the stream encoder.
  • outputCongestion: Network congestion estimate (0.0 to 1.0).

Note: For network-dropped frames specifically, you can also query GetOutputStatus with outputName: "simple_stream" or "adv_stream" depending on your output configuration to inspect network drop numbers.

Calculating the Dropped Frame Percentage

Once your automation script receives the response, calculate the drop rate:

\[\text{Drop Percentage} = \left( \frac{\text{outputSkippedFrames}}{\text{outputTotalFrames}} \right) \times 100\]

To measure real-time spikes rather than lifetime averages, store the values from the previous poll cycle and calculate the delta:

\[\Delta \text{Skipped} = \text{Skipped}_{\text{current}} - \text{Skipped}_{\text{previous}}\] \[\Delta \text{Total} = \text{Total}_{\text{current}} - \text{Total}_{\text{previous}}\] \[\text{Current Drop Rate} = \left( \frac{\Delta \text{Skipped}}{\Delta \text{Total}} \right) \times 100\]

Triggering Stream Alerts in OBS

When the drop rate exceeds a predetermined threshold (e.g., 5% over a 10-second period), your tool sends an action request back through the same WebSocket connection to alert you. Common integration methods include:

1. Displaying an On-Screen Indicator

Create a hidden warning graphic, text box, or browser source in OBS Studio, and make it visible using SetSceneItemEnabled:

{
  "op": 6,
  "d": {
    "requestType": "SetSceneItemEnabled",
    "requestId": "show-warning",
    "requestData": {
      "sceneName": "Live Scene",
      "sceneItemId": 12,
      "sceneItemEnabled": true
    }
  }
}

2. Playing an Audio Chime

Route a private audio alert to your monitoring headphones by creating a dedicated media source set to "Monitor Only" and triggering it via TriggerMediaInputAction:

{
  "op": 6,
  "d": {
    "requestType": "TriggerMediaInputAction",
    "requestId": "play-audio-chime",
    "requestData": {
      "inputName": "FrameDropWarningAudio",
      "mediaAction": "OBS_WEBSOCKET_MEDIA_INPUT_ACTION_RESTART"
    }
  }
}

Resetting the Alert State

To prevent notification loops, your automation tool should incorporate hysteresis or cooldown logic. Once the delta dropped frame rate falls back below an acceptable threshold (e.g., under 1%) for a sustained period, dispatch a follow-up request to set sceneItemEnabled: false, clearing the alert until the next instability event.
