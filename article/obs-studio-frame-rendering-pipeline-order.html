OBS Studio Frame Rendering Pipeline Order

During a single frame cycle, OBS Studio executes source rendering, transformations, filter processing, and transitions in a strict sequential order to compose the final visual output. This article details the exact step-by-step pipeline OBS Studio traverses—from initial source polling to transition evaluation and final canvas output—to process transformations, filter stacks, and scene transitions within a single frame tick.

1. Frame Tick and Source Updating

Before any visual rendering occurs on the graphics thread, OBS Studio runs a tick phase (obs_source_video_tick). During this phase, every active source calculates its internal timing, advances animation frames, polls capture cards, or synchronizes video packets with the global audio clock.

2. Source Filter Execution (Source-Level)

Each source that requires rendering draws its base content to a dedicated render target. OBS Studio immediately processes the source's attached filter stack:

  1. Pre-Processing (Async/Audio): Audio filters and asynchronous video buffers are aligned.
  2. Effect/Render Filters: Filters in the source's filter list are evaluated sequentially from top to bottom. Each filter takes the output of the preceding filter (or the raw source for the first filter) and renders it to a temporary texture using its designated shader (e.g., Color Correction, Chroma Key, Sharpen).

The output of this stage is a fully filtered, flat source texture at the source's native or filter-modified resolution.

3. Source Transformations (Scene Item Processing)

Once the source filter stack completes, OBS Studio processes the scene item within the context of the containing scene. The transform properties defined on the scene item are calculated and applied using a matrix multiplication:

  1. Cropping: Crop margins (left, right, top, bottom) are applied to the filtered source texture.
  2. Scaling: The cropped texture is scaled using the chosen scaling filter (Point, Bilinear, Bicubic, or Lanczos).
  3. Rotation and Positioning: Rotation angles, alignment origins, and position coordinates map the item into the scene's coordinate space.
  4. Blending: The transformed texture is drawn to the scene's internal render target according to the item's blend mode (e.g., Normal, Additive, Multiply).

4. Scene-Level Filter Execution

Because scenes in OBS Studio are technically sources themselves, an entire scene can hold its own filter stack.

Once all individual scene items inside the scene are transformed and composited onto the scene canvas, OBS Studio passes that composite scene texture through the scene's own filter stack from top to bottom. Any color grading, blurs, or masks assigned at the scene or group level are applied at this stage.

5. Scene Transition Evaluation

If a scene transition (such as a Fade, Stinger, Move, or Swipe) is active:

  1. OBS Studio maintains the render outputs of both the outgoing scene ("A") and the incoming scene ("B").
  2. The transition system calculates the current progress percentage based on frame timing.
  3. The transition effect shader executes, sampling both scene textures simultaneously and blending, wiping, or masking between them based on the active transition parameters.

If no transition is active, the active scene's final texture bypasses this step entirely.

6. Final Canvas Rendering and Output

The post-transition composite is rendered to the main canvas texture. From here, OBS Studio splits the result to its final destinations: the user interface preview window, any active projector windows, and the encoding pipeline for recording and streaming.
