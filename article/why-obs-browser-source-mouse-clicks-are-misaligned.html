Why OBS Browser Source Mouse Clicks Are Misaligned

When using OBS Studio to interact with browser sources, users frequently encounter an issue where mouse clicks register several pixels—or even entirely different quadrants—away from the visual cursor. This article explains the technical causes of mouse click coordinate misalignment on scaled browser sources, focusing on coordinate translation failures between the Chromium Embedded Framework (CEF), OBS scene transforms, display scaling, and canvas viewport math.

The Disconnect Between CEF and OBS Transform Matrices

OBS Studio renders web content using the Chromium Embedded Framework (CEF). CEF generates an off-screen render buffer based strictly on the width and height specified in the Browser Source properties (for example, 1920×1080).

When you scale, stretch, or rotate a browser source inside the OBS preview using bounding box handles, OBS applies an affine transformation matrix to that rendered texture on the scene canvas. However, the underlying webpage within CEF does not natively understand that it has been resized on an external canvas.

When you click the interact window or the preview, OBS must perform an inverse matrix calculation to translate the click coordinate from the preview display space back into the local coordinate space of the CEF viewport. If the source has non-uniform scaling, altered aspect ratios, or rotation applied, the coordinate mapping can desynchronize, causing clicks to register at the wrong position.

Source Resolution vs. Bounding Box Scaling

The most common cause of coordinate drift is resizing the browser source by dragging its red transform boundaries on the canvas instead of updating its native resolution in the source properties:

  • Native Resolution: Setting the width and height inside the Browser Source properties instructs CEF to create an exact viewport of that size.
  • Canvas Scaling: Dragging the edges of the source scales the output frame texture after CEF has already rendered it.

When an interact event passes input to a source that has been scaled via the bounding box, the click location often maps to the original, unscaled pixel coordinates. This creates an increasing offset the further your cursor moves from the source’s origin point (usually the top-left corner).

OS Display Scaling and High-DPI Discrepancies

Operating system scaling (such as Windows Display Scaling set to 125%, 150%, or 200%) directly impacts how coordinate events are dispatched across the application:

  1. The operating system reports raw mouse coordinates to OBS Studio based on the scaled display.
  2. The OBS user interface (built with Qt) normalizes these inputs based on its own DPI awareness settings.
  3. OBS forwards the translated coordinates to CEF.

If there is a mismatch between how Qt interprets the system DPI and how CEF interprets the scale factor of the off-screen buffer, mouse coordinates will scale exponentially. This results in the visual cursor appearing to move at one speed while the underlying interaction registers at a magnified or reduced offset.

Preview Canvas Zoom and Viewport Offsets

Clicking directly within the OBS Studio preview window introduces another layer of coordinate translation. The preview viewport dynamically scales the base canvas to fit within your current UI layout.

To determine a click's target, OBS must calculate:

  1. The cursor position relative to the preview UI widget.
  2. The zoom and pan factor of the preview window relative to the Base (Canvas) Resolution.
  3. The position of the source within the Base Canvas.
  4. The scaling and cropping applied to the source.
  5. The internal resolution of the browser source.

A rounding error, non-integer scaling factor, or unapplied canvas offset at any of these stages will misalign the final coordinates sent to CEF.

Source Cropping and Bounding Box Types

Using Alt-drag to crop a browser source or setting a specific "Bounding Box Type" (such as Scale to inner bounds) often breaks click coordinate accuracy. Cropping cuts off portions of the visual frame in OBS, but CEF continues to render the entire webpage. Unless OBS accurately accounts for the cropped pixel offset before passing the coordinate to CEF, mouse clicks will be shifted horizontally or vertically by the exact number of pixels that were cropped from the top and left edges.
