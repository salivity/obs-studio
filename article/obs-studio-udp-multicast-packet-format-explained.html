OBS Studio UDP Multicast Packet Format Explained

When broadcasting video feeds via raw UDP multicast, OBS Studio encapsulates media streams using the MPEG-2 Transport Stream (MPEG-TS) format packed into UDP datagrams. This article breaks down the exact byte-level structure utilized during transmission, including UDP frame aggregation, the standard 188-byte MPEG-TS container header, and how Packetized Elementary Streams (PES) carrying video and audio data are mapped within these packets.

Network Layer Framing and Aggregation

OBS Studio utilizes FFmpeg libraries to output raw UDP streams. At the network level, sending individual transport packets would cause massive overhead and network inefficiency. To adhere to standard Ethernet Maximum Transmission Units (MTUs) of 1500 bytes, OBS Studio groups multiple TS packets into a single UDP datagram.

  • Ethernet MTU: 1500 bytes standard limit.
  • IP + UDP Headers: 28 bytes total (20-byte IPv4 header + 8-byte UDP header).
  • Payload Capacity: 1472 bytes maximum.
  • Aggregation Count: OBS packs exactly 7 MPEG-TS packets per UDP datagram.
  • Total UDP Payload Size: \(7 \times 188\text{ bytes} = 1316\text{ bytes}\).

This leaves 156 bytes of headroom under the standard MTU, preventing IP-level packet fragmentation across standard network hardware.

The 188-Byte MPEG-TS Packet Structure

Every UDP datagram payload consists of a sequential array of 188-byte MPEG-TS packets. Each 188-byte packet is composed of a 4-byte header followed by an optional adaptation field and the payload itself.

The 4-Byte MPEG-TS Header

  1. Sync Byte (8 bits): Always set to 0x47 (ASCII character 'G'). This acts as the frame delimiter.
  2. Transport Error Indicator / TEI (1 bit): Set to 1 by demodulators/network receivers if an uncorrectable bit error exists; set to 0 by OBS.
  3. Payload Unit Start Indicator / PUSI (1 bit): Set to 1 when the packet marks the beginning of a new PES packet or Program-Specific Information (PSI) table.
  4. Transport Priority (1 bit): Indicates higher priority for the packet when set to 1.
  5. Packet Identifier / PID (13 bits): Uniquely identifies the stream content (e.g., Program Association Table, Program Map Table, video data, or audio data).
  6. Transport Scrambling Control (2 bits): Set to 00 for unscrambled broadcast feeds.
  7. Adaptation Field Control (2 bits): Indicates whether an adaptation field or payload is present:
    • 01: Payload only (184 bytes of data)
    • 10: Adaptation field only (no payload)
    • 11: Adaptation field followed by payload
  8. Continuity Counter (4 bits): Increments from 0x0 to 0xF for each consecutive packet sharing the same PID, enabling receivers to detect dropped UDP packets.

Adaptation Field

When present, the adaptation field carries synchronization and clock metadata essential for decoding:

  • Adaptation Field Length (8 bits): Defines the size of the adaptation field.
  • Flags (8 bits): Signals the presence of optional metadata such as the Program Clock Reference (PCR), Discontinuity Indicator, or Random Access Indicator.
  • Program Clock Reference (PCR) (42 bits): Provides a 27 MHz clock reference enabling the receiver to synchronize audio and video timestamps without drift.
  • Stuffing Bytes (0xFF): Used to pad the packet out to the mandatory 188-byte boundary when data does not fill the space.

Program-Specific Information (PSI)

To allow a multicast receiver to parse the feed, OBS Studio interleaves system metadata packets into the transmission:

  • Program Association Table (PAT): Transmitted on PID 0x0000. Contains the list of programs and maps program numbers to their corresponding Program Map Table PIDs.
  • Program Map Table (PMT): Transmitted on an assigned PID (commonly 0x1000 or assigned dynamically). Defines elementary stream types (e.g., 0x1B for H.264/AVC, 0x24 for H.265/HEVC, 0x0F for AAC) and maps them to specific audio and video PIDs.

PES Payload (Video and Audio Streams)

The actual media content (typically H.264/H.265 video and AAC audio) is fragmented into Packetized Elementary Stream (PES) packets:

  1. PES Header: Begins with the start code prefix 0x000001, followed by the Stream ID (e.g., 0xE0 for video, 0xC0 for audio), and PES packet length.
  2. Timestamps: Contains the Presentation Time Stamp (PTS) and Decoding Time Stamp (DTS) to control frame display and decode sequences.
  3. Data Chunks: The PES payload contains the raw video Network Abstraction Layer (NAL) units or raw audio frames, which are divided into consecutive 184-byte chunks across multiple MPEG-TS packets sharing the respective stream PID.
