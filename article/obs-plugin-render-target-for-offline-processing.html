OBS Plugin Render Target for Offline Processing

Creating an isolated render target for offline processing or offscreen rendering in an OBS Studio plugin is achieved using the gs_texrender_create function from the libobs graphics subsystem. This function allocates an isolated texture render target (gs_texrender_t), enabling developers to redirect rendering passes into an independent buffer rather than the main output canvas. This guide explains how gs_texrender_create works, how to manage its lifecycle, and how to use it alongside staging surfaces for offline pixel manipulation.

The Core Function: gs_texrender_create

The primary graphics function for setting up an offscreen rendering surface is:

gs_texrender_t *gs_texrender_create(enum gs_color_format format,
                                   enum gs_zstencil_format zsformat);
  • format: Specifies the pixel format of the target texture (such as GS_RGBA, GS_BGRA, or GS_RGBA16F).
  • zsformat: Defines the depth/stencil buffer format (such as GS_ZS_NONE if depth testing is not needed, or GS_Z16, GS_Z24_S8, etc.).

This function returns a pointer to a gs_texrender_t structure that manages the underlying texture and framebuffers across different graphics backends (Direct3D 11 or OpenGL).

The Render Target Workflow

To render graphics into this isolated target, use the following operational lifecycle within the graphics thread:

  1. Initialization: Call gs_texrender_create during plugin initialization or inside the source's video render callback.
  2. Begin Capture: Call gs_texrender_begin(gs_texrender_t *trs, uint32_t cx, uint32_t cy) to set the render target and clear the viewport to the specified width (cx) and height (cy).
  3. Execute Draw Calls: Perform standard drawing commands, such as applying shaders, rendering text, or drawing primitive geometry.
  4. End Capture: Call gs_texrender_end(gs_texrender_t *trs) to restore the previous render target and finalize the offscreen pass.
  5. Access the Texture: Retrieve the resulting rendered texture using gs_texrender_get_texture(const gs_texrender_t *trs). This returns a gs_texture_t* that can be mapped to materials or sampled in subsequent rendering passes.
  6. Destruction: Call gs_texrender_destroy(gs_texrender_t *trs) when the target is no longer needed to prevent GPU memory leaks.

Offline CPU Readback

If "offline processing" requires copying the rendered frames from GPU memory to CPU system memory (such as for AI inference, custom encoding, or image analysis):

  1. Create a staging surface using gs_stagesurf_create(uint32_t width, uint32_t height, enum gs_color_format color_format).
  2. Copy the texture from the render target to the staging surface using gs_stage_texture(gs_stagesurf_t *dst, gs_texture_t *src).
  3. Map the staging surface using gs_stagesurf_map(gs_stagesurf_t *surf, uint8_t **data, uint32_t *linesize) to access the raw pixel byte array.
  4. Process the data, then call gs_stagesurf_unmap(gs_stagesurf_t *surf).
  5. Release the staging surface using gs_stagesurf_destroy(gs_stagesurf_t *surf) upon shutdown.
