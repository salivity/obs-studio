How OBS Downsamples 4:4:4 to 4:2:0 Chroma

When OBS Studio takes a full-resolution 4:4:4 or RGB video source and outputs it as 4:2:0 for streaming or recording, it downsamples the color information using GPU shader pipelines. This process halves the horizontal and vertical resolution of the chrominance (U and V) planes relative to the luminance (Y) plane, using bilinear filtering or box averaging to calculate the shared color values before packing the final frames into formats like NV12 or I420 for encoder delivery.

Internal Render Pipeline and Color Conversion

OBS Studio processes scene composition internally using the GPU in full color—typically in an RGB color space or full 4:4:4 YUV. When the output format in OBS Settings is configured to a 4:2:0 format (most commonly NV12 for hardware acceleration, or I420 for specific software codecs), the video core must convert and compress the color data prior to passing it to the encoder.

This step takes place on the GPU using custom pixel shaders (written in HLSL for Direct3D on Windows or GLSL for OpenGL on Linux):

  1. Luminance Separation: The shader first calculates the full-resolution Y (luma) plane. Every single pixel from the 4:4:4 source maintains its distinct brightness value, ensuring that overall image sharpness and edge contrast remain intact.
  2. Chrominance Decimation: The shader then calculates the U (Cb) and V (Cr) values at half the horizontal and half the vertical resolution of the original frame. For every 2x2 block of luma pixels, only one U sample and one V sample are generated.

Chroma Siting and Filtering

To downsample the chroma planes without creating severe color aliasing or color fringing, OBS relies on texture sampling hardware on the GPU.

  • Bilinear Downsampling: The shader samples the full-resolution chroma data using bilinear interpolation. It calculates an average of the four surrounding chroma values in each 2x2 pixel cluster.
  • Chroma Siting Alignment: In accordance with standard video specifications (such as H.264/AVC and H.265/HEVC), OBS positions the downsampled chroma sample at the center or the left-center of the 2x2 grid (MPEG-4/H.264 standard siting). This alignment ensures that the color boundaries match up precisely with the luminance edges when the playback device reconstructs the frame.

Memory Layout and Plane Packing

Once the downsampled values are calculated, the GPU writes the luma and chroma data into an output texture structured for 4:2:0 transmission:

  • NV12 (Interleaved Chroma): The primary format used by OBS Studio. The luma plane (Y) is written as a continuous, full-resolution block of memory occupying the first section of the frame. Directly below it, the U and V components are written together into a single half-height plane, interleaved as alternating bytes (UVUV...).
  • I420 (Planar Chroma): If configured for planar output, the memory is split into three separate planes: full-resolution Y, followed by a separate U plane at one-quarter the total pixel count, followed by an equivalent separate V plane.

Transmission to the Encoder

Because the color space conversion and chroma decimation occur via GPU shaders, the resulting 4:2:0 buffer resides directly in video memory (VRAM).

  • When using hardware encoders such as NVIDIA NVENC, AMD AMF, or Intel QuickSync, OBS transfers the downsampled NV12 texture directly within GPU memory, avoiding costly CPU-memory copies.
  • When using a software encoder such as x264, the packed 4:2:0 frame is copied from GPU memory back to system RAM, where the CPU compresses the pre-downsampled luma and chroma arrays into the final video stream.
