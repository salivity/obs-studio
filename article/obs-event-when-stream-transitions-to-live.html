OBS Event When Stream Transitions to Live

When OBS Studio establishes a successful connection to an RTMP/WHIP server and transitions from connecting to an active live status, it triggers specific events depending on whether you are using the internal C/C++ API or the OBS WebSocket interface. In the native C/C++ Frontend API, the event is OBS_FRONTEND_EVENT_STREAMING_STARTED. In the modern OBS WebSocket (v5.x) protocol, this state change fires the StreamStateChanged event with an outputState of OBS_WEBSOCKET_OUTPUT_STARTED.

Native Frontend API: OBS_FRONTEND_EVENT_STREAMING_STARTED

For plugin developers using the native obs-frontend-api, OBS notifies registered callbacks using the obs_frontend_event enum.

During the lifecycle of a stream:

  1. Connecting phase: OBS triggers OBS_FRONTEND_EVENT_STREAMING_STARTING when the user initiates the stream and connection handshakes begin.
  2. Live phase: Once the connection is fully acknowledged by the streaming ingest server and data packets begin flowing, OBS triggers OBS_FRONTEND_EVENT_STREAMING_STARTED.

This event indicates that the stream output is completely initialized and frames are transmitting to the endpoint.

Core Libobs Output Signal: start

At the underlying engine level (libobs), streaming is managed by an obs_output_t object. When the output establishes a connection and transitions from the connecting state to the active streaming state, the output's signal handler triggers the "start" signal.

Developers monitoring output signals directly hook into this using: signal_handler_connect(obs_output_get_signal_handler(stream_output), "start", callback, data);

OBS WebSocket v5: StreamStateChanged

For remote integrations, automation tools, and external control software interacting with OBS over the v5 WebSocket API, the event dispatched is:

  • Event Name: StreamStateChanged
  • Condition: When entering the live state, the payload contains:
    • outputActive: true
    • outputState: "OBS_WEBSOCKET_OUTPUT_STARTED"

Prior to this transition, OBS WebSocket broadcasts the same event with outputState: "OBS_WEBSOCKET_OUTPUT_STARTING". Applications tracking live status should evaluate outputState to confirm the transition to "OBS_WEBSOCKET_OUTPUT_STARTED".

Legacy OBS WebSocket v4: StreamStarted

In legacy environments using OBS WebSocket v4.x, the protocol used distinct event names rather than unified state payloads. The transition to live was signaled by:

  • Event Name: StreamStarted

This followed the initial StreamStarting event once the ingest server confirmed the RTMP connection.
