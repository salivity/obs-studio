Trace Corrupted OBS Config Files in AppData

An unexpected power outage can interrupt disk write operations, leaving OBS Studio with truncated or corrupted configuration files that prevent the application from launching properly. This guide explains how to locate the OBS Studio AppData directory, review crash and session logs to pinpoint broken files, identify zero-byte or malformed configuration assets, and restore your settings from automatic backups.

Step 1: Open the OBS Studio AppData Directory

OBS Studio stores its global settings, profiles, and scene collections inside the Windows roaming profile directory.

  1. Press Windows Key + R to open the Run dialog.
  2. Type %appdata%\obs-studio and press Enter.
  3. Keep this folder open, as all target configuration files and logs are located within this directory tree.

Step 2: Review OBS Studio Log Files

Log files typically state the exact file path and line number where a configuration load failed.

  1. Inside %appdata%\obs-studio, open the logs folder.
  2. Sort the files by Date modified and open the most recent text file in a text editor like Notepad.
  3. Scroll to the bottom of the log or search for terms such as error, failed to load, parse error, or JSON.
  4. If OBS crashes instantly upon launch, check the crashes folder in %appdata%\obs-studio instead. Look for crash logs that reference invalid pointers or exceptions in obs.dll during startup initialization.

Step 3: Scan for Truncated and Zero-Byte Files

When a power outage cuts disk writes mid-process, Windows often leaves the affected file as an empty 0 KB file.

  1. Check the primary global configuration file: %appdata%\obs-studio\global.ini. Right-click it, select Properties, and ensure its size is greater than 0 KB.
  2. Navigate to %appdata%\obs-studio\basic\scenes. Look at the Size column for any .json files that register as 0 KB.
  3. Navigate to %appdata%\obs-studio\basic\profiles. Open each profile folder and check if basic.ini or streamEncoder.json are empty.
  4. Any 0 KB file located in these directories is corrupted and must be repaired or replaced.

Step 4: Validate JSON Syntax in Configuration Files

If a file contains data but was only partially written, the JSON formatting will be broken.

  1. Open suspected .json scene files in an editor such as Notepad++ or VS Code, or paste the content into an online JSON validator.
  2. Look at the end of the file. A healthy OBS scene configuration always concludes with closing curly brackets (}) or square brackets (]). If the file ends abruptly mid-string, it is truncated.

Step 5: Restore from Automatic Backups

OBS Studio automatically creates backup copies of scene collections during regular operation.

  1. In %appdata%\obs-studio\basic\scenes, look for files ending with .json.bak.
  2. Delete or move the corrupted .json file out of the directory.
  3. Rename the corresponding .json.bak file by removing the .bak extension so that it becomes a standard .json file.
  4. If global.ini was the corrupted file and no backup exists, delete global.ini. OBS Studio will generate a clean version on the next startup, though basic preferences (such as language and general UI layout) will need to be reconfigured.

Step 6: Verify the Fix

Launch OBS Studio. If the application starts normally, your scene collections, sources, and stream settings are recovered. If an error persists, return to Step 2 and check the newest log file to identify any secondary files damaged during the shutdown.
