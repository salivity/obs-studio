Toggle OBS Filter Visibility via WebSocket

Controlling filter visibility programmatically in OBS Studio allows creators and developers to automate visual effects, color grading, and audio processing dynamically. This article outlines the specific WebSocket request used to toggle individual filter visibility on an OBS source, explains the required payload structure for the modern OBS WebSocket v5 protocol, and covers the standard implementation method for flipping filter states.

The WebSocket Request: SetSourceFilterEnabled

In OBS Studio 28 and newer (which integrates obs-websocket v5 natively), the request used to set the visibility of an individual filter is SetSourceFilterEnabled.

Because the API does not provide a standalone single-command "toggle" action, toggling is achieved by passing the inverted boolean state to SetSourceFilterEnabled.

Request Data Structure

To enable or disable a filter, send a WebSocket message with the Request op-code (6) containing the following JSON payload:

{
  "op": 6,
  "d": {
    "requestType": "SetSourceFilterEnabled",
    "requestId": "toggle-filter-example",
    "requestData": {
      "sourceName": "Camera Source",
      "filterName": "Color Correction",
      "filterEnabled": false
    }
  }
}

Parameters:

  • sourceName (String): The name of the source hosting the filter. Alternatively, you can use sourceUuid.
  • filterName (String): The exact name of the filter applied to the source.
  • filterEnabled (Boolean): Set to true to make the filter visible/active, or false to hide/disable it.

Implementing a True Toggle

To dynamically toggle the filter state without tracking it locally in your application:

  1. Check Current State: Send a GetSourceFilter request. 
    {
  "op": 6,
  "d": {
    "requestType": "GetSourceFilter",
    "requestId": "check-state-1",
    "requestData": {
      "sourceName": "Camera Source",
      "filterName": "Color Correction"
    }
  }
}
  2. Read the Response: The response payload (responseData) returns filterEnabled as a boolean.
  3. Invert and Apply: Send the SetSourceFilterEnabled request with filterEnabled set to the opposite value of the current state.

Legacy Support (obs-websocket v4.9.x)

For systems running OBS Studio 27 or older with the legacy v4 plugin, the corresponding request name is SetSourceFilterVisibility:

{
  "request-type": "SetSourceFilterVisibility",
  "message-id": "legacy-toggle-1",
  "sourceName": "Camera Source",
  "filterName": "Color Correction",
  "filterEnabled": false
}
