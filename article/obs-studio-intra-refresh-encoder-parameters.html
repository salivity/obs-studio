OBS Studio Intra-Refresh Encoder Parameters

Intra-refresh replaces traditional, bandwidth-heavy Instantaneous Decoder Refresh (IDR) keyframes with a continuous, rolling wave of intra-coded macroblocks or slices spread across multiple frames. In OBS Studio, configuring this behavior eliminates bitrate spikes and reduces transmission latency for live streaming and real-time interactive video. Enabling intra-refresh requires tuning specific encoder parameters, primarily activation flags, refresh period lengths, and keyframe interval overrides across different hardware and software encoding backends like x264, NVIDIA NVENC, and AMD AMF.

Core Mechanics of Intra-Refresh vs. IDR

Standard video encoding periodically transmits a complete IDR frame, forcing the decoder to clear its reference picture buffer and decode a brand-new, standalone frame. While this guarantees clean recovery from packet loss, it introduces large bitrate spikes.

Intra-refresh spreads the refresh process over a user-defined number of P-frames. A fraction of each frame is coded with intra macroblocks (an intra-refresh slice), moving cyclically across the screen until the entire image is reconstructed. For this mechanism to function, the encoder must suppress conventional periodic IDR frames and replace them with intra-slice cycles.

Custom Encoder Parameters Across Implementations

OBS Studio exposes intra-refresh controls primarily through the "Custom Encoder Settings" or custom FFmpeg options fields, depending on the active encoder profile.

1. Software Encoding (x264)

In software-based x264 encoding, intra-refresh is governed by libx264 parameters:

  • intra-refresh=1 (or --intra-refresh): The master toggle that enables the rolling intra-refresh column instead of emitting periodic IDR frames.
  • keyint: Sets the maximum interval between complete refresh cycles. When intra-refresh is active, this value defines the cycle length rather than an IDR boundary.
  • ref=1: Typically required or recommended alongside intra-refresh to prevent references across refresh waves, ensuring error recovery occurs cleanly within one complete cycle.

2. NVIDIA NVENC

Modern NVENC APIs support intra-refresh, accessible in OBS Studio via advanced or custom parameters:

  • intra-refresh=1: Activates intra-refresh mode in the NVENC hardware engine.
  • intra_refresh_period: Specifies the total number of frames in which a complete screen refresh takes place.
  • intra_refresh_cnt: Governs the duration (in frames) of the refresh cycle. A higher count spreads the data more thinly across frames, while a lower count refreshes the screen faster at the cost of a temporary bitrate increase.

3. AMD AMF

For AMD hardware encoders, the AMF integration exposes intra-refresh through the graphical interface or property strings:

  • Intra-Refresh Enable (AMF_VIDEO_ENCODER_INTRA_REFRESH_MODE): Sets the mode to row-based or column-based intra-refresh.
  • Number of MBs per Slot / Intra-Refresh Period: Determines how many macroblocks (MBs) per frame are designated as intra, directly dictating how many frames are required for a complete picture cycle.

Governing Keyframe Settings in the OBS GUI

For any custom intra-refresh parameter to operate effectively, the standard OBS GUI Keyframe Interval setting must be configured to prevent forced IDR insertions:

  • Keyframe Interval = 0 (Auto/Infinite): Setting the standard interval to 0 prevents OBS and the underlying encoder from forcing regular IDR frames into the stream.
  • Conflict Resolution: If a nonzero keyframe interval (such as the standard 2 seconds) is set alongside intra-refresh flags, the encoder may still force an IDR frame at each interval, overriding the latency and smoothing benefits of the intra-refresh configuration.
