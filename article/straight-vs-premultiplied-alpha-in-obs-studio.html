Straight vs Premultiplied Alpha in OBS Studio

In OBS Studio, understanding the difference between straight alpha and premultiplied alpha is essential for correctly rendering transparent overlays, stingers, and media sources without visual artifacts. Alpha blending determines how semi-transparent pixels composite over a background scene. While straight alpha preserves raw color values independently of the transparency mask, premultiplied alpha pre-calculates the color intensity based on opacity, dictating how the OBS compositor mathematically combines source layers to avoid unsightly dark or discolored edges.

Straight Alpha (Unassociated Alpha)

In straight alpha, the RGB color channels and the alpha channel (A) remain completely independent:

  • Pixel Data: The RGB values store the full, unattenuated color information, even if a pixel is 50% or completely transparent.
  • Compositing Math: To render a straight alpha layer onto a background, the compositor must first multiply the source RGB values by the source alpha value, then multiply the background RGB values by the inverted alpha \((1 - Alpha)\), and finally add the two results together: \[\text{Final Color} = (\text{Source}_{\text{RGB}} \times \text{Source}_A) + (\text{Background}_{\text{RGB}} \times (1 - \text{Source}_A))\]

Straight alpha is the standard format for most static image formats like PNG and is intuitive for manual editing, as the underlying color remains intact regardless of the alpha channel level.

Premultiplied Alpha (Associated Alpha)

In premultiplied alpha, the source RGB values have already been multiplied by their alpha values during the export or rendering process:

  • Pixel Data: A 50% transparent pure red pixel \((R: 1.0, G: 0.0, B: 0.0, A: 0.5)\) is stored in the file as \((R: 0.5, G: 0.0, B: 0.0, A: 0.5)\). Fully transparent pixels always become pure black \((0, 0, 0, 0)\).
  • Compositing Math: Because the color channels are already scaled by the alpha value, the compositor skips the first multiplication step, reducing computational overhead: \[\text{Final Color} = \text{Source}_{\text{RGB}} + (\text{Background}_{\text{RGB}} \times (1 - \text{Source}_A))\]

Premultiplied alpha is computationally faster for real-time graphics engines and prevents filtering artifacts when assets are scaled or filtered.

Key Differences in the OBS Studio Compositor

The primary difference inside OBS Studio lies in how the graphics compositor interprets incoming pixel data from media sources, stinger transitions, and browser layers.

  1. Incorrect Interpretation Artifacts:

    • Premultiplied asset treated as Straight: If an asset rendered with premultiplied alpha is composited using straight alpha math, the alpha multiplication happens twice. This results in dark or black fringes around semi-transparent edges, glows, shadows, and motion blur.
    • Straight asset treated as Premultiplied: If a straight alpha asset is read as premultiplied, the initial multiplication step is skipped entirely. This causes semi-transparent edges to appear overly bright, washed out, or surrounded by a white halo.

  2. Common Source Types:

    • Browser Sources & WebM: Modern web renderers and WebM clips often use premultiplied alpha to optimize performance.
    • PNG & ProRes 4444: Graphic design assets and ProRes video files with an alpha channel are commonly exported using straight alpha unless explicitly specified otherwise in rendering software like Adobe After Effects or DaVinci Resolve.

To ensure clean edges in OBS Studio, the source's alpha interpretation setting must match the exact export method used during asset creation.
