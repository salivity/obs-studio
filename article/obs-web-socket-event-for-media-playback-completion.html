OBS WebSocket Event for Media Playback Completion

When a media source in OBS Studio finishes playing and transitions to an idle state, the OBS WebSocket protocol notifies connected clients by emitting a dedicated event. In modern versions using the obs-websocket version 5 protocol, this event is MediaInputPlaybackEnded. In legacy versions running obs-websocket 4.x or earlier, the equivalent event is MediaEnded. This article details how this event functions, its payload, and how to handle it in automated streaming workflows.

The Modern Event: MediaInputPlaybackEnded (v5.x Protocol)

In obs-websocket version 5 (bundled natively starting with OBS Studio 28), the event emitted upon media completion is MediaInputPlaybackEnded.

This event is dispatched automatically when a media source (such as a VLC Video Source or a standard Media Source) plays to the end of its duration without looping, causing the playback state to change to ended or idle.

Event Subscription

To receive MediaInputPlaybackEnded, the WebSocket client must subscribe to the MediaInputs event category during the handshake (Identify) phase by including the appropriate bitmask flag:

  • Category Name: MediaInputs
  • Bitmask Value: 1 << 9 (Integer: 512)

Event Payload

When the event fires, the WebSocket server transmits a JSON payload identifying the source that finished playing:

{
  "d": {
    "eventData": {
      "inputName": "Replay Video",
      "inputUuid": "a1b2c3d4-e5f6-7a8b-9c0d-1e2f3a4b5c6d"
    },
    "eventType": "MediaInputPlaybackEnded",
    "eventIntent": 512
  },
  "op": 5
}
  • inputName: The user-defined string name of the media input in OBS Studio.
  • inputUuid: The unique internal identifier for the input (available in obs-websocket 5.1.0+).

Playback Behavior and Conditions

The MediaInputPlaybackEnded event triggers under specific operational conditions:

  1. Looping Disabled: The media source must have "Loop" unchecked in its properties. If looping is active, the media re-triggers playback immediately upon reaching the end, emitting MediaInputActionTriggered or loop cycles rather than entering an idle ended state.
  2. Natural Playback End: The media reaches its final frame in real-time playback.
  3. Manual Stops: Stopping a media clip programmatically or via the UI may also transition the source to an idle state, prompting playback termination events.

Legacy Protocol: MediaEnded (v4.x Protocol)

For legacy implementations using obs-websocket version 4.9.1 or older, the event emitted is MediaEnded.

Legacy Event Payload

{
  "update-type": "MediaEnded",
  "sourceName": "Replay Video"
}

In the legacy protocol, sourceName provides the name of the media source that ceased playback. Applications migrating from legacy OBS installations should update listeners from MediaEnded to MediaInputPlaybackEnded to ensure compatibility with modern OBS releases.
