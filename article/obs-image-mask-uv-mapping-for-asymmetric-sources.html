OBS Image Mask UV Mapping for Asymmetric Sources

This article explains how OBS Studio computes UV coordinate mapping when an Image Mask/Blend filter is applied to an asymmetric video layer. It covers the underlying graphics pipeline, normalized coordinate generation, shader sampling mechanics, and the practical implications of aspect ratio mismatches between the mask and the video source.

The Coordinate Space and Quad Generation

OBS Studio relies on its core rendering library, libobs, alongside a graphics API abstraction layer (Direct3D 11 on Windows, OpenGL/Metal on macOS/Linux). When any source is drawn to a frame buffer, OBS constructs a two-dimensional rectangular mesh (a quad) defining the bounding area of that source.

Regardless of whether the video layer is asymmetric (for example, an ultrawide 21:9 feed, a vertical 9:16 camera feed, or an arbitrarily cropped source), the rendering pipeline generates vertex positions mapped to normalized device coordinates. Alongside vertex positions, standard texture coordinates (\(U, V\)) are assigned to the four vertices:

  • Top-left: \((0.0, 0.0)\)
  • Top-right: \((1.0, 0.0)\)
  • Bottom-left: \((0.0, 1.0)\)
  • Bottom-right: \((1.0, 1.0)\)

These normalized coordinates represent the entirety of the layer’s visible bounds at the time the filter is executed.

UV Calculation in mask_filter.effect

The Image Mask/Blend filter in OBS Studio is implemented as a pixel shader via mask_filter.effect. The vertex shader takes the vertex stream generated for the layer's quad and directly interpolates the \((U, V)\) coordinates across the primitive.

struct VertData {
    float4 pos : POSITION;
    float2 uv  : TEXCOORD0;
};

VertData VSDefault(VertData v_in)
{
    VertData vert_out;
    vert_out.pos = mul(float4(v_in.pos.xyz, 1.0), ViewProj);
    vert_out.uv  = v_in.uv;
    return vert_out;
}

In the fragment/pixel shader stage, two primary texture samples occur at the exact same interpolated UV coordinate:

  1. Source Texture (image): The asymmetric video feed.
  2. Mask Texture (target): The static image or alpha mask file selected by the user.
float4 PSMask(VertData v_in) : TARGET
{
    float4 rgba = image.Sample(textureSampler, v_in.uv);
    float4 mask = target.Sample(textureSampler, v_in.uv);
    // Mask blending logic follows
}

Because both the source layer and the mask image are sampled using the identical v_in.uv coordinate, OBS maps the full horizontal domain \([0, 1]\) and vertical domain \([0, 1]\) of the mask directly onto the full horizontal and vertical bounds of the video layer.

Non-Uniform Scaling on Asymmetric Layers

Because the mapping relies entirely on normalized \([0, 1]\) UV space without automatic aspect-ratio correction matrices, an asymmetric layer produces anisotropic (non-uniform) scaling:

  • Aspect Ratio Discrepancies: If the video layer has an aspect ratio of 16:9 (\(1.77:1\)) and the mask texture is 1:1 (\(1.00:1\)), the UV coordinates interpolate across a surface that is horizontally wider than it is tall. The shader samples the mask from \(U = 0.0\) to \(U = 1.0\) across the full width, causing the mask features to stretch horizontally to match the 16:9 layer.
  • Pixel Density Disregard: The UV mapping logic does not calculate texel-to-pixel ratios. The physical resolution (in pixels) of neither the source nor the mask dictates the sampling scale; only the relative coordinate span matters.

Filter Execution Order and Cropping

How UVs are mapped also depends on where the asymmetry originates:

  • Source-Level Filters: If an Image Mask is placed directly on a source, the UV coordinates map to the native pixel dimensions of that source. If crop settings are applied inside an upstream filter or via native source settings, the UV \([0, 1]\) bounds encompass only the post-crop canvas.
  • Scene-Item Transforms: If the asymmetry is created via Scene Item cropping (e.g., holding Alt and dragging edges in the OBS preview window), this transform occurs after the source-level filter stack executes. The mask filter will evaluate against the uncropped source canvas first, and the resulting masked output will subsequently be cropped by the scene transform.
