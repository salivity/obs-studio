OBS Log USB Controller Bandwidth Exhaustion

When multiple high-throughput USB devices—such as 4K capture cards, uncompressed webcams, and multi-channel audio interfaces—share a single USB root hub, the controller can run out of isochronous bandwidth. This article outlines the specific hardware indicators, error codes, and behavioral patterns that appear in an OBS Studio log file when USB host controller bandwidth is exhausted, allowing you to quickly diagnose hardware-level bottlenecks.

DirectShow Error Codes (0x800705AA and 0x8007001F)

The most direct indicators of USB bandwidth saturation appear in lines initialized by the DirectShow (DShow) capture subsystem. Windows returns system-level HRESULT codes when a device fails to negotiate required bandwidth with the USB host controller.

Look for these specific errors in the log:

  • 0x800705AA (ERROR_NO_SYSTEM_RESOURCES): This is the primary indicator of USB bandwidth exhaustion. It occurs when a video capture device requests an isochronous transfer endpoint, but the host controller cannot allocate the required bandwidth slots. The log will typically display: DShow: Run failed (0x800705AA) or DShow: Failed to set video format: 0x800705AA.
  • 0x8007001F (ERROR_GEN_FAILURE): Indicates that "A device attached to the system is not functioning." In the context of USB saturation, this happens when a device abruptly disconnects mid-stream because the USB controller timed out packet delivery.

Capture Device Reset Loops and Topology Spam

When a USB host controller drops packets, devices frequently stall, drop off the USB bus, and attempt to re-enumerate. In an OBS Studio log, this creates repetitive device initialization cycles:

  • Continuous Add/Remove Events: Sequential entries showing DShow: Device '[Device Name]' removed followed moments later by DShow: Device '[Device Name]' added.
  • Format Negotiation Failures: Repeated entries where OBS tries to restart the capture stream with default video configurations (e.g., falling back from YUY2 to MJPEG or lower resolutions) because the requested data rate was rejected by the bus.

Audio Subsystem Desynchronization and WASAPI Invalidation

Audio interfaces sharing a saturated USB controller suffer packet loss, leading to buffer degradation or hardware invalidation in OBS Studio's audio monitoring pipeline:

  • WASAPI: Device invalidated: Occurs when the Windows Audio Session API loses communication with the USB audio device because the host controller dropped the connection.
  • Max audio buffering reached!: While this can occur due to general system stalls, a cluster of these warnings paired with capture device drops indicates that audio packets from a USB source are arriving late, forcing OBS to pad the buffer until it hits its hard ceiling.

Source-Level Frame Freezes vs. Encoding/Rendering Lag

OBS Studio logs provide clear summaries at the end of a session distinguishing between different types of performance issues:

  • Rendering Lag: Logged as Number of frames dropped due to rendering lag (GPU overload).
  • Encoding Lag: Logged as Number of frames dropped due to encoding lag (CPU/GPU encoder overload).
  • USB Bandwidth Saturation: Does not appear as rendering or encoding lag. Instead, the total rendered frames and output frames may show 0% dropped, but the captured video stream itself freezes or stutters. The log will show normal encoder performance, but specific capture source threads will log timeouts, such as [source_name]: Timed out waiting for frame or repeated timestamp synchronization jumps.

How to Resolve USB Bandwidth Saturation

  1. Separate Host Controllers: Move one or more high-bandwidth devices (such as a capture card) to a different USB controller. Motherboards often have different physical ports wired to the CPU controller versus the chipset controller.
  2. Change Video Formats: In OBS, change the video capture format from uncompressed (YUY2 or NV12) to compressed (MJPEG). This drastically reduces the data payload transmitted over the USB bus.
  3. Install a Dedicated PCIe USB Card: Adding a discrete PCIe USB expansion card provides a separate, dedicated host controller and independent bandwidth channel for capture hardware.
