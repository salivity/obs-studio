OBS Studio Hardware Video Buffer Allocation

This article provides an overview of how developers can allocate and manage hardware-accelerated video buffers in OBS Studio using its C API. OBS Studio delegates GPU memory management to its internal graphics subsystem (libobs/graphics), allowing custom plugins to allocate native graphics textures, offscreen render targets, staging surfaces, and interop handles across supported graphics backends such as Direct3D 11, OpenGL, and Metal.

The Graphics Context Requirement

All graphics-related allocations in OBS Studio must occur within the graphics execution context. Attempting to allocate GPU resources outside this thread will result in undefined behavior or crashes. Custom plugins must wrap allocation routines using:

obs_enter_graphics();
/* Allocate or modify hardware buffers here */
obs_leave_graphics();

1. Direct GPU Texture Allocation (gs_texture_create)

The primary method for allocating standard 2D hardware-accelerated video buffers in VRAM is gs_texture_create. This function allocates a native GPU texture managed directly by the active graphics backend.

gs_texture_t *gs_texture_create(
    uint32_t width,
    uint32_t height,
    enum gs_color_format color_format,
    uint32_t levels,
    const uint8_t **data,
    uint32_t flags
);
  • color_format: Defines the pixel format (e.g., GS_RGBA, GS_BGRA, GS_NV12, or GS_R8).
  • levels: Number of mipmap levels. Passing 1 creates a flat video frame buffer.
  • data: Pointer to initial pixel data. Passing NULL allocates uninitialized VRAM on the GPU without performing a host-to-device copy.
  • flags: Allocation behavior flags:
    • GS_DYNAMIC: Optimizes the buffer for frequent updates from host memory via gs_texture_set_image.
    • GS_RENDER_TARGET: Designates the buffer as an offscreen render target for GPU rendering passes.

Hardware buffers created via gs_texture_create are freed using gs_texture_destroy(gs_texture_t *tex).

2. Staging Surfaces for Asynchronous Transfers (gs_stagesurface_create)

When plugins must transfer video data between system memory (RAM) and GPU memory (VRAM) without stalling the graphics pipeline, the API provides staging surfaces:

gs_stagesurface_t *gs_stagesurface_create(
    uint32_t width,
    uint32_t height,
    enum gs_color_format color_format
);

Staging surfaces act as intermediate host-visible or device-accessible staging buffers. They allow non-blocking pixel readbacks (GPU-to-CPU) and asynchronously staged texture uploads (CPU-to-GPU). Staging surfaces are mapped using gs_stagesurface_map and destroyed with gs_stagesurface_destroy.

3. Offscreen Render Targets (gs_texrender_create)

For video processing pipelines requiring dynamic multi-pass rendering, OBS Studio provides the gs_texrender_t abstraction:

gs_texrender_t *gs_texrender_create(
    enum gs_color_format format,
    enum gs_zstencil_format zsformat
);

This creates an encapsulated hardware framebuffer object that manages an underlying texture and optional depth/stencil buffer. It is dynamically resized using gs_texrender_begin(gs_texrender_t *render, uint32_t cx, uint32_t cy). The resulting hardware buffer can be accessed via gs_texrender_get_texture for sampling in downstream video rendering passes. Clean up is handled by gs_texrender_destroy.

4. Platform-Specific Zero-Copy Hardware Interoperability

For custom plugins integrating hardware decoders (such as NVDEC, Intel QuickSync, or VA-API) or external capture APIs, OBS Studio provides platform-specific texture creation routines to avoid CPU memory copies.

Windows: Shared Direct3D 11 Textures

Plugins can open shared GPU resources allocated by external processes or APIs (like Direct3D 11/12, CUDA, or Media Foundation) using:

gs_texture_t *gs_texture_open_shared(uint32_t handle);
gs_texture_t *gs_texture_open_nt_shared(void *handle);

Alternatively, plugins can retrieve the native Direct3D 11 device handle directly from OBS using gs_get_device_obj() to allocate buffers using native DirectX interfaces.

Linux: DMA-BUF Import

On Linux platforms, OBS supports importing zero-copy Linux kernel DMA buffers (DMA-BUFs) directly into OBS textures:

gs_texture_t *gs_texture_create_from_dmabuf(
    unsigned int width,
    unsigned int height,
    uint32_t drm_format,
    enum gs_color_format color_format,
    uint32_t n_planes,
    const int *fds,
    const uint32_t *strides,
    const uint32_t *offsets,
    const uint64_t *modifiers
);

This function allows custom capture or decoder plugins utilizing PipeWire, V4L2, or VA-API to bind hardware memory directly to OBS textures without moving frame data across the PCI bus.
