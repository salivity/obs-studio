OBS DCI-P3 Color Profile Handling on macOS

Capturing wide-gamut displays such as Apple's Display P3 on macOS using OBS Studio often introduces color shifts, washed-out visuals, or unnatural oversaturation. This article examines how macOS manages wide color gamuts, how OBS Studio ingests frames via macOS capture APIs like ScreenCaptureKit, how color space conversions occur internally within OBS, and how to configure settings for accurate color reproduction.

The macOS Color Pipeline and Display P3

Modern Mac displays—including built-in MacBook Pro screens, the Studio Display, and iMacs—use the Display P3 color space. Display P3 uses the wide color gamut of DCI-P3 combined with the sRGB transfer function (gamma curve) and a D65 white point.

macOS enforces system-wide color management via Apple ColorSync. Applications that support ColorSync tag their window buffers with specific ICC profiles. When macOS renders these buffers to the screen, the compositor maps colors accurately to the physical display's color profile.

Capture Ingestion: ScreenCaptureKit and CoreGraphics

OBS Studio captures macOS displays using Apple’s ScreenCaptureKit framework (on macOS 13 Ventura and later) or legacy CoreGraphics APIs. ScreenCaptureKit delivers video frames from the display compositor directly to OBS.

When ScreenCaptureKit delivers a frame, the pixel buffer retains color metadata reflecting the display's native state:

  • Pixel Format: Typically 8-bit or 10-bit BGRA/RGBA.
  • Color Space Tag: Tagged as kCGColorSpaceDisplayP3 or standard sRGB.

If an older macOS capture API is used, color space tags may be stripped or ignored, causing the raw pixel values to be forwarded to OBS without contextual gamut metadata.

How OBS Studio Converts DCI-P3 to Rec. 709

OBS Studio operates primarily in the Rec. 709 color space using an 8-bit standard dynamic range (SDR) pipeline by default. When ingesting a Display P3 or DCI-P3 surface, OBS must translate wide-gamut color coordinates into standard gamut coordinates.

1. Matrix Transformation via Shaders

When color tags are properly communicated from ScreenCaptureKit to OBS's rendering subsystem, OBS uses internal GPU shaders to apply a color matrix transform. This converts the RGB coordinates from the P3 color primaries to Rec. 709 primaries:

  • Colors within the standard Rec. 709 gamut maintain their visual appearance.
  • Wide-gamut colors extending outside the Rec. 709 gamut boundary are clamped to the nearest reproducible Rec. 709 values.

2. The "Washed Out" Fallback Issue

If OBS does not read or apply the ColorSync profile from the capture source, it assumes incoming pixel data is already standard Rec. 709 / sRGB. Because DCI-P3 coordinates define a wider gamut, interpreting P3 pixel values directly as Rec. 709 values without conversion results in lower saturation and incorrect color luminance, making the output appear faded or washed out.

3. HDR and Advanced Color Management (OBS 28+)

Starting in OBS Studio 28, native support for 10-bit color and HDR workflows was introduced. When configured for HDR:

  • OBS can ingest the full P3 gamut without clamping down to Rec. 709.
  • The internal pipeline utilizes Rec. 2100 primaries with either the PQ (Perceptual Quantizer) or HLG transfer curve.
  • P3 coordinates are mapped into the larger Rec. 2020 container via matrix multiplication, preventing color clipping during recording or streaming to HDR-capable platforms.

Configuring OBS for Proper Color Accuracy on macOS

To ensure OBS Studio handles macOS DCI-P3 displays properly, configure the following settings:

  1. Use ScreenCaptureKit: Under OBS Sources, ensure the capture method is set to the native macOS Screen Capture (ScreenCaptureKit), which preserves display color metadata far better than older display capture methods.
  2. Set Color Space in Advanced Settings:
    • Navigate to Settings > Advanced > Video.
    • For SDR streaming, set Color Format to NV12 or I420, Color Space to Rec. 709, and Color Range to Partial or Limited (standard broadcast range to prevent crushed blacks).
  3. Configure HDR/Wide Gamut Recording (Optional):
    • If targeting wide-gamut or HDR playback, change the Color Format to P010, set the Color Space to Rec. 2100 (PQ) or Rec. 2100 (HLG), and ensure you record with a compatible 10-bit codec such as Apple HEVC (ProRes or H.265).
  4. Source-Level Overrides: If a capture appears desaturated due to metadata mismatch, open the properties of the macOS Screen Capture source and verify whether manual color space overrides (such as forcing Rec. 709 or sRGB) are available to correct raw matrix translation.
