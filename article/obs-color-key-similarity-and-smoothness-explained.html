OBS Color Key Similarity and Smoothness Explained

The Color Key filter in OBS Studio isolates and removes specific colors from a video source by measuring the geometric distance between individual pixel colors and a designated target key color. This article details the mathematical mechanics behind this shader-based process, explaining how OBS treats RGB values as three-dimensional vectors and uses the similarity and smoothness thresholds to compute the final alpha transparency of each pixel.

Vector Representation in RGB Space

Unlike the Chroma Key filter—which converts color data to the YCbCr (YUV) color space to separate brightness from chrominance—the standard Color Key filter operates directly in normalized RGB space.

Every pixel is represented as a three-dimensional vector:

\[\mathbf{C}_{\text{pixel}} = (R_p, G_p, B_p)\]

where each channel is normalized to a floating-point range between \(0.0\) and \(1.0\). The target color selected by the user is defined as a vector in the exact same format:

\[\mathbf{C}_{\text{key}} = (R_k, G_k, B_k)\]

Calculating Vector Distance

To determine how closely a pixel matches the chosen key color, the graphics shader computes the Euclidean distance (\(D\)) between the two color vectors:

\[D = \|\mathbf{C}_{\text{pixel}} - \mathbf{C}_{\text{key}}\| = \sqrt{(R_p - R_k)^2 + (G_p - G_k)^2 + (B_p - B_k)^2}\]

Because each color component ranges from \(0.0\) to \(1.0\), the maximum possible distance between opposite corners of the RGB color cube (e.g., pure black to pure white) is \(\sqrt{1^2 + 1^2 + 1^2} \approx 1.732\).

The Similarity Threshold

In the OBS Studio interface, the Similarity slider allows users to define the threshold radius around the target color vector within which pixels are identified as key color.

Internally, the slider's integer value is scaled to match the normalized color distance metric. Let this converted value be represented as \(T_{\text{sim}}\).

  • If the calculated Euclidean distance \(D\) is less than or equal to \(T_{\text{sim}}\), the pixel is treated as an exact match to the key color.
  • At or below this distance, the pixel's alpha multiplier is set to \(0.0\), making it completely transparent.

The Smoothness Threshold

If the filter only relied on similarity, the boundary between transparent and opaque pixels would produce harsh, aliased ("jagged") edges. The Smoothness slider introduces an anti-aliasing feathering zone extending outward from the edge of the similarity boundary.

The smoothness value is mapped to a normalized floating-point range, denoted as \(T_{\text{smooth}}\). It defines an outer boundary:

\[\text{Outer Limit} = T_{\text{sim}} + T_{\text{smooth}}\]

Within this transition zone, pixel opacity ramps linearly from fully transparent to fully opaque:

  • \(D \le T_{\text{sim}}\): Fully transparent (\(\text{Alpha Multiplier} = 0.0\))
  • \(D \ge T_{\text{sim}} + T_{\text{smooth}}\): Fully opaque (\(\text{Alpha Multiplier} = 1.0\))
  • \(T_{\text{sim}} < D < T_{\text{sim}} + T_{\text{smooth}}\): Semi-transparent gradient

Alpha Factor Calculation in the Shader

In the pixel shader, the final alpha factor is calculated using a standard linear interpolation and clamp operation:

\[\text{Factor} = \text{clamp}\left(\frac{D - T_{\text{sim}}}{T_{\text{smooth}}}, 0.0, 1.0\right)\]

This computed factor is then multiplied by the pixel's original alpha channel:

\[A_{\text{final}} = A_{\text{source}} \times \text{Factor}\]

When \(T_{\text{smooth}}\) is set to zero (or an extremely small value approaching zero), the formula behaves like a step function, resulting in a hard cutoff. Increasing \(T_{\text{smooth}}\) widens the denominator, expanding the range of color distances that receive partial transparency, which softens fringes and edge artifacts around the subject.
