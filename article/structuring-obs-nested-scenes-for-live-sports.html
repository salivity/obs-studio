Structuring OBS Nested Scenes for Live Sports

Structuring nested scenes in OBS Studio allows broadcast operators to swap complex graphics—such as scorebugs, player lower-thirds, rosters, and sponsor tags—seamlessly during live sports productions. By organizing graphical elements into modular, layered hierarchies rather than placing individual assets into every main scene, you ensure visual consistency, reduce system resource usage, and enable one-click graphics changes without interrupting live video feeds.

The Hierarchical Master Structure

A reliable sports production requires a clear three-tier hierarchy:

  1. Master/Output Scenes: These are the final broadcast scenes you push to program (e.g., [OUT] Live Camera 1, [OUT] Fullscreen Replay). They contain only the raw video/audio capture and the nested graphics containers.
  2. Graphics Containers (Routing Scenes): These nested scenes group elements by screen position or broadcast tier (e.g., [CONTAINER] HUD/Scorebug, [CONTAINER] Lower Thirds, [CONTAINER] Fullscreens).
  3. Asset/Source Scenes: The lowest level, containing actual assets like browser sources, PNGs, and text layers for specific teams, players, or sponsors (e.g., [ASSET] Team A Roster, [ASSET] Player Card - Striker).

By building your layout this way, modifying or swapping an asset in a lower-level scene updates every master scene simultaneously.

Isolating the HUD and Scorebug

The scorebug is a persistent element that should rarely be turned off during gameplay.

  • Place your scorebug asset inside a dedicated scene named [SYS] Scorebug.
  • Add [SYS] Scorebug as a nested source inside all gameplay master scenes.
  • When changing from regular gameplay to a penalty shootout, overtime, or halftime breakdown, swap the source inside [SYS] Scorebug rather than updating multiple camera scenes. This guarantees position coordinates never drift between camera cuts.

Dynamic Swapping with Dual-Container Routing

To swap player lower-thirds or match statistics instantly without accidental visual glitches, implement an A/B routing structure:

  • Create two identical container scenes: [GFX] Slot A and [GFX] Slot B.
  • Nest both slots into your Master Graphics overlay.
  • While Slot A is displayed live on-air, update the asset or data source inside Slot B off-air.
  • Use a macro, Elgato Stream Deck, or OBS hotkeys to hide Slot A and show Slot B. This technique eliminates source loading lag and avoids blank rendering flashes.

Managing Transitions with Scene Transition Overrides

Default global transitions (such as cuts or crossfades) do not suit every graphic element. A scorebug might require a simple fade, a replay requires a stinger with an audio track, and a lower-third needs a directional slide:

  • Right-click your nested graphic scene in the Scenes panel.
  • Select Transition Override.
  • Assign a specific transition (e.g., Slide Right for lower-thirds, Cut for score trackers).
  • Now, toggling the visibility of this nested scene via a hotkey will execute the assigned transition specifically for that asset without affecting the primary video cut.

Utilizing Browser Sources vs. Scene Nesting

For automated sports setups driven by external software (such as Singular.live, Uno Overlays, or local HTML/Node scoreboards), use nested scenes to group your browser inputs by z-index layer. Even if graphics are generated via URLs, keep them compartmentalized in nested scenes so you can apply color correction filters, crop boundaries, and positioning transforms globally without altering the underlying data feed.

Performance Optimization for Live Production

  • Lock All Sources: Prevent accidental mouse drags mid-game by locking all layers inside nested scenes.
  • Limit Redundant Captures: Avoid adding identical video capture devices across multiple nested scenes; always reference an existing capture scene to prevent GPU bottlenecking.
  • Standardize Canvas Coordinates: Build every nested graphic scene at full canvas resolution (e.g., 1920x1080) with assets positioned in their exact final screen locations. This ensures that when you import a nested scene into any master scene, it aligns automatically at coordinates 0, 0 without manual repositioning.
