OBS MTU Sizing for Cellular Bonding Streaming

Configuring OBS Studio for live field reporting over bonded mobile connections requires careful management of the Maximum Transmission Unit (MTU) to avoid packet fragmentation and frame drops. When multiple cellular uplinks are combined using bonding software or hardware routers, encapsulation overhead reduces the effective packet payload size. Understanding how cellular carrier networks, bonding tunnels, and transport protocols like SRT or RTMP interact enables field broadcasters to set optimal packet limits, ensuring low-latency, uninterrupted video feeds from the field.

The Problem with Default MTU in Cellular Bonding

The standard MTU for local Ethernet networks is 1500 bytes. However, mobile broadband networks (4G LTE and 5G) rarely deliver a true 1500-byte MTU. Carrier-grade NAT, IPv6 transition mechanisms (such as 464XLAT), and radio access network headers routinely reduce the native cellular MTU to between 1420 and 1440 bytes.

When live reporting involves bonding multiple cellular modems, an additional encapsulation layer is added. Whether using multi-WAN bonding proxies (like Speedify), dedicated bonding hardware, or custom tunnels (such as WireGuard or OpenVPN), each bonded packet is wrapped in new IP and tunnel headers. These headers consume an extra 28 to 80 bytes depending on the protocol used.

If OBS Studio transmits full-sized packets, they will exceed the Path MTU (PMTU) of the bonded cellular link. This results in:

  • IP Fragmentation: Routers must split large packets into smaller fragments, multiplying network overhead and increasing packet drop risk over unpredictable wireless links.
  • Packet Dropping / Blackholing: Many cellular networks drop fragmented UDP packets or silently block ICMP "Packet Too Big" messages, causing catastrophic stream stalls without an obvious error.
  • Bufferbloat and Latency Spikes: Reassembling fragmented video frames on the receiving ingest server adds processing delay, negating the low-latency benefits of remote field reporting.

Calculating the Safe MTU Target

To maintain stream stability across diverse cellular carriers (such as mixing AT&T, Verizon, and T-Mobile), you must size your MTU to the lowest common denominator among all active SIM cards, minus the bonding overhead.

A practical calculation formula for field reporting:

  • Base Carrier MTU: Assume a worst-case baseline of 1420 bytes.
  • Bonding Tunnel Overhead: Subtract 40 to 80 bytes for bonding encapsulation (e.g., GRE, WireGuard, or custom aggregation headers).
  • Transport Layer Overhead: Account for the video protocol (RTMP/TCP requires 40 bytes for standard TCP/IP headers; SRT/UDP requires 28 bytes for UDP/IP plus 16 bytes for the SRT header).

A universally safe target MTU for the bonded network adapter is between 1340 and 1380 bytes. Setting your MTU within this threshold prevents fragmentation across nearly all commercial cellular carriers worldwide.

Configuring MTU and MSS for OBS Studio

OBS Studio relies on the operating system’s network stack and the underlying stream protocol to govern packet sizing.

1. Network Interface Tuning

If you are running software-based cellular bonding directly on your streaming laptop, configure the virtual bonding network adapter rather than the physical modems:

  • Windows: Use PowerShell to set the subinterface MTU:
    netsh interface ipv4 set subinterface "Bonded-Adapter-Name" mtu=1360 store=persistent
  • macOS / Linux: Set the MTU on the virtual interface:
    sudo ifconfig <interface_name> mtu 1360

2. Configuring SRT in OBS Studio

Secure Reliable Transport (SRT) is the industry standard for cellular field broadcasting because of its resiliency over lossy connections. OBS Studio allows you to manually limit the Maximum Segment Size (MSS) directly via the SRT stream URL parameters in the OBS Output settings:

srt://ingest.example.com:9000?streamid=live/feed&mss=1360

Setting mss=1360 explicitly forces the SRT library inside OBS Studio to create UDP payloads that do not exceed 1360 bytes, completely bypassing interface-level fragmentation across bonded cellular interfaces.

3. Configuring RTMP / TCP Streams

If you must stream over standard RTMP (TCP), OBS Studio depends entirely on TCP Maximum Segment Size negotiation. When the MTU of your bonded adapter is lowered to 1360, the operating system automatically announces a reduced MSS (typically MTU minus 40 bytes, or 1320 bytes) during the TCP three-way handshake. If you are using a dedicated hardware bonding router, verify that "MSS Clamping" is enabled in the router's WAN settings to ensure outbound RTMP traffic matches the tunnel constraints.

Field Verification Checklist

Before going live with remote reporting:

  1. Run a Path MTU Test: Use ping with the "Don't Fragment" flag enabled to test your bonded connection against your ingest server:
    • Windows: ping ingest.example.com -f -l 1332 (1332 payload + 28 bytes ICMP/IP header = 1360 MTU)
    • macOS/Linux: ping -D -s 1332 ingest.example.com
  2. Monitor Carrier Swapping: If the bonding appliance switches primary traffic to a higher-latency or lower-MTU carrier, monitor OBS's dropped frame counter. If frame drops occur while bitrate remains below total upload bandwidth, reduce the MTU or SRT mss value by another 20 to 40 bytes.
