How OBS Studio Passes Custom FFmpeg Muxer Options

OBS Studio provides an advanced recording mode that bypasses standard encoder pipelines to interface directly with FFmpeg, enabling granular control over media containers. This article explains how OBS Studio accepts, parses, and forwards custom muxer parameters through its Advanced Custom Output interface down to the underlying libavformat library, along with the proper syntax required to apply these options successfully.

The Custom Output (FFmpeg) Interface

To access custom muxer controls in OBS Studio, navigate to Settings > Output, set the Output Mode dropdown to Advanced, and select Custom Output (FFmpeg) under the Output Type.

In this mode, OBS directly exposes FFmpeg's container (AVOutputFormat) and codec mechanisms. Near the bottom of this interface is the Muxer Settings (if any) input field. This text field acts as a direct bridge between the OBS graphical user interface and the FFmpeg muxing engine.

How OBS Parses and Translates Muxer Inputs

When you enter parameters into the "Muxer Settings" field, OBS Studio does not process them as standard command-line flags (such as -movflags +faststart). Instead, the internal plugin (obs-ffmpeg) treats the string as a collection of dictionary assignments:

  1. Tokenization: OBS reads the string and splits it into discrete key-value pairs. Pairs can typically be delimited by spaces or newlines, using the standard format: key=value.
  2. Dictionary Allocation: The obs-ffmpeg output module initializes an internal FFmpeg dictionary struct (AVDictionary).
  3. Populating AVDictionary: For each parsed key-value pair, OBS calls the FFmpeg utility function av_dict_set(). This populates the dictionary with your specified options. Flags that require multiple values or bitwise operations are passed as standard strings that FFmpeg evaluates internally (e.g., movflags=frag_keyframe+empty_moov).
  4. Passing to the Context: When recording starts, OBS calls avformat_write_header(), passing the pointer to this allocated AVDictionary alongside the AVFormatContext.
  5. Option Application: FFmpeg matches the keys in the dictionary against the private options supported by the selected container format (such as MP4, Matroska, or FLV). Valid options are applied directly to the container's private context.

Formatting Syntax and Practical Example

Because options are parsed directly into an AVDictionary, you must omit standard CLI prefixes like dashes (-).

  • Incorrect: -movflags frag_keyframe+default_base_moof -frag_duration 4000
  • Correct: movflags=frag_keyframe+default_base_moof frag_duration=4000

Multiple options should be separated by single spaces or new lines. If a parameter value requires spaces, encapsulate the value in quotation marks.

Error Handling and Validation

OBS Studio performs minimal validation on the strings entered into the Muxer Settings field. If an invalid or unrecognized key is provided:

  • FFmpeg's avformat_write_header() will reject the unrecognized dictionary entries depending on the container's strictness settings.
  • If any unconsumed entries remain or cause an initialization failure, OBS halts the process immediately and displays a generic output error to the user.
  • Detailed debugging information—including whether FFmpeg rejected a specific key—is written directly to the current OBS log file located under Help > Log Files > View Current Log.
