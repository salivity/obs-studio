OBS Studio Sub-Pixel Accuracy in Text Scaling

This article explains how OBS Studio maintains visual fidelity and sub-pixel precision when applying incremental scale transformations to vector text assets. Through the combination of floating-point transformation matrices, specialized GPU texture sampling shaders, and high-resolution dynamic rasterization pipelines, OBS Studio prevents positional jitter, rounding drift, and aliasing artifacts during continuous scaling operations.

Floating-Point Scene Transformations

OBS Studio decouples the logical position and scale of scene items from the discrete pixel grid of the output canvas. Internally, transforms applied to a text source are represented using 32-bit single-precision floating-point matrices (struct matrix4 in libobs).

When an incremental scale transformation is applied—such as through animations or programmatic script updates—the transformation values are multiplied continuously without rounding to whole-number screen coordinates. This preserves fractional coordinate data across multiple frames, preventing cumulative rounding errors that would otherwise cause visual stuttering or geometric distortion.

Dynamic Glyph Rasterization

OBS Studio does not transform raw vector paths directly on the final compositing canvas for every frame. Instead, it relies on underlying text rendering engines (such as FreeType on Linux/macOS or GDI+/DirectWrite on Windows) to rasterize glyph outlines into a dedicated offscreen texture buffer.

When text source properties are altered natively (such as changing the font size directly), the engine re-evaluates the vector curves using sub-pixel hinting and anti-aliasing to generate fresh alpha masks. However, when an item-level scale transformation is applied to the scene node, OBS Studio maps the pre-rasterized text texture to a quad on the GPU, avoiding the performance penalty of re-evaluating vector contours on every incremental step.

Texture Sampling and Sub-Pixel Interpolation

To maintain sub-pixel accuracy when the quad is scaled to non-integer pixel dimensions or positions, OBS Studio delegates sampling to GPU fragment shaders.

  1. UV Coordinate Mapping: Vertex shaders calculate normalized floating-point texture coordinates (\(U, V \in [0, 1]\)) for each vertex of the text quad. As the quad scales incrementally, these coordinates align to fractional offsets on the target render surface.
  2. Scale Filtering Algorithms: OBS Studio provides selectable scale filtering modes that determine how the GPU reconstructs the image across fractional boundaries:
    • Bicubic and Lanczos Filtering: These algorithms sample a multi-tap grid of surrounding texels, weighting their contributions via cubic or sinc-based kernel functions according to the exact fractional sub-pixel offset. This prevents harsh stair-stepping and softens edge movement.
    • Area Scaling: For downscaling, area averaging accumulates color contributions across the contracted fractional footprint, preserving thin vector strokes.
    • Bilinear Filtering: Hardware-accelerated linear interpolation evaluates texel values based on the fractional distance between adjacent pixel centers.

Prevention of Temporal Aliasing

During fine-grained, incremental scaling, nearest-neighbor rounding can cause "pixel popping," where an edge abruptly snaps from one pixel row to the next. By utilizing floating-point quad vertices combined with higher-order texture filtering, OBS Studio smoothly redistributes luminance across neighboring boundary pixels. This continuous shift in alpha transparency mimics continuous vector motion at a sub-pixel level, ensuring smooth rendering across varying output resolutions.
