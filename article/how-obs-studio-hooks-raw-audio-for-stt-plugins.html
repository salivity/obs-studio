How OBS Studio Hooks Raw Audio for STT Plugins

OBS Studio processes microphone input through its core media subsystem (libobs), allowing external plugins to intercept raw, uncompressed Pulse-Code Modulation (PCM) audio via specialized internal hooks. By attaching a source audio capture callback or an audio filter hook, a Speech-to-Text (STT) plugin gains direct access to audio buffers as they are captured from system drivers. These buffers are extracted on a dedicated real-time audio thread, downmixed or resampled to the STT engine's expected format (typically 16 kHz mono PCM), and passed safely across thread boundaries via circular FIFO buffers for real-time transcription.

The Audio Pipeline and libobs Data Structures

When a microphone source is active in OBS Studio, native audio subsystems (such as WASAPI on Windows, CoreAudio on macOS, or PipeWire/ALSA on Linux) feed raw audio frames into the source's internal buffer. Within libobs, this audio data is structured as struct audio_data.

The audio_data struct exposes key properties required for processing:

  • data[MAX_AV_PLANES]: Pointers to the raw audio sample arrays. OBS typically works with 32-bit floating-point planar audio (IEEE float).
  • frames: The number of audio frames present in the current chunk (commonly in increments corresponding to several milliseconds of audio, depending on the sample rate).
  • timestamp: The presentation timestamp (PTS) in nanoseconds, which assists in synchronizing transcriptions with live video frames.

Interception Methods: Source Callbacks vs. Audio Filters

STT plugins generally employ one of two hooking strategies to acquire these chunks:

1. Audio Capture Callbacks (obs_source_add_audio_capture_callback)

Plugins can globally monitor an existing audio source by registering a capture callback using:

void obs_source_add_audio_capture_callback(obs_source_t *source,
                                           obs_source_audio_capture_t callback,
                                           void *param);

When registered, OBS automatically calls this function whenever the target source receives a new chunk of raw audio. This hook operates non-destructively without modifying the audio being sent to the master output or stream.

2. Audio Filter Hooks (filter_audio)

Alternatively, a plugin can register itself as an audio filter (OBS_SOURCE_TYPE_FILTER with capability flag OBS_SOURCE_AUDIO). This implementation defines the filter_audio member of the obs_source_info struct:

static struct audio_data *stt_filter_audio(void *data, struct audio_data *audio)
{
    // Access audio->data here
    return audio; // Pass audio downstream unaltered
}

This method allows users to attach the STT functionality specifically to individual input devices inside the OBS Audio Mixer UI.

Format Normalization and Resampling

Most STT engines (such as Whisper, Vosk, or cloud-based speech APIs) do not accept the 32-bit float, multi-channel planar format at 44.1 kHz or 48 kHz that OBS defaults to natively. They typically require 16 kHz or 24 kHz mono signed 16-bit integer (S16LE) or 32-bit float PCM data.

To bridge this gap inside the hook:

  1. Channel Downmixing: Planar stereo/surround channels are averaged into a single mono channel.
  2. Sample Conversion: 32-bit float values (normalized between -1.0 and 1.0) are converted to 16-bit signed integers (-32768 to 32767), if required by the target engine.
  3. Resampling: The plugin initializes OBS’s internal resampler API (audio_resampler_t) or a third-party resampler (such as SpeexDSP or libswresample) to downsample the frame rate to the required target rate.

Non-Blocking Audio Dispatch via Ring Buffers

The execution context of obs_source_audio_capture_t and filter_audio runs directly on the high-priority real-time audio thread of OBS. Executing blocking network requests or CPU-intensive inference directly within the hook will stall the audio pipeline, causing audio dropouts, stream stuttering, and buffer underruns.

To prevent audio pipeline stalls, plugins transfer audio chunks using an asynchronous, lock-free ring buffer (circular buffer):

  1. Producer (Audio Hook): The hook copies normalized raw PCM bytes into a shared ring buffer memory segment.
  2. Signaling: The hook triggers a condition variable or lightweight semaphore to notify a background worker thread.
  3. Consumer (STT Worker Thread): A separate processing thread reads contiguous chunks (often aggregated into 100ms–1000ms segments, depending on whether streaming or batch transcription is used) from the ring buffer and feeds them directly into the speech-to-text inference runtime.
