Dual NVENC Split-Frame Encoding in OBS Studio

This article explains how OBS Studio configures and utilizes the NVENC split-frame encoding feature available on dual-NVENC Ada Lovelace graphics processors. It covers the underlying architecture of NVIDIA's dual encoders, how OBS Studio interfaces with the NVIDIA Video Codec SDK to distribute encoding workloads, the specific settings required to trigger split-frame execution, and how to verify that both hardware encoders are functioning concurrently.

Understanding Dual-NVENC Architecture on Ada Lovelace

High-tier NVIDIA Ada Lovelace graphics cards—such as the GeForce RTX 4070 Ti, RTX 4080, and RTX 4090—feature two independent 8th-generation NVENC hardware blocks. Split-frame encoding is a hardware-accelerated feature designed to cut encode latency in half for high-demand formats, such as 4K and 8K resolutions at high frame rates. Instead of processing an entire video frame on a single NVENC instance, the GPU driver splits each frame horizontally or vertically into two segments, sending each segment to a separate NVENC engine in parallel before combining them into a unified bitstream.

How OBS Studio Interacts with Split-Frame Encoding

OBS Studio does not implement split-frame encoding through a distinct manual UI toggle labeled "Split-Frame." Instead, OBS Studio interfaces directly with the NVIDIA Video Codec SDK, passing encoding parameters that allow the NVIDIA display driver to determine whether to distribute the workload across both chips.

  1. API Parameter Negotiation: OBS Studio configures NVENC sessions using the NV_ENC_INITIALIZE_PARAMS structure. Within the NVIDIA Video Codec SDK, split encoding is managed via the splitEncodeMode settings. OBS Studio by default requests automatic hardware allocation, delegating frame management directly to the driver.
  2. Codec Limitations: Split-frame encoding on Ada Lovelace is strictly limited to HEVC (H.265) and AV1. The legacy H.264 (AVC) standard does not support split-frame encoding across dual hardware units in the same manner, meaning single-stream H.264 outputs in OBS Studio will only occupy a single NVENC block.

Configuration Steps in OBS Studio

To ensure OBS Studio triggers split-frame encoding on a supported Ada Lovelace GPU, configure the output settings as follows:

  1. Open Settings in OBS Studio and navigate to the Video tab.
  2. Ensure your Base (Canvas) Resolution and Output (Scaled) Resolution are set to 4K (3840x2160) or higher. Split-frame encoding typically requires high pixel throughput to activate; standard 1080p outputs will not trigger dual-encoder operation because a single NVENC block can already encode 1080p in real time with minimal overhead.
  3. Navigate to the Output tab and change the Output Mode dropdown from Simple to Advanced.
  4. Select the Recording or Streaming tab.
  5. In the Video Encoder dropdown, select either NVIDIA NVENC HEVC or NVIDIA NVENC AV1.
  6. Set the Rate Control (e.g., CBR, CQP) and choose a high-performance preset such as P5: Slow (Good Quality), P6: Slower (Better Quality), or P7: Slowest (Best Quality).
  7. Ensure the Multipass Mode is set to Two Passes (Quarter Resolution) or Two Passes (Full Resolution) for optimal encoder engagement.

Advanced Parameters and Custom FFmpeg Mode

For setups requiring explicit enforcement of split-frame features outside standard driver heuristics, OBS Studio allows passing custom encoder options in the Custom Multiplexer Settings field or by using the FFmpeg Output mode.

By directing FFmpeg parameters directly to the underlying NVENC wrapper, developers and advanced users can pass flags that interface directly with nvenc_av1 or hevc_nvenc libraries, ensuring parallel execution flags are passed directly without driver-level scaling checks.

Verifying Dual NVENC Utilization

Because OBS Studio delegates split-frame distribution to the driver, verification must be completed using system hardware monitors:

  1. Open Task Manager while actively recording or streaming in OBS Studio.
  2. Go to the Performance tab and select your GPU.
  3. Under the GPU utilization graphs, select a drop-down menu on one of the graphs and change it to Video Encode. If available, locate the secondary engine graph (labeled as separate NVENC instances or combined under Video Encode).
  4. For deeper analysis, run NVIDIA System Management Interface (nvidia-smi) via the command line: 
    nvidia-smi dmon -s u
    Monitor the enc column to verify aggregate hardware encoder throughput and confirm both encoding engines are actively drawing power and clock cycles simultaneously.
