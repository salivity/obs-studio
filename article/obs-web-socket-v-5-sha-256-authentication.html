OBS WebSocket v5 SHA-256 Authentication

This article provides a concise technical overview of the authentication mechanism used in the OBS Studio WebSocket v5 protocol. It covers the initial handshake exchange, the role of the challenge and salt parameters, the step-by-step SHA-256 hashing algorithm required to generate the authentication response, and how OBS Studio verifies the client's identity before granting access.

The Authentication Handshake

OBS WebSocket v5 utilizes a challenge-response authentication mechanism over a standard WebSocket connection. The process prevents the transmission of plain-text passwords and protects against replay attacks by using dynamic salts and challenges generated per session.

  1. Connection: The client initiates a WebSocket connection to the OBS WebSocket server (default port 4455).
  2. Server Hello (OpCode 0): Upon connection, the server immediately sends a Hello message. If authentication is enabled in OBS, this payload includes an authentication object containing two key base64-encoded strings:
    • challenge: A unique, randomly generated cryptographic challenge for the session.
    • salt: A unique salt string stored or generated by the server for password hashing.
  3. Client Identify (OpCode 1): The client computes an authentication string using the password, salt, and challenge, then sends it back to the server in an Identify payload.
  4. Server Verification: The server verifies the computation. If valid, it responds with an Identified message (OpCode 2). If invalid, it immediately closes the WebSocket connection with close code 4009 (AuthenticationFailed).

The SHA-256 Hashing Algorithm

The client calculates the authentication string using a two-stage SHA-256 hashing process. All binary hash outputs are encoded into Base64 strings before subsequent operations.

Step 1: Generate the Secret

Concatenate the plain-text password with the server-provided salt, compute the SHA-256 digest of this combined string, and encode the raw binary result into a Base64 string.

secret = Base64( SHA256( password + salt ) )

Step 2: Generate the Final Authentication String

Concatenate the secret generated in Step 1 with the server-provided challenge, compute the SHA-256 digest of this combined string, and encode the resulting binary digest into a Base64 string.

auth_response = Base64( SHA256( secret + challenge ) )

Sending the Identify Payload

Once the client computes auth_response, it constructs the Identify message with op: 1 and includes the result in the data field:

{
  "op": 1,
  "d": {
    "rpcVersion": 1,
    "authentication": "auth_response_string_here",
    "eventSubscriptions": 33
  }
}

The server performs the identical mathematical calculation using the stored password. Because the challenge changes with every connection attempt, a previously intercepted auth_response cannot be reused, ensuring secure access to OBS Studio controls.
