OBS macOS Application Audio Capture Without KEXTs

This article explains how OBS Studio captures isolated, per-application audio on macOS natively, without requiring third-party kernel extensions (KEXTs) or virtual audio cables. By transitioning away from legacy driver-based workarounds, modern versions of OBS Studio leverage Apple's native frameworks to tap into individual audio streams directly. The following sections break down the transition from kernel-level drivers to Apple's modern user-space APIs, how ScreenCaptureKit handles stream isolation, and how OBS processes these audio buffers.

The Shift Away From Kernel Extensions

Historically, capturing desktop audio or specific application sound on macOS required third-party virtual audio loopback drivers, such as Soundflower or BlackHole, or legacy Kernel Extensions (KEXTs). Apple systematically deprecated KEXTs due to system stability, performance, and security concerns. Kernel-level code runs with unrestricted privileges, meaning a single fault in an audio driver could trigger a kernel panic and crash the entire operating system.

To replace this approach, Apple introduced user-space audio and display capture APIs that provide secure, low-latency access to media streams without compromising the operating system's integrity.

ScreenCaptureKit: The Core Framework

The primary mechanism OBS Studio uses to capture per-application audio on macOS 13 (Ventura) and later is ScreenCaptureKit.

ScreenCaptureKit is a high-performance framework designed to run entirely in user space. While primarily known for screen sharing and video capture, the framework includes robust support for system and application-level audio routing via its streaming pipeline.

When configured:

  1. Application Discovery: OBS queries the system for running applications using SCShareableContent. This returns a list of active applications and display windows.
  2. Target Filtering: When a user selects a specific application in the "Application Audio Capture" source, OBS creates an SCContentFilter targeting only that specific application's process identifier (PID) or bundle identifier.
  3. Audio-Only Stream Creation: OBS initializes an SCStreamConfiguration object. It sets capturesAudio = true and excludes or minimizes video processing to save system resources.
  4. Stream Execution: An SCStream instance is instantiated with the filter and configuration. The stream outputs raw audio samples directly from the targeted application.

How the Audio is Tapped Without Virtual Drivers

Under the hood, macOS handles audio mixing via the Core Audio Hardware Abstraction Layer (HAL). When an application plays sound, it sends PCM buffers through Core Audio to the system's output device.

Instead of intercepting these buffers at the hardware or kernel driver level, ScreenCaptureKit taps the audio session at the system compositor and window-server level. The operating system isolates the process’s audio graph, splits off a copy of the uncompressed PCM stream, and sends it directly to the authorized capture application (OBS Studio) via an asynchronous delegate callback (stream(_:didOutputSampleBuffer:of:)).

Because this pipeline is managed entirely by Apple's system daemons, OBS receives the audio after the application renders it, but before it reaches the master output mix, ensuring zero bleed from other running software.

Buffering and Internal Routing in OBS

Once ScreenCaptureKit delivers the audio sample buffers:

  1. Buffer Conversion: The incoming CMSampleBuffer containing Linear PCM audio is extracted.
  2. Resampling: OBS Studio checks the sample rate and channel layout of the incoming stream and resamples the audio (using its internal resampler routines) to match the canvas's global audio settings (typically 44.1 kHz or 48 kHz).
  3. Mixer Injection: The processed samples are fed into the standard OBS audio pipeline, where volume filters, noise suppression, and routing to specific output tracks (such as streaming and recording tracks) are applied.

Permissions and User Space Security

Because this process operates strictly within macOS's user space, it relies on the Transparency, Consent, and Control (TCC) framework rather than system extension approvals. To capture per-app audio, users simply grant OBS Studio permission under System Settings > Privacy & Security > Screen & System Audio Recording. Once authorized, OBS can capture audio from any targeted process without rebooting the system or lowering SIP (System Integrity Protection).
