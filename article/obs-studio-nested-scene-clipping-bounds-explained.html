OBS Studio Nested Scene Clipping Bounds Explained

This article explores how OBS Studio's internal graphics subsystem resolves, transforms, and renders clipping bounds when nested scenes feature non-standard aspect ratios. It covers the hierarchical matrix pipeline, off-screen render target creation, bounding box alignment modes, and the hardware-level scissor testing used to prevent visual artifacts across differing canvas dimensions.

Scene Hierarchy and Transformation Matrices

OBS Studio treats every scene as a standard source (obs_scene_t wrapping an underlying obs_source_t). When scenes are nested, the engine organizes them into a directed acyclic graph. Each item within a scene maintains its own transform matrix—comprising position, rotation, scale, and explicit crop offsets (top, bottom, left, and right).

When a nested scene has an aspect ratio that deviates from the base canvas or its parent scene, OBS computes a local transformation matrix. During the render pass, this local matrix is multiplied by the parent’s world transform matrix:

\[\mathbf{M}_{\text{world}} = \mathbf{M}_{\text{parent}} \times \mathbf{M}_{\text{local}}\]

This composite matrix maps the normalized device coordinates of the child elements directly into the coordinate space of the parent canvas.

Off-Screen Render Targets and Aspect Ratio Handling

To render a nested scene, OBS typically diverts the rendering pass to an off-screen intermediate texture using a render target (gs_texrender_t).

  1. Resolution Allocation: The nested scene renders into a surface defined by the scene’s internal dimensions. If the nested scene has a non-standard ratio (for example, 9:16 inside a 16:9 canvas), the render target retains that native pixel ratio.
  2. Projection Setup: A temporary orthographic projection matrix is established for the nested scene’s dimensions using gs_ortho(). All child sources within that scene are drawn onto this off-screen buffer.
  3. Texture Sampling: Once the off-screen pass completes, the resulting texture is drawn back onto the parent canvas as a single textured quad.

Bounding Box Types and Alignment Rules

When an item within a nested scene, or the nested scene itself, uses explicit bounding limits, OBS applies one of several obs_bounds_type modes to reconcile differing aspect ratios:

  • OBS_BOUNDS_STRETCH: Ignores the original aspect ratio completely, scaling the source’s vertices directly to the defined rectangular dimensions.
  • OBS_BOUNDS_SCALE_INNER: Calculates uniform scale factors for the X and Y axes (\(S_x = \frac{\text{bound}_w}{\text{source}_w}\), \(S_y = \frac{\text{bound}_h}{\text{source}_h}\)), selects \(\min(S_x, S_y)\), and fits the entire frame within the bounds without cropping, resulting in pillarboxing or letterboxing.
  • OBS_BOUNDS_SCALE_OUTER: Selects \(\max(S_x, S_y)\), filling the entire bounding boundary. Any content extending beyond the specified bounds is clipped.
  • OBS_BOUNDS_SCALE_TO_WIDTH / HEIGHT: Forces the scale factor of one specific axis while scaling the other proportionally, regardless of boundary overflow.

Crop Application vs. Scissor Testing

OBS processes clipping via two distinct mechanisms depending on the operation:

  1. Texture UV Clipping (Explicit Crops): When standard pixel cropping is applied to an item, OBS alters the vertex coordinates and UV mapping of the rendered quad. The geometry itself is truncated before rasterization, adjusting the sampling coordinates so pixels outside the crop values are never fetched or rendered.
  2. Hardware Scissor Rectangles (gs_scissor_rect): When content must be clipped due to bounding constraints, parent container borders, or rendering masks, the engine relies on scissor testing. The canvas renderer projects the bounding boundary into target viewport screen coordinates, sets the active scissor rectangle via the underlying graphics API (Direct3D 11 or OpenGL), and clips any fragments generated outside this region at the rasterizer stage.

Mathematical Coordinate Mapping for Non-Standard Ratios

When calculating the final scissor rectangle for nested non-standard bounds, the renderer converts the nested local coordinates through the view hierarchy:

// Conceptual representation of OBS scissor box calculation
vec3 top_left = vec3(bound_x, bound_y, 0.0f);
vec3 bottom_right = vec3(bound_x + bound_width, bound_y + bound_height, 0.0f);

vec3_transform(&screen_tl, &top_left, &current_matrix);
vec3_transform(&screen_br, &bottom_right, &current_matrix);

gs_scissor_rect(
    (int)screen_tl.x, 
    (int)screen_tl.y, 
    (int)(screen_br.x - screen_tl.x), 
    (int)(screen_br.y - screen_tl.y)
);

If rotation is introduced alongside a non-standard aspect ratio, scissor testing alone is insufficient because hardware scissor rects are axis-aligned to the viewport. In such scenarios, OBS Studio bypasses viewport scissor rects and uses multi-pass alpha blending or stencil buffers, ensuring that the clipped boundary matches the exact transformed edges of the parent container without edge bleeding.
