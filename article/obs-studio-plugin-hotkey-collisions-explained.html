OBS Studio Plugin Hotkey Collisions Explained

This article explains the internal mechanics of hotkey management in OBS Studio, detailing what occurs when two external control plugins register identical hotkey identifiers or duplicate key combinations. It covers the core registration process, how OBS separates logical internal IDs from string names, how the configuration system handles duplicate entries, and the exact order of execution when a collision occurs.

Internal Hotkey ID Generation

In OBS Studio, external plugins interact with the hotkey system via the obs-hotkeys.c API, typically calling functions such as obs_hotkey_register_frontend() or obs_hotkey_register_source().

OBS Studio does not allow external plugins to define the primary numeric shortcut ID directly. Instead:

  1. A plugin provides a string identifier (e.g., plugin_a.toggle_mute), a human-readable description, and a callback function.
  2. OBS core generates a unique, sequential runtime integer (obs_hotkey_id) and returns it to the registering plugin.
  3. Because the internal obs_hotkey_id is assigned sequentially by OBS, low-level integer collisions cannot occur at the system level.

Handling Duplicate String Identifiers

A collision problem arises when two independent plugins register using the exact same textual identifier.

OBS Studio maintains hotkeys inside a dynamic array (da_push_back(obs->hotkeys, ...)). The core library does not implement strict uniqueness validation on the string identifiers during registration. Consequently:

  • Dual Registration: Both registrations succeed. OBS creates two distinct hotkey entries internally, each holding the same string identifier but assigned different numeric obs_hotkey_id values.
  • Callback Retention: Each entry retains its own independent callback pointer assigned by its respective plugin.

Configuration File Mapping and Persistence

OBS Studio persists user-assigned key combinations inside the profile configuration files (such as basic.ini). Hotkeys are mapped using their string identifiers rather than dynamic numeric IDs, ensuring that bindings persist across application restarts.

When two plugins claim the same string identifier:

  • Binding Assignment: When OBS parses the configuration file at startup, it matches the saved key combination against registered hotkeys by their string names.
  • Duplicate Population: If two entries match the saved name, OBS assigns the loaded physical key binding to both internal hotkey objects.
  • UI Display: In the OBS Settings > Hotkeys menu, both hotkeys appear. If their human-readable descriptions are identical, they are visually indistinguishable to the end-user.

Execution Behavior During a Trigger Event

When a physical shortcut or an external control trigger is pressed:

  1. Sequential Execution (FIFO): The OBS input handler matches the pressed key combination against all active hotkey objects. Because both registrations hold the same key combo, the event dispatcher executes both registered callbacks sequentially in the order they were registered (first-in, first-out).
  2. Lack of Priority Overrides: OBS does not feature a priority system for hotkey listeners. One plugin cannot intercept or consume the event to prevent the second plugin from executing.

External API and WebSocket Collisions

When external control plugins interact via the obs-websocket protocol or IPC to trigger a hotkey by name:

  • Most lookup methods iterate through the internal hotkey array and execute the first matching name found.
  • The plugin registered first typically receives the simulated trigger, while the second registered plugin with the matching name is bypassed entirely.
  • If the external tool triggers hotkeys via virtual key presses rather than API name lookups, both plugins will fire simultaneously, matching standard keyboard input behavior.
