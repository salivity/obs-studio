OBS Studio Buffer Size for Third-Party VST Plugins

This article examines the audio buffer size allocation used by OBS Studio when running third-party VST plugins, including equalizers. It details the fixed internal frame sizes utilized by the OBS audio engine, explains how the software feeds audio data to the VST host module, and explores the practical impact this buffer size has on processing latency and filter behavior.

The Default Buffer Size Allocation

OBS Studio allocates a fixed buffer size of 1,024 samples per audio block when processing audio through its internal pipeline and third-party VST 2.x plugins.

In the core OBS architecture (libobs), the audio system defines standard processing chunks using the macro AUDIO_OUTPUT_FRAMES, which is hardcoded to 1,024 audio frames per channel. When audio passes through the filter chain on any audio source, the native obs-vst plugin host passes audio data to the plugin’s processReplacing or processDoubleReplacing functions in chunks of this exact size.

Latency and Sample Rate Calculations

Because the buffer size is tied to a fixed sample count rather than a fixed time slice, the physical latency introduced by this buffer depends on the global sample rate configured in OBS Studio:

  • At 48 kHz (standard broadcast rate): A 1,024-sample buffer equates to approximately 21.33 milliseconds of processing latency per block.
  • At 44.1 kHz (standard media rate): A 1,024-sample buffer equates to approximately 23.22 milliseconds of processing latency per block.

Unlike a Digital Audio Workstation (DAW) utilizing dedicated low-latency ASIO drivers, OBS Studio does not provide a native user interface setting to alter this internal 1,024-sample processing block size. The audio pipeline relies on this uniform buffer to maintain stability and prevent buffer underruns during real-time video compositing and encoding.

Impact on VST Equalization Plugins

The 1,024-sample block size directly affects how third-party equalization filters function inside OBS Studio:

  • Minimum-Phase Equalizers (IIR Filters): Standard parametric and graphic EQs process samples sequentially with virtually zero inherent algorithmic latency. These plugins execute well within the 1,024-sample block, introducing no additional delay beyond the software's standard 21.33 ms processing chunk.
  • Linear-Phase Equalizers (FIR / FFT Filters): Linear-phase EQs require larger internal Fast Fourier Transform (FFT) windows (often 2,048, 4,096, or more samples) to maintain accurate low-frequency resolution. When the internal plugin window exceeds OBS’s 1,024-sample buffer, the plugin must queue multiple incoming blocks before returning processed audio. This adds reportable latency that can misalign live microphone audio with corresponding video feeds.

Latency Compensation in OBS Studio

While standard DAWs automatically delay timeline tracks to match the plugin with the highest latency, OBS Studio does not feature universal automatic plugin delay compensation (PDC). If a complex VST equalizer introduces internal processing delay on top of the 1,024-sample engine buffer, manual adjustment is required. Broadcasters must enter a negative or positive offset via the Sync Offset setting in the Advanced Audio Properties menu to keep equalized microphone audio synchronized with visual camera frames.
