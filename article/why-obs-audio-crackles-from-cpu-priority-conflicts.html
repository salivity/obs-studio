Why OBS Audio Crackles from CPU Priority Conflicts

Sudden crackling, popping, or robotic artifacts in OBS Studio audio typically occur when resource-intensive games starve background audio processing threads of essential CPU cycles. This article examines how operating system thread scheduling, digital audio buffer underruns, and competing process priorities interact to disrupt the real-time audio pipeline in OBS Studio, and how these performance bottlenecks can be resolved.

The Role of Audio Buffer Underruns

Digital audio relies on a continuous, uninterrupted stream of data processed in discrete time blocks called buffers. In OBS Studio, audio capture sources—such as desktop audio, game capture, and microphone inputs—feed into an internal mixer that processes and encodes the sound in real time.

When the CPU fails to process and deliver an audio buffer before the output device or encoder requests the next one, a buffer underrun (or buffer dropout) occurs. The resulting gap in the audio waveform manifests audibly as a sharp click, pop, or sustained crackling. Because human hearing is exceptionally sensitive to discontinuities in sound waves, even a microsecond delay in processing can cause noticeable audio degradation.

Thread Priority and CPU Scheduling

Modern operating systems, such as Windows, manage CPU time through a preemptive scheduler. Threads are assigned priority levels ranging from idle to real-time. When a game demands maximum system resources, several scheduling conflicts can arise:

  • Game Engine Priority Bias: Many modern games automatically elevate their main rendering, physics, or anti-cheat threads to above-normal or high priority to maintain stable frame rates.
  • Deprioritization of Background Tasks: If OBS Studio is running at normal process priority or minimized in the background, the scheduler treats its threads with lower urgency than the foreground game.
  • Preemption of Real-Time Audio Threads: Windows uses the Multimedia Class Scheduler Service (MMCSS) to grant real-time priority to audio threads. However, if heavily loaded game threads saturate the CPU cores assigned to audio, the scheduler may delay the execution of OBS's audio rendering loops.

CPU Core Contention and Thread Starvation

When a game attempts to utilize 100% of available CPU capacity, thread contention becomes severe. OBS Studio relies on multiple asynchronous threads: video rendering, scene compositing, encoding, and audio mixing.

If a multi-threaded game consumes all available execution pipelines on physical and logical cores, the operating system must constantly swap context between game threads and OBS threads. If context switching stalls the OBS audio thread—even for a few milliseconds—the mixer falls behind the game's actual audio output, creating a backlog that results in repetitive audio distortion and stutter.

Solutions to CPU Priority Conflicts

Eliminating priority-induced audio crackling requires restoring predictable CPU access to OBS Studio's audio sub-system:

  • Run OBS as Administrator: Launching OBS Studio with administrative privileges enables it to leverage hardware-accelerated GPU scheduling and hook into Windows MMCSS, elevating its internal threads above standard background tasks.
  • Adjust Process Priority in OBS: Within OBS Studio, navigate to Settings > Advanced > General and ensure the Process Priority is set to Above Normal or High. This instructs the OS scheduler to serve OBS threads before standard game threads.
  • Cap In-Game Frame Rates: Uncapped frame rates force the CPU and GPU to run at maximum capacity, leaving zero overhead for background capture software. Capping the game's frame rate to match the monitor’s refresh rate immediately frees up scheduling headroom.
  • Manage Core Affinity: On CPUs with hybrid architectures (such as Intel Performance and Efficient cores) or high thread counts, manually assigning CPU affinity via Task Manager can prevent games and OBS from fighting over the same execution cores.
