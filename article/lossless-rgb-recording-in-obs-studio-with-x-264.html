Lossless RGB Recording in OBS Studio with x264

This article explores the technical mechanisms that enable mathematically lossless RGB capture in OBS Studio using the x264 encoder set to CRF 0. Achieving true lossless recording requires bypassing lossy color matrix conversions, eliminating chroma subsampling, and disabling quantization stages within the H.264 compression pipeline. Below is a detailed breakdown of how OBS Studio and the x264 library handle native RGB data from screen acquisition to bitstream output.

The Role of CRF 0 in x264

Constant Rate Factor (CRF) typically acts as a perceptual rate-control mechanism that varies quantization to maintain consistent visual quality. However, setting CRF 0 functions as an operational trigger within x264 that switches the encoder into a true mathematical lossless mode.

In standard lossy encoding, the encoder applies an integer Discrete Cosine Transform (DCT) to prediction residuals and divides the resulting coefficients by a Quantization Parameter (QP) matrix, permanently discarding high-frequency detail. When CRF 0 is invoked:

  • The QP is set to 0.
  • The transform and quantization stages are bypassed using H.264's transform_bypass_mode_flag.
  • Instead of quantizing the spatial frequency domain, the residual difference between the predicted block and the source frame is transmitted directly to the entropy encoder (CABAC or CAVLC).
  • The decoded output matches the uncompressed input frame bit-for-bit.

Bypassing Color Conversion and Subsampling

Most digital video is encoded in the YUV (YCbCr) color space, often paired with 4:2:0 chroma subsampling to reduce data bandwidth by discarding half the horizontal and vertical color resolution. This presents two points of degradation for computer graphics: conversion rounding errors between RGB and YUV matrices, and spatial color loss.

For lossless RGB capture to function:

  1. Source Capture: Computer graphics are rendered natively in sRGB/RGB space. OBS captures these textures directly via GPU hooks (DirectX, OpenGL, or Vulkan) as raw RGB surfaces.
  2. Color Format Configuration: In OBS Settings > Advanced > Video, the Color Format must be set directly to RGB rather than NV12, P010, or I420.
  3. Pipeline Preservation: Setting the format to RGB forces OBS to keep the captured GPU textures in planar RGB without executing a color space conversion shader (such as RGB to Rec. 709 or Rec. 601). This eliminates the color clipping and rounding errors inherent to matrix transformations.

High 4:4:4 Predictive Profile (Hi444PP)

Standard H.264 profiles (Baseline, Main, High) are restricted to 4:2:0 subsampled YUV video. To process native RGB data losslessly, x264 engages the High 4:4:4 Predictive Profile (Profile IDC 244).

Under this profile:

  • Planar RGB / GBR Mapping: H.264 stores RGB data internally mapped as GBR (Green, Blue, Red). Green is assigned to the luma channel (\(Y\)) because it carries the majority of luminance information, while Blue and Red are mapped to the chroma channels (\(Cb\) and \(Cr\)).
  • Full Resolution Channels: All three color channels retain an identical \(1:1\) pixel grid, meaning no downsampling occurs.
  • Spatial Intra-Prediction: The encoder uses intra-prediction modes across all three independent color planes, predicting pixel values based on neighboring boundary pixels.
  • Lossless Residual Coding: The arithmetic differences (residuals) between predicted pixels and source pixels are calculated, passed through entropy coding, and written directly into the bitstream without loss.

End-to-End Pipeline Summary

When OBS Studio is configured for RGB recording with x264 at CRF 0:

  1. Graphic frames are acquired from the desktop or application surface in 8-bit RGB format.
  2. The OBS rendering engine transfers the uncompressed RGB frame buffer to the libx264 library without matrix conversion or downsampling.
  3. x264 identifies the RGB input and initializes the High 4:4:4 Predictive Profile.
  4. Setting CRF to 0 instructs x264 to bypass the forward transform and quantization steps entirely.
  5. Spatial predictions are generated, exact residuals are entropy-encoded using lossless CABAC/CAVLC, and the data is multiplexed into the designated container (such as MKV), producing a pristine, mathematically identical replica of the display output.
