Moving OBS Scene Collections Across Operating Systems

Transferring an OBS Studio scene collection between different operating systems—such as Windows, macOS, and Linux—invariably leads to broken media references because file systems handle directory structures differently. This article explains how OBS Studio references local file paths within its configuration files, what happens when those references fail on a new platform, and how the software helps you locate and relink your missing assets.

How OBS Studio Stores File Paths

When you export a scene collection in OBS Studio, the configuration is saved as a JSON file. Within this file, every media source—including images, video clips, browser dock local files, audio tracks, and LUTs (lookup tables)—is stored using its absolute local file path.

Because paths are recorded as absolute strings, they are tied to the platform where the collection was created:

  • Windows: Uses drive letters and backslashes (e.g., C:\Users\Username\Videos\overlay.mp4).
  • macOS: Uses Unix-style paths starting at the volume root (e.g., /Users/username/Movies/overlay.mp4).
  • Linux: Uses standard Unix paths (e.g., /home/username/Videos/overlay.mp4).

OBS Studio does not automatically translate or map directory hierarchies across different operating systems upon import, because file systems and user directory naming conventions vary fundamentally between platforms.

The Missing Files Dialog

When OBS Studio loads a scene collection on a new platform and discovers that the absolute paths point to nonexistent directories or invalid path syntaxes, it flags these assets as missing.

To handle this, OBS triggers the Missing Files window automatically. This interface lists:

  • The source name inside the scene.
  • The original (now inaccessible) file path.
  • The current detection status.

From this window, you can double-click a missing asset to select its new location on the host file system. OBS Studio includes a recursive search feature: if you point one missing source to its new folder, OBS will scan that directory and its subdirectories to locate and relink any other missing assets that share matching filenames. Once resolved, the JSON configuration updates with the new operating system's absolute paths.

Manual Path Re-mapping via JSON

For large scene collections with deeply nested folder structures, relying on the user interface to relink dozens of assets can be time-consuming. Because OBS scene collection exports are standard text files, you can modify them manually before importing:

  1. Open the exported .json file in a dedicated text editor (such as VS Code or Notepad++).
  2. Use the Find and Replace tool to locate the old directory prefix (e.g., C:\\Users\\Name\\Assets\\). Note that backslashes in Windows JSON paths are escaped as double backslashes (\\).
  3. Replace the old string with the corresponding destination path prefix for the target system (e.g., /home/name/assets/).
  4. Save the modified file and import it into OBS Studio.

If the file names match and the paths are formatted according to the destination platform's syntax, OBS Studio will load the sources immediately without displaying the Missing Files prompt.
